# VER6.1 A–E 비교실 검증

2026-10-28 · 전용 로컬 빌드 `http://127.0.0.1:8031/lab/v6-1/` · Chrome/CUA. 운영 데이터 쓰기·배포·커밋 없음.

## 확인한 동작

- A/B/C/D/E를 실제 선택하고 iframe 주소·제목·설명·선택 상태가 맞게 교체되는 것을 확인했다. 하나씩 보기 1개, 나란히 보기 최대 2개만 마운트된다.
- 1440×1000 두 창에서 같은 사진첩으로 이동하면 각 프레임 내부 제목 위쪽 위치가 약 44px로 맞춰졌다. 예식 안내·위치·이야기·계좌·방명록 메뉴도 해당 section 명령을 전달한다. 오프닝 다시 보기는 두 창을 첫 화면으로 돌려놓는다. 재생 버튼 클릭 뒤 자동화 관측 시점에는 획 재생이 끝났으므로 이 기록은 중간 획 프레임 측정으로 주장하지 않는다.
- 왼쪽 음악 재생 때 미디어 상태는 왼쪽 `paused=false`, 오른쪽 `true`. 오른쪽으로 전환하면 반대 상태가 됐다. 오른쪽 재생 중 모바일 폭으로 바꾸면 오른쪽 iframe이 제거되고 음악 선택은 `none`, 남은 미디어는 정지했다.
- 빠른 모듈 로드의 `ready` 메시지가 iframe `load`보다 먼저 도착할 때, 새 시안의 음악 소유권이 해제되는 문제를 발견하고 수정했다. `setupCatalog`를 실행하는 회귀 검사로 순서·교체·이전 프레임의 지연 메시지를 검증했다. 수정 뒤 C에서 D로 변경해 선택값 `left`와 실제 음악 재생을 확인했다. 자동재생 정책에 막힌 경우에는 화면 터치 안내가 표시됐다.
- C 메모를 입력·저장하고 E에는 나타나지 않는 것을 확인했다. C로 복귀 및 새로고침 뒤에도 남았고, QA 메모는 입력란을 비워 저장하여 정리했다. 메모/점수는 로컬 비교 키만 사용한다.
- 320×740, 390×844에서 문서 가로 넘침이 없었다. 모바일 비교창의 좌우 여백을 없애 내부 청첩장이 최대 폭을 쓰게 수정했다. 320px 브라우저에서 iframe 너비 305px(브라우저 세로 스크롤바 제외), 이름과 시간 한 줄을 확인했다. 점수 선택 영역은 최소 44×44px다. 모바일에서는 나란히 보기 제어가 숨겨지고 iframe 1개만 유지된다.
- 최종 관측된 Chrome console error/warn 0개. 테스트 viewport는 초기 크기로 복원하고 테스트 탭을 닫았다.

## 빌드 자원 예산

`node docs/invitation-lab/measure-resources.mjs`로 다시 계산할 수 있다. 상세 파일 목록은 [resource-budget.json](resource-budget.json). HTML(인라인 SVG 포함), 연결된 CSS, 도달 가능한 모든 로컬 JS와 선택한 테마는 **파일별 gzip level 9**로 합산했다. 첫 사진과 네 폰트는 원래 파일 크기로 계산했다. 캐시 절감은 적용하지 않았다. 전체 MP3, 지연 지도·사진첩·이야기 사진, 비교실 호스트는 제외한다.

단위 byte. 다섯 시안 모두 JS gzip 150KB 미만, 초기 계산 예산 1.8MB 미만이다. 비교 방식은 같지만 기존 첫 사진은 실제 `date-1440.webp`, 새 시안은 요청 기준 `forest-960.webp`다. 같은 960 사진으로 정규화한 기존 값은 1,283,870byte로, 새 시안은 비슷한 수준이다. 실제 화면은 srcset에 따라 다른 사진을 선택할 수 있다.

이 값은 파일 예산이며 실제 Vercel 전송량이나 브라우저 성능 수치가 아니다. **실기기 LCP·CLS, 저성능 Android/iOS, OS 캘린더·지도 앱 실행은 미검증**이다. Chrome에서 레이아웃과 조작을 확인한 결과를 해당 수치로 대체하지 않는다.
