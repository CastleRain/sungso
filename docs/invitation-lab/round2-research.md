# VER6.1 두 번째 탐색 — 이야기 밖의 기능 모션

조사일: 2026-10-28 · 범위: 예식 안내, 사진첩, 오시는 길, 마음 전하실 곳, 방명록, 빠른 메뉴.

사용자 피드백은 “이야기만 달라지고 다른 항목은 비슷하다”였다. 이번에는 이야기 페이지의 비중을 늘리지 않고, 하객이 날짜를 확인하고 사진을 보고 길을 찾고 축하를 전하는 과정 자체에 차이를 만든다. 아래의 구현 제안은 참고 사이트의 코드를 복제한 것이 아니라 관찰과 공식 지침을 바탕으로 설계한 제안이다.

기술 확인: [MDN prefers-reduced-motion](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion)은 기기의 동작 감소 선호를 읽는 방법을 설명한다. 이를 효과 끄기와 함께 적용하고, 설정 변경 중에도 완성 상태를 즉시 보여준다.

## 2. 직접 화면을 확인한 두 단계

1. **계좌 펼치기 — 구조 명확, 기능 개선 여지 있음.** 양가가 접기/펼치기 헤더로 분리되고 이름·은행·번호·송금 링크가 같은 행에 묶인다. 새 버전에서는 금융 정보를 움직이게 하기보다 선택 인디케이터와 복사 완료 표시를 연결한다.
   - 캡처: [theirmood-account.jpg](round2-research/theirmood-account.jpg)
2. **방명록 작성 — 입력 집중, 목록과의 연결은 더 다듬을 여지 있음.** 이름·내용·비밀번호를 받는 별도 작성 화면을 확인했다. 우리의 데모는 기존 저장 계약을 유지하며, 카드가 작성면으로 열리고 저장 후 목록의 새 카드로 돌아오는 흐름을 제안한다.
   - 캡처: [theirmood-guestbook.jpg](round2-research/theirmood-guestbook.jpg)

두 캡처는 이번 실행에서 저장 후 파일을 다시 열어 확인했다. 화면으로 전체 접근성 준수나 실제 휴대폰 입력 품질까지 검증한 것은 아니다. 샘플 데이터를 수정하지 않았다.

## 3. 새로운 버전에서 차이가 보여야 하는 여섯 장면

| 영역 | 제안하는 경험 | 하객에게 남는 정보/기능 | 과해지지 않는 제한 |
|---|---|---|---|
| 예식 날짜 | 날짜 숫자·달력·시간이 짧은 구간 안에서 한 장으로 정리되는 장면. 큰 날짜를 또 별도 섹션으로 추가하지 않는다. 달력의 6일 강조선이 완성되고 15:30 안내로 시선이 이동한다. | 2027.03.06 토요일 15:30, 달력 저장, 남은 시간 | 스크롤을 가로채지 않는다. 전체 날짜는 항상 읽을 수 있다. 큰 글씨/짧은 화면에는 정적 배치. |
| 사진첩 | 중앙 사진과 주변 사진이 느슨한 스택에서 가지런한 앨범으로 정리된다. 선택한 사진은 같은 위치에서 확대되는 느낌으로 연결한다. | 하나의 앨범, 전체 사진 진입, 확대/이전/다음/닫기 | 한 장을 보기 위해 긴 스크롤을 요구하지 않는다. 모바일 세로 스와이프는 페이지 이동으로 남긴다. |
| 오시는 길 | 지도/주소/층수가 연결된 도착 안내가 펼쳐진다. 지도 위 장식 경로는 실제 이동 경로로 오인되지 않게 사용하지 않거나 명확히 추상화한다. | 부산 목화웨딩홀, 15층 벨리스홀, 주소 복사, 기존 지도 앱 3개 | 주소·지도 앱은 효과가 끝나기 전에도 조작 가능. 확대 지도가 휠/세로 스크롤을 잡지 않는다. 주차 미확정 정보는 만들지 않는다. |
| 마음 전하실 곳 | 신랑/신부 선택 표시가 부드럽게 이동하고, 계좌 행을 누르면 복사 표식이 체크로 바뀐다. 복사한 행만 잠깐 밝아져 대상이 분명해진다. | 신랑/신부 및 양가 부모님, 숫자만 복사, 은행 앱 붙여넣기 안내 | 계좌 숫자 자체는 돌아가거나 분해되지 않는다. 복사 성공 전에 성공 모션 금지. 실제 계좌가 없는 실험안은 예시임을 명시. |
| 방명록 | 두 장의 짧은 메시지가 작은 편지처럼 겹쳐 보이고, 작성 액션에서 입력면이 열린다. 저장이 실제 성공한 다음 새 메시지가 목록에 자리잡는다. | 이름과 축하 메시지, 최근 목록/전체 보기, 내 글 삭제 | 끊임없는 자동 슬라이드 없음. 읽는 중 글을 교체하지 않는다. 입력 취소 시 초점과 스크롤 복귀. |
| 빠른 메뉴 | 스크롤 위치의 현재 섹션을 작은 표시로 알려주고, 필요한 순간 짧은 안내 패널을 펼친다. 움직이는 요소 수는 1개로 제한한다. | 날짜·지도·계좌·방명록 즉시 접근, 큰 글씨, 효과 끄기 | 본문이나 사진을 넓게 가리지 않는다. 탭/모달/모션 감소 시 안정된 위치. 44px 조작 영역과 키보드 접근. |

별도 이야기는 지금의 세 장 구조를 유지하고 입구의 크기만 줄인다. 이번 변화의 대표 캡처는 이야기 대신 날짜/사진첩/길찾기/계좌/방명록에서 만든다.

## 4. 구현 우선순위와 완료 기준

### 먼저 만드는 핵심

1. 예식 안내를 한 장의 정보로 정리하면서 스크롤 연동 차이를 눈에 띄게 만든다.
2. 사진첩은 정적인 썸네일 변화보다 스택/배열 전환과 선택 사진의 연결감을 만든다.
3. 장소·계좌·방명록은 색만 바꾸지 않고 선택·복사·작성 결과가 짧게 이어지도록 만든다.
4. 기존 손글씨·한 개의 MP3·한글 서체·정확한 예식 정보·보안 경계를 유지한다.

### 섹션별 검증 목록

- **날짜:** KST 기준 날짜/요일/시간 일치, 카운트다운 음수 없음, 저장 파일의 시간/새 실험 주소 일치. 효과를 끄거나 직접 링크로 와도 필요한 내용이 사라지지 않음.
- **사진:** 0/1/7/20장에 배열 붕괴 없음. 확대 후 이전/다음/닫기와 브라우저 뒤로/앞으로가 선택 사진·배경 위치를 보존. 사진 로딩 실패에도 닫기와 다른 사진 이동 가능.
- **지도:** 주소/층수/홀 이름 일치, 각 앱 링크 유지, 주소 복사 실패 시 수동 복사, 지도 위 세로 이동 가능. 실제 앱 실행 성공은 실기기에서 별도 기록.
- **계좌:** 양가 선택 상태 명확, 숫자 복사값 정확, 실패를 성공처럼 표시하지 않음, 번호/예금주를 분리하지 않음. 실제 정보 없는 상태는 예시/숨김 정책 유지.
- **방명록:** 빈 입력/길이/HTML 텍스트 처리, 저장 성공 후 목록 반영, 실패 시 입력 보존, 취소/완료/내 글 삭제 후 초점과 위치 복귀. 실험 저장소는 운영과 분리.
- **메뉴:** 모든 항목이 실제 섹션으로 이동, 현재 영역 표시, 숨긴 계좌/빈 영역으로 연결되지 않음, 하단 안전 영역과 음악 버튼 충돌 없음.

### 전체 검증 목록

- 320/390/430px 모바일, 768/1440px 넓은 화면, 가로모드와 큰 글씨에서 가로 넘침 없음.
- 보통/빠른/역방향 스크롤, 중간 앵커 진입, 새로고침, 브라우저 복귀에서 모든 실용 정보 읽기 가능.
- 모션 감소와 효과 끄기에서 정보·동작은 동일하고 장식 변형은 완성 상태. 장면 밖/숨은 탭/모달 배경에서 불필요한 프레임 실행 없음.
- 애니메이션을 기다리지 않고 탭·키보드·Escape로 조작할 수 있음. 네이티브 페이지 스크롤을 유지하며 긴 고정 장면을 연속 배치하지 않음.
- 손글씨 시작/건너뛰기·음악 첫 터치 대체/명시적 정지·이야기/사진 왕복 연속 재생 보존.
- 콘솔/리소스 로딩 오류, 로컬 파일 참조, 기존 버전 파일 해시 보존, 전용 Vercel 빌드 허용 목록과 다른 앱 경로 404 점검.
- 실제 성능 수치는 측정한 것만 기록한다. 데스크톱 미리보기에서 매끄러워 보인다는 이유로 모바일 60fps·LCP 통과를 주장하지 않는다.

## 5. 제외 및 다음 판단

자동 RSVP, 하객 사진 업로드, 알림톡, 축하 화환 구매, 강한 커서 추적, 3D 회전 계좌, 강제 가로 스크롤, 내용 읽기 전 긴 잠금은 추가하지 않는다. 사용자가 원한 새로움은 정보의 등장·선택·결과가 자연스럽게 이어지는 경험으로 해결한다.

완성 뒤에는 “어느 이야기가 좋은가”보다 “날짜·사진·지도·계좌·방명록 중 어떤 방식이 좋은가”를 비교할 수 있게 보여준다. 조사 표의 제안은 구현 완료 주장과 구분하며, 실제 적용·검증 결과는 해당 버전 QA 문서에 기록한다.
