# Round 2 · 사진첩 검증

새 구현은 `apps/invitation-experience/js/gallery-experience.mjs` 및 `css/gallery-experience.css`에만 추가했다. 기존 A–E와 운영 VER6 사진첩은 수정하지 않았다.

## 동작

- F: 뒤쪽 두 장의 인화사진이 중앙 사진으로 정돈되는 짧은 스크롤 진입 장면.
- G: 네 장의 콘택트시트가 중앙 대표 사진으로 모이는 진입 장면.
- 하나의 대표 사진과 전체 사진 필름스트립, 이전/다음, 현재/전체 장수를 제공한다.
- 대표 사진은 원본 비율을 보존하는 `contain`으로 보인다. 사진 설명은 추가하지 않았다.
- 전체 사진이 썸네일에서 직접 접근 가능하며, 확대는 기존 `gallery.openPhoto`를 사용해 전체화면·다운로드·이력 복귀 기능을 유지한다.
- 좌우 키, Home/End, 명확한 가로 스와이프를 지원한다. 세로 스크롤은 막지 않는다. 확대창에서 이동한 사진으로 돌아왔을 때 대표 사진 선택도 맞춘다.
- 기존 사진 목록이 갱신되면 사진 ID로 선택을 유지하며 원본 URL·썸네일·대체문구도 새 자료로 갱신한다.
- 모션 끄기·기기 모션 감소·숨은 탭·열린 대화상자에서는 지속 애니메이션을 실행하지 않는다. 모션을 꺼도 사진·선택·확대 기능은 그대로다.

## 자동 검사

`node --test apps/invitation-experience/tests/gallery-experience.test.mjs`: **9개 통과**.

1. 진입 진행값 경계 및 세로·짧은 제스처 무시.
2. 사진 ID 재정렬 유지·삭제 시 선택 경계·빈 목록.
3. 0장일 때 빈 상태 및 존재하지 않는 사진 확대 방지.
4. 1장일 때 실제 원본 확대, 이전/다음 비활성, 장식 중복 숨김.
5. 20장 전체 선택·끝/처음 순환·키보드·확대창 복귀 동기화.
6. 선택 사진의 원본 변경·빈 목록·재등록 시 오래된 이미지 제거.
7. 세로 이동 보존·가로 이동·스와이프 뒤 의도치 않은 확대 방지.
8. 숨은 탭/대화상자/모션 감소/효과 끄기 및 해제 시 리스너·프레임 정리.
9. 이미지 오류 시 확대 진입 유지·다음 이미지 성공 시 복구.

## 아직 검증하지 않은 범위

실제 휴대전화의 터치 감도·iOS 사진 저장 및 원본 다운로드 동작은 이 단위 검사로 보장하지 않는다. 브라우저의 터치 이벤트 검사는 실제 휴대전화 검사를 대체하지 않는다.

## 2026-10-28 실제 브라우저 확인

IAB의 실제 `innerWidth/innerHeight`를 읽어 크기 설정이 적용됐는지 확인한 뒤 검사했다.

- F 390×844, 320×568: 가로 넘침 없음. 7장 모두 필름스트립에서 선택 가능. 7번째 원본 이미지의 `naturalWidth=854` 로딩, 확대창 7→1 이동, 닫은 뒤 대표 사진도 1번으로 복귀, 전체 사진 창 7장 표시를 확인했다.
- G 390×844, 1440×900: 가로 넘침 없음. 4번 사진에서 End 키로 7번을 선택하며 키보드 초점과 선택 상태가 함께 이동했다. 데스크톱에서도 7개 썸네일이 모두 화면 안에 배치됐다.
- 대표사진 이미지는 `contain`으로 렌더링되어 사진의 내용을 과도하게 자르지 않는다. 선택 표시와 확대 진입은 실제 클릭으로 확인했다.
- F 검증 탭에서 관측된 console error/warn은 0건이다.
- 초판 진행 구간은 사진 전체가 보이기 전에 거의 끝나는 것을 확인해, 0.48 화면 높이 구간을 0.90 화면 높이로 늘렸다. 사진이 실제로 보이는 동안 정렬 장면이 이어지도록 수정했다.
- 최종 재빌드에서 F 390×844의 실제 사진 진입 진행값 0.5269, 이미지 배율 0.9290, 뒤 사진 회전이 남아 있는 상태를 확인했다. G 390×844는 아래쪽 키 스크롤에 따라 진행값 0.5331→0.6190, 배율 0.8319→0.8628로 변했다. 즉 단순 시간 재생이 아니라 실제 스크롤 위치에 따른 중간 상태다.
- 최종 F 1440×900은 진행값 0.5636에서 양옆 사진층이 보이는 화면을 저장했다. 모바일·PC 모두 정보/사진 클릭을 가리지 않으며 이 최종 탭에서도 관측된 console error/warn 0건이다.
