# 우리의 발자취 — 구현 검수

status: passed (등록·저장·지도 중심 UI·대표 실자료 재생·공개 배포; 실제 휴대폰 터치는 별도)

## 후속 요청 — 지도 중심 재생

사용자가 실제 Journey Studio 원본을 성우 기록으로 등록하고 지도를 가장 크게 보도록 요청했다. 원본 등록은 브라우저의 성우 선택·미리보기·명시적 추가로 완료했으며, 새로고침한 세 달의 합계가 로컬 원본 분석과 일치한다. 원본·개인 장소·좌표·실자료 화면은 저장소에 넣지 않는다.

달력과 사진/기록을 기본으로 접고 각 토글과 지도 집중, 기록 있는 날짜 앞뒤 이동을 제공한다. 지도와 재생 도구는 상단 실제 높이를 측정해 남은 화면에 맞춘다. 320/390/430/1440px 가로 넘침 없음과 재생 도구·지도 하단 화면 안착, 모바일 달력 열기·날짜 선택 복귀·독립 기록 펼치기·지도 집중을 확인했다.

60초로 압축한 하루 재생, 일시정지·이어 재생·시간 탐색·배속·시작으로를 추가했다. 실제 시간 범위는 지도 상태에서 하나로 받아 UI와 맞춘다. 사람별 원형 이동점과 상태 라벨을 표시하며 구간 사이 GPS 공백은 이전 확인점에서 `기록 공백`으로 구분한다. 사진/기록이나 달력을 접고 펼쳐도 재생 진행과 지도 중심을 유지한다.

Journey 51개 검사 통과. 최초 전체 검사에서 기존 청첩장 임시 서버의 `bad port` 1건은 해당 검사+지도/UI 33개 재실행에서 모두 통과했다. 최종 전체 2,036개 검사 및 f02c726의 Pages 40684979793 검사·배포가 성공했다. 공개 15개 파일이 빌드와 일치하며 내부 파일 4개는 404다.

실자료 대표 날짜에서 이동 시각과 경로 SVG 변화, 성우 이동점·마지막 기록, 일시정지·30% 탐색·4배속 완료·시작 복귀를 확인했다. 접기/펼치기 동안 일시정지 위치와 진행 중 재생을 유지하며, 기록 있는 이전 날짜로 이동해 날짜별 목록/경로를 다시 읽는다. 실제 NAVER SDK가 내부 호스트 너비를 고정하는 문제는 외부 컨테이너 기준 resize로 수정했다. 달력 펼침 762px/접힘 1,035px·모바일 349px에서 내부 지도와 외부 너비가 일치하고 빈 영역이 사라졌다. 모바일 재생 도구 하단은 844px 화면 안에 있고 브라우저 오류·경고는 0이다. 실제 기록 화면은 로컬 전용으로 보관한다.

## 기준과 구현

승인 기준은 기존 작업 폴더 `docs/journey-design-2026-10-28/04-calendar-records-v2.png`다. 기준 이미지와 실제 1440px 구현 캡처를 함께 비교했다. 왼쪽 달력·저장한 달, 오른쪽 날짜·사람별 보기·지도·사진 구조와 sungso 워드마크를 유지했다. 색상은 실제 sungso 공통 sky 토큰을 사용한다. 사람별 경로는 파랑·코럴·보라로 구분한다.

사용자가 이번에 승인한 범위인 타임라인 추가·사진/수동 입력·DB 재조회만 조작 가능하다. 시안의 NAVER 경로 파일·영상 만들기는 후속 범위로 분리했다. 개인 자료가 없는 상태에는 예시 사진이나 이동을 만들지 않는다. 검수 캡처의 모든 기록은 공개 장소 좌표를 사용한 합성 자료이며 운영 DB에 넣지 않았다.

긴 타임라인에서도 사진이 먼저 보이게 배치하고, 제목/시간/메모는 실제 자료를 표시한다. 사진 없는 장소에는 사진 대신 텍스트를 표시한다. 사진 확대는 입력창을 보존하며 별도 창에서 닫기/Escape로 돌아온다. 모바일에서는 달력→하루→지도→기록 순서로 배치한다.

## 실제 확인

- 320/390/430/1440px 문서 가로 넘침 없음. 지도 높이 328/363px. 320px 편집창 296px 폭, 화면 안의 스크롤/저장 버튼.
- 실제 브라우저 파일 선택 → 합성 JSON 2일 미리보기 → 명시적 저장 → 날짜 선택으로 재조회.
- 합성 JPEG의 촬영일 2026-09-12·11:30·위치 자동 채움 → 확인·저장 → 새로고침 후 같은 날짜/메모/사진 재조회.
- 위치·시각 없이 수동 기록 저장. 저장 503을 한 번 주입한 뒤 입력 유지와 재시도 성공.
- 저장 사진 전체 크기 조회(400×280 검수 JPEG)·편집창 복귀. 운영 사진은 최대 긴 변 1600px의 웹용 축소본이며 원본 백업은 아니다.
- JS 통합검사: 응답 유실 재시도 중복 방지, 파일/사람 변경 경합, 부분 import 이어받기, 다른 기기 수정 충돌과 초안 유지, 사진 확대 URL 폐기, 로그아웃 전에 DOM이 제거된 경우의 정리, 첫 로딩 중 월 선택 보존.
- 실제 원본 타임라인은 로컬 파서로만 읽었다. 59일·752개 장소·7,185개 점을 보존했으며 전후 SHA가 같다. 그 내용을 서버나 캡처에 옮기지 않았다.
- 운영 Google 회원 로그인에서 빈 달·하루 조회, 실제 NAVER 지도 타일 표시, 지도 클릭 → 입력창 위도·경도 반영 → 저장 없이 취소를 확인했다. 브라우저 오류·경고는 없었다.

## 저장·접근 경계

기존 Google 활성 회원 확인과 Render의 `/api/journey/v1`을 사용한다. 일별 JSON과 월별 요약·사진은 Firestore `journey_private/shared` 아래 저장된다. 운영 자료 검증 쓰기나 자동 시딩이 없다. 메모리 검수 서버는 운영 Firebase/Render 연결을 CSP로 차단하며 빌드 허용 목록에 포함되지 않는다.

실제 demo-homehunt Emulator 검사 63개가 통과했다. 직접 Firestore 접근 거부, 회원 전용 API, 실제 저장·재조회·동시 트랜잭션·중복 import 무쓰기를 포함한다. 모든 서비스 번들이 빌드됐다. 공개 배포 결과는 루트 AGENTS 진행 상황을 따른다.

## 제한과 다음 확인

localhost:8047 및 localhost:8000에서는 NAVER 도메인 인증이 실패했다. 지도 실패 상태에서도 기록 저장·조회·좌표 입력을 확인했으며 없는 지도를 가짜로 그리지 않았다. SDK의 동기 콜백이 전역 namespace 할당보다 먼저 실행되는 순서를 보완한 4ef66ac의 Pages 40675695465 검사·배포 성공과 운영 지도 표시를 확인했다. 공개 15개 파일은 빌드 결과와 일치했고 내부 파일 4개는 404다. 운영 실자료의 마커·경로 재생 및 실기기 터치는 자료 입력 후 확인할 항목이다. 경로 재생은 실제 시각/좌표 구간만 사용하고 GPS가 없는 구간이나 끊긴 점 사이를 만들어 잇지 않는다.

원본 파일은 사용자 기기에 별도 보관한다. 사진은 400장/160MiB, 일별 JSON은 10,000일/160MiB 한도로 제한하며 초과 시 기존 기록을 유지한다. 원본 NAVER 파일을 받은 다음 경로 형식과 MP4 연결을 검토한다.

최종 4dd5e31의 Pages 40677079158 검사·배포가 성공했다. 공개 15개 파일 일치·내부 대상 4개 404, 공개 CSS 1.0.1·지도 타일·안내 여백·가로 넘침 없음·브라우저 오류 0을 재확인했다.

합성 자료 캡처: `1440.png`, `390.png`, `320.png`, `430.png`, `photo-full.png`. 운영 화면 캡처는 원래 로컬 작업 공간에만 보관하며 저장소에 올리지 않는다. 320px 편집창 치수는 DOM에서 확인했으며, 캡처 도구의 축소 오류가 있는 편집창 이미지는 제외했다. 저장소의 문서는 정적 사이트 공개 허용 목록에 들어가지 않는다.
