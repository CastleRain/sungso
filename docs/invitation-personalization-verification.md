# 공통 사진·예식장과 원본 여섯 가지의 장면 전환

2026-09-15 작업. 현재 사용자가 명시 요청한 실제 사진·예식장의 회원 공동 저장을 추가한다. 하객용 공개 페이지, 연락처·계좌·응답 수집, 다른 앱 운영 일정 변경은 포함하지 않는다.

## 구현

- 목록과 각 미리보기의 **사진·예식장 설정**에서 대표사진 1장과 갤러리 최대 20장을 고르고 순서를 바꾼다. 대표사진은 사진형 표지의 첫 사진에 사용하며 그림·타이포 표지는 원래 구성을 유지한다. 예식장 이름·홀/층·주소·HTTPS 지도 링크·교통·주차를 29종에 반영한다. 선택 전에는 기존 가상 예시를 보여준다.
- 사진은 브라우저에서 최대 긴 변 1,600px의 JPEG로 변환하고 메타데이터를 제거한다. 원본을 보관하는 사진 백업 기능은 아니다. 데이터 URL은 장당 360,000자 이하, 갤러리 20+별도 대표 1장까지다.
- `invitation_settings/shared`와 그 `photos/{uuid}`에 두 활성 Google 회원만 접근한다. 사진과 설정은 명시 저장 때 하나의 트랜잭션으로 생성·교체·정리한다. 기존 번호와 다르면 초안을 유지하고 최신 설정을 사용자가 다시 불러온다. 조회는 시딩하지 않고 사진·예식장·회원 정보는 Git/정적 배포에 넣지 않는다.
- 사진 문서는 불변 ID를 쓰고 참조된 모든 사진을 불러온 뒤 새 설정을 화면에 반영한다. 이후 실패 시 마지막으로 확인한 설정과 오류/재시도를 표시한다. 저장 완료와 사진 표시 완료를 구분한다. 계정 전환·로그아웃은 구독·편집 초안·큰 사진·비교 화면의 개인 사진을 정리하며 기존 디자인 로컬 초안 키는 유지한다.
- Firestore의 문서/요청 크기 안에서 작은 웹 사진만 저장한다. 교체 때 읽은 기존 사진과 신규 사진 합계가 보수적 8,000,000자 한도를 넘으면 일부씩 저장하도록 안내한다. 서버 규칙은 사진 쓰기와 부모 revision·참조를 묶는다. 부모의 21개 사진 존재 여부를 규칙에서 모두 조회하는 구조는 아니며 어댑터와 완전한 사진 스냅샷 검사도 함께 사용한다.
- Spark를 유지한다. Cloud Storage는 2026년부터 Blaze 요구가 있으므로 이번에는 사용하지 않는다. [Firebase Storage 변경 안내](https://firebase.google.com/docs/storage/faqs-storage-changes-announced-sept-2024), [Firestore 한도](https://firebase.google.com/docs/firestore/quotas). 비용·무료 할당량을 무제한으로 보장하는 기능은 아니다.
- 예식 시각까지 남은 일·시간·분·초를 실제 시계 기준으로 매초 다시 계산한다. 화면이 숨겨지면 중단하고 돌아오면 보정한다. 예식 후에는 음수 대신 시작일 안내를 표시한다.
- 원본 여섯 가지는 첫 레터링 뒤 고정 화면에서 장면을 전환한다. 사진 줌아웃·종이 면 펼침·이야기 진행선을 각 두 디자인에 적용한다. 문서의 기본 스크롤을 사용하고 긴 내용의 끝까지 읽은 뒤 전환한다. 사진 확대·갤러리·이전/다음·꾸미기를 유지한다. 연출 끄기와 모션 감소에서는 전체 본문을 바로 읽는다. [공식 사례와 제안의 구분](invitation-personalization-research.md)을 따른다.

## 검증

- 최종 build/test/check: 1,718개 통과. 공개 참조 516개·JavaScript 문법 188개를 확인했다.
- Firestore Emulator: `demo-homehunt`에서 기존 청첩장 26개와 새 프로필 14개, 총 40/40 통과. 비회원/다른 문서 차단, 첫 저장 경합·revision 충돌, 사진 삭제/생성의 원자성·참조·크기/형식과 기존 선택 계약을 검사했다. 운영 프로젝트에서 실행한 검사가 아니다.
- 개인 콘텐츠 검사는 29종×사진 1/4/20장×갤러리 구성에서 사진 참조·실제 예식장 치환·정확히 한 개 타이머·선택 옵션 보존을 확인한다. 추가 통합 검사는 사진 준비/저장/구독의 순서 변화와 늦은 응답·계정 정리를 검사한다.
- 독립 `couple-qa-server.mjs` 8877 포트에서 기존 생성 예시 사진 3장과 가상 예식장만 사용했다. 대표/갤러리 분리·순서 변경·저장·새로고침 유지·다른 대역 회원 확인, 실패 입력 보존·충돌 재불러오기와 명시 재저장, 사진 누락 시 마지막 화면/오류 안내를 실제 UI로 확인했다. 처음 사진 3장+설정 4쓰기, 재저장 1쓰기의 대역 트랜잭션과 시나리오 제어를 사용했다. 운영 요청은 0이다.
- 390×844 포르투에서 첫 표지/인사 전환·갤러리 2장/확대·긴 달력 아래 타이머까지 확인했다. 전환 50%에 두 장면이 함께 투명해지던 문제는 이전 면을 유지하고 새 면을 겹쳐 해결했으며 화면 덮임 회귀 검사를 추가했다. 1440×900과 390×844 설정창의 사진·안내·입력·저장 버튼을 확인했다.

- 360×640 여섯 표지에서 다음/이전 복귀와 마지막 장면까지 이동, 가로 넘침 없음·타이머 한 개를 확인했다. 표지 간격과 사진은 실제 사용 가능한 높이에 맞췄고, 제주 이름·날짜가 한 화면에 들어간다. 1440×900의 390px 휴대폰 프레임에서 폴라로이드 표지/날짜를 확인했다. 연출 끄기 뒤 전체 본문/갤러리 복원과 로그아웃 뒤 개인 data URL 이미지 0개·JS 오류 0개를 확인했다.

## 범위와 남은 확인

실제 두 회원 계정에서 원격 사진 업로드·다른 실기기 동기화, HEIC 업로드, 실제 지도 장소 일치·하객 공유는 검증하지 않았다. 업로드 입력은 JPG/PNG/WebP를 지원한다. 브라우저 대역과 Emulator가 인증·저장의 운영 실행 자체를 대신하지 않는다. 실제 사진/예식장은 사용자가 설정해야 하며 대역 자료를 운영에 옮기지 않는다. 모션의 원본 사이트 실측값과 다른 모바일 브라우저의 성능은 확인하지 않았다.
