# 폴더 구조 정리 검증 기록

2026-09-13 기준, **로컬 자동 검사·Emulator·서비스 빌드와 데스크톱/휴대폰 UI 확인을 마쳤다. 공개 배포와 최종 운영 확인은 아직 진행 중이다.** 기존 저장 데이터·공개 URL·계산·화면 동작을 유지하면서 앱·공통 코드·서비스를 분리한 변경이다.

## 구현과 보존 범위

- 화면은 `apps/`, 금융·여행·HomeHunt 공통 로직은 `shared/`, 검색·수집·배포는 `services/`, 이전 문서·참고자료는 `archive/`로 구분했다. 등록부와 루트 명령으로 새 앱의 빌드·미리보기·검사를 연결한다.
- 공통 모듈은 소스→기존 공개 URL로 직접 출력한다. wrapper·새 별칭·query 제거 없이 캐시된 소비자와 새 소비자가 동일한 모듈·상태·오류 클래스를 참조하도록 검증했다.
- 다섯 페이지의 기존 공개 주소, 한글 견적 PDF 10개, 명시한 독립 보고서·백업 URL을 유지한다. 여행 패널은 여행에서만 로드하고 기존 `shared/decision-panel.*` 공개 주소에 출력한다.
- 변경 전 SHA-256과 이동 후 파일을 대조해 HomeHunt/Honeymoon 데이터·PDF **22개**, 유지한 CSS **46개**, `firestore.rules` **1개**의 내용이 같음을 확인했다. 사용하지 않던 Honeymoon의 주석 전용 CSS는 이 유지 파일 수에서 제외했다.
- Firebase의 프로젝트·컬렉션·앱 이름·SDK·구독/시딩 순서, PIN 실행 순서, API·브라우저 저장 키를 유지한다. 이 구조 정리로 데이터 마이그레이션이나 보안 규칙 배포를 수행하지 않았다.

## 브라우저 확인의 근거와 한계

로컬 QA 서버는 배포물 `dist/`를 `/sungso/`로 제공하고 Firebase의 `setDoc`·`addDoc`·`updateDoc`·`deleteDoc`·transaction·batch 쓰기를 차단하는 SDK 대역을 적용했다. 요청 기록에서 다섯 페이지 진입점과 PDF 10개의 HTTP 200을 확인했으며 기록된 정적 요청에 404는 없었다. 자동 쓰기 시도는 대역에서 차단되었으며 운영 DB에 전달되지 않았다. 운영 DB 쓰기와 새 통근 호출은 수행하지 않았다.

별도로 실제 브라우저의 데스크톱 1440px·휴대폰 390px에서 아래 UI를 확인했다. 확인한 다섯 앱 모두 가로 넘침이 없었다.

| 앱 | 실제 확인한 UI |
|---|---|
| Hub | PIN 통과 후 요청한 직접 주소로 복귀, 기존 일정 3개·핀된 D-day 2개 표시, 달력과 홈의 앱 링크 |
| WeCost | 네 탭을 데스크톱·휴대폰에서 전환하고 배치 확인 |
| Travel | 여섯 화면과 양쪽 크기 배치, 3월 9일→10일 날짜 선택의 세로 스크롤 변화 0, 숙소 목록·현재 공동 일정, 결정 패널 열기/닫기와 변경 이력 |
| Honeymoon | 카드·비교·토너먼트, 현재 공동 여행·이전 일정 기록, PDF 10개 각각 canvas 렌더와 휴대폰 배치 |
| HomeHunt | 양쪽 크기의 여섯 메뉴, NAVER 지도 표시, 메뉴 왕복 뒤 가격·면적 조건 유지 |

PDF 뷰어에서 리조트 견적 6개는 각각 3페이지, 패키지 4개는 8·10·7·8페이지로 인식됨을 확인했다. 파일마다 canvas 표시를 확인한 것이며 모든 페이지의 내용을 다시 검수했다는 뜻은 아니다. 접근 PIN 값과 개인 조건의 구체적인 금액은 이 문서에 기록하지 않는다.

정적 요청 로그·UI 조작·저장 동작 검증을 구분한다. 이 UI 확인은 운영 저장 성공이나 원래 사용자 인증의 완전한 확인을 의미하지 않는다. 실제 저장 성공/실패와 동시 편집은 대역·Emulator 검사 결과로 구분하며 공개 배포 후 확인은 아직 남아 있다.

**새 QA origin에서 사용자의 기존 HomeHunt 로그인과 원래 브라우저 기록을 재현해 검증하지 않았다.** 기존 사용자 탭·조건·기록을 그대로 두었으며 새 origin의 빈 기록을 원래 데이터 소실로 해석하거나 기존 기록 복원 검증 완료로 기록하지 않는다. 또한 변경 전 로컬 상태 기록에는 이 체크아웃에서 발견한 `.env`·`.local/` 파일이 없어 실제 개인 키·캐시·장부 파일 이동을 대조했다는 주장은 하지 않는다. 경로 계승 동작과 초기화 방지는 코드·대역 검사로 확인한다.

## 운영 전환과 남은 확인

현재 결과는 배포 가능한 로컬 변경의 검증이다. Pages Source/배포 artifact와 Render Build/Start·실제 배포를 전환하고, 공개 다섯 페이지·기존 주소·API 인증 경계·자동 수집→배포 연결을 확인해야 한다. 공개 완료 여부와 실행 ID는 [루트 진행 상황](../AGENTS.md#진행-상황)에 실제 확인 후 기록한다.

수집 작업·Render 자동 배포의 일시 중지/복원, 원래 데이터·사용량 장부 유지, 실패 시 이전 웹 산출물·서버 버전 복구는 [배포 안내](deployment.md)를 따른다. 원격 화면·인증 또는 실제 사용자 기록을 확인하지 못한 범위는 최종 보고에도 남긴다.
