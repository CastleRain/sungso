# 매거진 스크롤 연출 검증 — 2026-09-14

## 구현 범위

- `magazine` 한 종에 기본 활성화한다. 기존 20개 ID·저장 계약·인증·Firestore 규칙은 변경하지 않는다.
- 문서 스크롤을 사용하며 `preview-stage`를 고정한다. 사진 확대, 긴 본문 이동, 장면 전환은 현재 스크롤 위치에서 계산하므로 역방향도 같은 프레임을 재현한다. 별도의 세로 스크롤 영역이나 휠·터치 가로채기는 없다.
- 기본 구성은 표지·초대글·이야기·날짜·갤러리·길 안내·마음 전하실 곳·참석 예시·방명록 예시·마무리 10장면이다. 기존 섹션 옵션을 반영하며 장면 길이와 수를 측정한다.
- 연출 켜기/끄기, 이전/다음 장면, 장면 이름·진행 표시를 제공한다. 기기의 모션 감소가 켜지면 기존 전체 본문을 읽는다.
- 화면 너비나 콘텐츠 높이 변경·꾸미기 재렌더 시 장면 키와 진행 비율로 복원한다. 기존 DOM을 연출로 복제하지 않으며 비활성 장면은 inert 처리한다. 화면 아래 버튼에 키보드 포커스가 가면 해당 내용까지 문서를 이동한다.
- 라우트 변경·페이지 숨김·로그아웃에서 관찰자·이벤트·DOM 참조를 정리한다. bfcache 복귀에는 저장한 장면 위치를 전달한다. 연출 설정은 탭 메모리만 사용한다.

## 자동 검사

- `npm run build`, `npm test`, `npm run check` 성공: 1,597개 테스트, 정적 참조 398개, JS 문법 149개.
- 이 수치는 함께 진행 중인 홈 변경을 포함한 작업 트리 기준이다. 이번 청첩장 변경을 커밋·배포한 결과를 뜻하지 않는다.
- 새 코어 검사 6개: 역방향 동일 프레임, 긴 본문 전체 이동 후 전환, 경계·마지막 장면, 짧은 단일 장면, 잘못된 측정값, 크기 변경 뒤 논리 위치 복원.
- 새 컨트롤러 검사 3개: 원래 노드·클릭 동작·접근성 상태 보존과 예약 작업 정리, 초기/변경된 모션 감소 설정의 해제·재개, 화면 및 본문 높이 변경 후 장면과 비율 보존.
- 컨트롤러 검사는 최소 DOM/이벤트 대역이다. 실제 브라우저의 sticky·클리핑 동작은 아래에서 확인했다.

## 브라우저 확인

`tests/site/couple-qa-server.mjs`의 로컬 대역을 `/sungso/`에서 사용했다. 청첩장 저장은 메모리 대역으로 연결하고 운영 요청은 차단한다.

- 1440px PC 기본/모바일 보기, PC 프레임 360/390/430px: 화면 너비·높이, 장면 고정, 가로 넘침 없음. 390→360px 변경 후 이야기 장면 유지.
- 모바일 390×844 및 360×640: 상단 조작과 하단 꾸미기/저장 버튼 사이에 장면·이동 조작이 들어온다. 360×640에서는 본문 화면 371px, 장면 조작 43px이며 하단 고정 버튼과 겹치지 않았다.
- 네이티브 스크롤 770→898→770px에서 표지 이동 -303.139375px, 사진 배율 1.0098827003393371로 정확하게 돌아왔다. 전환 중 두 본문 글줄이 겹치지 않게 순서대로 페이드한다.
- 화면 아래 갤러리의 세 번째 사진으로 Shift+Tab 이동 시 사진 버튼이 본문 화면 안으로 나타나고, Enter 확대·Escape 닫기가 동작했다.
- 색감 변경 후 갤러리 장면 유지, 기사 챕터 선택, 일반 본문 전환 후 모든 콘텐츠와 접근성 상태 복원을 확인했다.
- 다음 필름 예시로 이동하면 매거진 장면/조작 DOM이 제거되고 필름 전체 본문을 읽는다. 확인한 브라우저 오류 로그는 없었다.
