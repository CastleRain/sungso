# Studio V2 · 계좌 등록과 받는 분 순서

2026-11-01 구현·배포 완료.

## 사용 흐름

1. 보호된 `/lab/studio-v2/`에서 **마음 전하실 곳** 장면을 선택한다.
2. **계좌 등록 · 표시 순서**에서 신랑/신부 측과 받는 분을 고른다. 본인·아버지·어머니 각 한 계좌, 총 여섯 계좌다.
3. 위/아래 화살표로 각 측 안의 표시 순서를 정한다. 숨김 계좌는 공개 화면에서 제외하며 입력과 순서는 보관된다.
4. 은행·예금주·번호, 공개 여부, 선택적인 기존 카카오페이 송금 링크를 입력한다.
5. **변경 내용 확인 → 계좌와 순서 반영**에서 확인하고 저장한다. 계좌는 기존 청첩장 데이터와 연결되므로 조합 보관/공개와 독립적으로 즉시 반영된다.

입력 중에는 같은 스튜디오의 장면을 옮겨도 유지된다. 금융 초안은 메모리에만 있고 조합 URL·IndexedDB·40개 보관함·공동 조합·내보내기에 넣지 않는다. 새로고침 전 경고, 변경 취소, 최신 계좌 다시 불러오기를 제공한다. 미리보기는 공개 가능한 완성 계좌만 전달하며 복사·송금은 실행하지 않는다.

## 호환·권한

- 기존 `wedding_accounts/sungso_20270306` schema 1에 선택적인 여섯 슬롯의 order만 추가한다. 없는 문서는 기본 순서로 읽으며 읽기만으로 생성하지 않는다.
- 이전 관리 화면의 order 없는 저장은 이미 정한 순서를 유지한다. 계좌와 순서를 함께 revision 비교/멱등 저장한다. 두 기기의 다른 변경은 409로 거절하고 입력을 유지한다.
- 기존 네 그룹 응답을 보존하며 최신 런타임용 두 측의 정렬된 sides를 추가한다. 비공개 번호·UID·전체 order는 공개 DTO에 포함하지 않는다. 옛 네 그룹 화면은 부모님을 한 그룹으로 묶고, 최신 두 측 화면은 세 받는 분의 순서를 그대로 표시한다.
- Vercel의 `/api/studio/accounts` GET/PUT은 기존 두 활성 Google 회원만 허용한다. PUT은 정확한 동일 출처/JSON/8KiB를 검사하고 기존 계좌 관리 API 한 곳으로만 전달한다. 새로운 권한·도메인·요금제 없음.
- 로그아웃/계정 변경 시 입력·검토 창·메모리와 V2 작업 화면을 비운다. 공개 청첩장과 다른 조합의 금융 데이터 QA 쓰기는 하지 않았다.
