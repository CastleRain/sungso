# Studio V2 — 선택형 장면 확장

2026-11-01. [V2 계획](../v2-analysis/PLAN.md)의 3단계를 구현·배포했다. 신규 미디어·퀴즈·공동 반응 등 4단계는 이번 범위가 아니다.

## 사용 방법

[보호된 Studio V2](https://sungso-wedding.vercel.app/lab/studio-v2/)에서 **추천 조합 → V2 · 작은 카페 초대**를 선택하면 이번 표현들을 한 번에 비교할 수 있다. 디자인 선택은 작업 초안에만 반영된다. 하객 주소를 바꾸려면 기존 **공동 저장 · 공개**에서 초안을 저장하고 명시적으로 공개해야 한다.

| 선택 위치 | 추가한 표현 | 유지하는 기능 |
| --- | --- | --- |
| 장면 더하기 → 당일 안내 패스 | 카페에서 온 초대: 영수증 종이 형태, 짧은 인쇄 등장 | 기존 날짜·시간·장소·지도·캘린더·주소 기능 |
| 사진첩 | 한 컷씩, 필름 사진첩: 필름 테두리와 가로 전환 | 사진첩 하나, 앞/뒤·스와이프·썸네일·확대, 설명 입력 없음 |
| 축하의 편지 | 한 장의 축하: 인화지 느낌의 메시지 카드 | 기존 이름·메시지·시간·삭제, 작성 중 입력 보존 |
| 전체 분위기 → 여백 → 장면 연결 | 사진 앞의 작은 숨: 84px 구간에서 선이 나비로 이어짐 | 사진첩 순서를 따라 이동, 스크롤 잠금·반복 없음 |

새 추천은 **우리다운 균형 / 작은 카페 초대 / 편안하게 읽는 초대** 3개다. 기존 추천은 접힌 ‘이전 추천 조합도 보기’에 보존했다. 추천 적용은 사용자의 문구·사진을 덮어쓰지 않는다. 기본 조합은 그대로이며 새 표현은 선택했을 때만 적용한다.

세부 옵션을 선택했을 때 상위 그룹 대신 실제 바꾼 항목을 시연하도록 수정했다. 예를 들어 여백 안의 나비 연결을 누르면 실제 사진첩 진입 구간으로 이동하고, 효과 시연 버튼도 같은 항목을 다시 보여준다.

## 데이터·접근 경계

- 형식 1, 기존 URL, 기기 보관함 최대 40개, 별점·메모·파일 형식을 유지한다. 새 값은 `receipt`, `film`, `polaroid`, `breath` 4개를 기존 허용 목록에 추가했다.
- 서버 저장·공개 검증에도 같은 값만 추가했다. 운영 방명록·사진첩·계좌·공동 초안에 QA 데이터를 쓰지 않았다. 합성 서버에서만 저장·명시적 공개를 확인했다.
- 공개 루트 VER5.6와 `/v6/`, 이전 버전·사진·음악·글꼴 및 기존 회원 권한을 유지한다. 선택만으로 운영 공개본을 변경하지 않는다.
- 전용 빌드의 기존 공개 파일 204개 중 196개가 바이트 동일하다. 8개 변경은 새 선택을 표시하는 `/published/js/` 런타임이고, 새 CSS/JS 2개를 추가했다. 전체 기존 파일이 바이트 동일하다고 주장하지 않는다. 상세는 [보존 검사](static-preservation.json).
- `/lab/studio/`, `/lab/studio-v2/`는 익명 요청 시 로그인으로 303 이동, 관리 스크립트와 API는 401이다. `/homehunt/`, `/wecost/`, `/honeymoon/`는 404다.

## 검증

- `npm run build`, `npm run check`: 전체 **2,545개 통과**. 서비스 4개 번들 빌드 통과. 새 선택의 서버 저장→명시적 공개, 추천 URL/보관함 왕복, 사진 노드 유지·키보드·확대·시연 복원, 취소·모션 감소/끄기 검사를 포함한다.
- 실제 Firestore Emulator `demo-homehunt`: 권한 **16개 통과**, 공동 초안·공개 스냅샷·사진은 클라이언트 직접 접근 금지. 다른 작업이 쓰는 8080을 건드리지 않고 별도 8189 포트로 실행했다. 운영 규칙/프로젝트에 쓰지 않았다.
- 합성 브라우저: 사진 전환·확대, 음악 진행 시간 보존과 명시적 정지 유지, 방명록 입력 보존·로컬 등록, 공동 초안 저장과 공개 분리 확인. 디자인 변경 시 음악 플레이어·미리보기 문서를 재생성하지 않는다.
- 편집기와 합성 하객 화면 모두 320/390/430/1100/1440px에서 가로 넘침 0. 새 영수증·필름·메시지·자동 시연을 실제 Chromium 화면에서 확인했다. [영수증 모바일](receipt-mobile.png), [축하 메시지 모바일](message-mobile.png), [실제 배포 필름 화면](studio-film-live.png).
- 최종 Vercel 배포 뒤 기존 루트·v6·대표 사진·새 자산 해시, MP3 Range 206, 익명 보호·다른 앱 404, Render health 200을 확인했다. [공개 검사](live-check.json).
- iOS Safari/Android Chrome/카카오톡 인앱의 실물 기기 검사는 수행하지 않았다. 브라우저 정책상 소리 자동재생이 항상 허용되는 것은 아니며 기존 작은 음악 켜기 동작을 유지한다. 프레임률 수치를 측정하지 않았다.
