# VER6.1 F/G 독립 코드 검토

검토일: 2026-10-28. 대상은 `js/experience.mjs`, `js/gallery-experience.mjs`, `js/app.mjs`, `js/guest-features.mjs`, `js/demo-data.mjs`, HTML 템플릿과 관련 CSS다. 이 문서는 실제 브라우저 QA 또는 실기기 검증을 대신하지 않는다.

## 결론

검토 중 찾은 동작 중단 관련 두 문제는 구현 담당자가 수정했고 재검사했다. 현재 코드와 테스트 범위에서 배포를 막는 기능 오류를 더 찾지 못했다. 날짜·교통·계좌·방명록·빠른 메뉴가 이야기와 독립된 기능 모션으로 구성되며, 기존 운영 API를 사용하지 않는 실험안 경계는 유지된다.

## 확인 및 수정된 문제

1. **숨은 탭/모달에서 진행 중인 피드백 애니메이션.** 처음 검토한 `experience.mjs`는 숨은 탭 또는 모달 열림에서 예약된 rAF만 취소하고 계좌/메시지 Web Animations 객체는 계속 유지했다. `cancelAnimations()`를 두 이벤트에도 연결하고, 새 애니메이션 시작 조건에도 열린 모달 검사를 추가한 것을 확인했다. 사진첩 담당자도 모달이 열릴 때 예약 프레임과 진행 중인 사진 전환을 취소했다.
2. **효과 끄기와 가상 요소.** 기존 `.motion-off *` 규칙으로는 계좌 선택 바/편지 덮개의 `::before` 전환까지 중단되지 않았다. 경험용 CSS의 `*::before`, `*::after` 규칙 추가를 확인했다. 기기 모션 감소는 기존 기본 CSS에서도 가상 요소를 포함한다.

## 새로 추가한 의미 있는 동작 테스트

`apps/invitation-experience/tests/experience.test.mjs`의 8개 테스트를 실행했고 8개 모두 통과했다. 단순 소스 문자열 일치가 아니라 EventTarget 기반 작은 DOM/프레임/MutationObserver 대역으로 실제 공개 컨트롤러를 실행했다.

| 테스트 | 확인한 결과 |
|---|---|
| 장면/선택 경계 | 진행률 유한값·0~1 범위, 비어 있는 계좌·음수·범위 밖 선택 처리 |
| 교통 수단 탭 | 클릭·좌우·Home·End 모두 하나의 패널만 노출, 선택과 tabIndex·초점 일치 |
| 양가 이후 받는 분 선택 | 한 번에 한 계좌 전체 표시, 좌우 순환·Home/End, 신랑→신부 목록 교체 뒤 ARIA 연결과 첫 선택 재구성 |
| 비어 있는 계좌 갱신 | 이전 받는 분 버튼 제거, 이후 단일 계좌가 생겨도 정상 선택 |
| 스크롤 생명주기 | 이벤트 여러 번에도 예약 프레임 하나, idle 반복 루프 없음, 숨은 탭/모달 중단 후 정상 복귀 |
| 효과 끄기 | 모든 장면이 완성 상태, 진행 중 피드백 취소, 계좌 선택 기능 유지 |
| 동작 도중 숨김/모달 | 실제 시작된 계좌 애니메이션의 취소 확인 |
| 정리 | observer 해제, 생성 wrapper/picker 제거, 계좌 행 모두 복원, 이후 이벤트의 새 프레임 없음 |

실행: `node --test apps/invitation-experience/tests/experience.test.mjs`.

## 보안·데이터 경계 검토

- `app.mjs`는 F/G와 build-selected `demo` 모드만 시작한다. 비교용 메시지는 같은 origin과 parent 출처 및 허용 액션을 검사한다.
- 계좌와 방명록은 `createDemoAdapter`를 사용한다. 계좌는 예시은행·가짜 번호·빈 송금 링크이며, 방명록 키는 경험 버전/F/G로 분리된다. 이 어댑터에는 네트워크 호출이 없다.
- 이름과 메시지는 `textContent`로 표시한다. 현재 템플릿의 체험/예시 표기가 사용자에게 보이며 운영 저장처럼 오인시키지 않는다.
- HTML CSP의 `connect-src 'self'`와 `form-action 'none'`을 확인했다. 실제 배포 허용 목록과 운영 파일 바이트 보존은 빌드/공개 검증 담당 결과로 확인해야 한다.
- 실제 관리 화면·인증·권한·운영 데이터의 변경을 이 모듈에서 찾지 못했다. 이 검토를 실서버 권한 검증으로 표현하지 않는다.

## 실제 화면에서 이어서 확인할 항목

- 320px/큰 글씨에서 날짜 티켓·지도 버튼·계좌 숫자·모달·고정 메뉴 가로 넘침과 겹침.
- 사진 위 세로 스와이프, 썸네일 가로 이동, 의도한 좌우 스와이프만 사진 변경.
- 스크롤 시작 전/중간/완성 3개 상태에서 모션 차이가 보이고 필요한 정보가 읽히는지.
- 계좌 복사 뒤 실제 clipboard 숫자, 성공 피드백의 대상 행 일치, 방명록 저장 후 새 메시지/초점/스크롤 복귀.
- 첫 손글씨·음악 단일 재생·직접 끄기·이야기/사진 왕복 유지.
- 앱 `matchMedia` 변화 → `setEnabled` 연결과 효과 끄기의 실제 CSS 결과. 단위 테스트는 기기 OS 설정 자체를 조작하지 않았다.
- 실제 휴대폰 지도 앱·OS 캘린더·공유·다운로드, 접근성 읽기 순서, 저사양 프레임 성능은 별도 검증이다. 코드 검토와 대역 테스트만으로 통과를 주장하지 않는다.
