# 우리 홈·모든 앱 검증

후속 일정 로컬 재현과 생활 앱 3개 추가·전체 앱 9개 검증은 [생활 앱 검증](life-local-verification.md)에 기록한다. 아래 내용은 그 이전의 6개 앱 대문 개편 검증이다.

2026-09-14. 밝은 커플 홈을 `우리 홈`과 `모든 앱`으로 나눴다. 기존 앱 6개를 사용하며 새 앱이나 예시 개인 기록을 추가하지 않았다. 이번 문서는 로컬 구현·자동 검사·합성 데이터 브라우저 QA 결과를 기록한다. 원격 배포와 실제 회원 검증은 포함하지 않는다.

## 변경과 데이터 보존

- 홈은 바로가기 최대 4개, 다가오는 일정 3개, 최신 메모 1개를 요약한다. 메모 전문·이전 기록·작성·삭제는 모달에서 제공한다.
- 모든 앱에서는 기존 6개 앱을 검색·그룹 분류·카드/목록 보기로 탐색한다. 페이지 기능은 앱이 늘어날 때 사용하며, 현재 6개에서는 페이지 이동 UI를 숨긴다.
- `site_home/shared`의 기존 `groups`, `apps`, `revision`, `updatedBy`, `updatedAt` 계약을 유지한다. `apps[].hidden`은 홈 노출만 제어하고, 모든 앱에서는 숨긴 앱도 계속 열 수 있다. 기존 그룹 이름·그룹 순서·앱의 그룹 배치를 보존한다.
- 기존 6개가 모두 표시된 구성은 읽을 때 앞의 4개만 홈에 보여준다. 읽기·검색·분류·보기 변경으로 저장하거나 기존 구성을 변환하지 않는다.
- 바로가기 적용을 명시적으로 눌렀을 때만 선택 순서와 홈 표시 여부를 저장한다. 기존 `saveHome()` 트랜잭션의 편집 시작 revision 비교를 재사용하며, 동시 편집 충돌 때 초안을 유지하고 최신 구성으로 다시 고르는 조작을 제공한다.
- 기존 앱 ID·공개 URL·Firebase 인증·Firestore 보안 규칙·메모 저장 계약은 변경하지 않는다. 조회 시 문서를 생성하지 않는다.

## 자동 검사

| 검사 | 결과 |
|---|---|
| `npm run build` | 앱 7개, 공개 파일 239개 생성 |
| `npm test` | 1,594개 통과 |
| `npm run check` | 1,594개 검사·공개 참조 398개·JavaScript 문법 149개 통과 |
| `node --test apps/hub/tests/view-core.test.mjs tests/site/couple-home.test.mjs` | 신규 12개·기존 19개, 합계 31개 통과 |

신규 검사는 읽기 시 원본 보존, 홈 최대 4개·전체 앱 6개, 숨긴 앱 탐색, 그룹 순서, 한글·영문·NFKC·공백·그룹 이름 검색과 교차 필터를 포함한다. 알 수 없는 ID·URL·중복 선택을 거부하고 명시적 선택 저장이 기존 트랜잭션 스키마와 충돌 보호를 유지함을 확인했다. 미래 앱 31개의 페이지 분할·경계·빈 결과·잘못된 페이지 값도 단위 검사로 확인했다.

## 합성 데이터 브라우저 QA

생성한 사이트를 `/sungso/` 경로로 열고 `tests/site/couple-qa-server.mjs`의 합성 회원·일정·메모만 사용했다. 실제 개인 기록이나 운영 회원 정보를 테스트 데이터로 넣지 않았다. 아래 저장 성공·실패·충돌 결과는 모두 대역 저장소에서 수행한 결과다.

### 한 화면 구성

| 뷰포트 | 홈 콘텐츠 하단 | 문서 높이 | 확인 |
|---|---:|---:|---|
| 1440 × 900px | 640.09px | 900px | 바로가기·일정·메모가 첫 화면에 표시됨 |
| 390 × 700px | 630.20px | 700px | 같은 세 기능이 첫 화면에 표시됨 |
| 390 × 700px, 줄바꿈 포함 500자 메모 저장 후 | 635.49px | 700px | 요약 높이 유지, 문서 가로 너비 390px |

메모 전체 길이는 모달에서 읽고 홈에서는 두 줄로 요약한다. 이 수치는 위 뷰포트의 대역 화면 측정값이며, 더 낮은 화면이나 확대 상태에서도 스크롤이 전혀 생기지 않는다는 뜻은 아니다.

### 앱 탐색과 바로가기

- `신혼` 검색 결과 1개, 일치하지 않는 검색어 결과 0개, 여행 그룹 필터 결과 2개를 확인했다. 목록 보기와 모바일 전체 앱 6개 표시도 확인했다.
- 바로가기 편집을 닫아 취소하면 대역 쓰기가 발생하지 않았다. 적용하면 기존 홈 문서의 revision이 증가했다.
- 기존 4개에 다른 앱을 더해 5개를 선택한 상태에서는 저장이 비활성화됐다. 저장 실패 후 선택을 유지했고, 원격 편집 충돌 표시·최신 구성 불러오기·재선택을 확인했다.
- 홈 바로가기 0개 저장 후 모든 앱에서 접근할 수 있었으며, 다시 4개로 복원했다.
- 현재 6개에서는 페이지 이동 UI가 숨겨지므로 브라우저에서 다음 페이지 이동을 검증하지 않았다. 31개 배열을 사용한 단위 검사 결과와 구분한다.

### 메모

- 최근 3개에서 더보기로 9개까지 확대했다. 합성 메모 9개 중 로그인한 작성자의 메모 5개에만 삭제 버튼이 나타났다.
- HTML 형태의 합성 메모를 문자 그대로 표시했으며 이미지 요소가 만들어지지 않았다.
- 500자 메모의 저장 실패 후 입력을 보존했다. 모달을 닫고 다시 열어도 초안이 유지됐고, 재시도 저장을 확인했다.
- 성공·실패 검증 중 운영 요청과 공급자 요청은 모두 0건이었다. 명시적인 대역 저장은 수행했으므로 전체 QA의 대역 쓰기를 0건으로 표현하지 않는다.

### 계정 전환과 연결 앱

- 기존 앱 정리에서 그룹 이름 변경을 저장하고, 공통 로그아웃 뒤 개인 메모·열린 모달이 남지 않음을 확인했다.
- 소희 대역 회원으로 로그인하면 직접 링크 `#apps`로 복귀하고 공유 바로가기 4개·전체 앱 6개가 유지됐다. 작성 초안은 비어 있었으며, 최근 3개 중 해당 작성자의 1개에만 삭제 버튼이 표시됐다.
- 390px에서 기존 6개 링크를 실제 클릭해 Dates·HomeHunt·WeCost·Invitation·Travel·Honeymoon 화면 진입과 홈 복귀를 확인했다. 연결 앱의 모든 기능을 다시 검증한 것은 아니다. Travel의 외부 지도 프레임은 대역 CSP로 차단되므로 실제 지도 연결 검증에 포함하지 않는다.
- 이 시점의 대역 카운터는 쓰기 5건·트랜잭션 4건, 운영 요청 0건·공급자 요청 0건이었다. 쓰기는 바로가기 적용 3건·앱 정리 1건·메모 추가 1건이며 운영 데이터와 관계없다.
- 최종 빌드를 다시 연 1440×900px 홈에서 브라우저 경고·오류 로그가 없었고, 모든 앱 화면은 앱 6개·문서 높이 900px·가로 너비 1440px였다. 변경 문서 7개의 상대 링크도 모두 존재함을 확인했다.

## 남은 확인과 배포

이번 변경의 원격 배포·실제 회원 접근은 아직 수행하지 않았다. 기존 개인 홈 계획의 이전 NAVER 키 폐기, 남은 실제 회원 QA, 사용자 보류 PDF 보호는 별도 미완료 상태를 유지한다.
