# 안으로 펼쳐지는 청첩장 — 구현·검증 기록

2026-09-14. [공식 사례 조사와 설계안](invitation-immersive-research.md)을 바탕으로 기존 20종에 새 3종을 추가했다. 실제 하객용 제작·응답 수집은 포함하지 않는다.

## 구현 범위

| 항목 | 구현한 동작 |
|---|---|
| 전체 목록 | 스크롤 소개 선반과 카드의 중복 스크롤 링크 제거. 기존 세 모음·검색·찜·비교·모바일 보기 유지. 새로운 이야기 11종, 전체 23종. 새 3종을 이야기 모음 앞에 배치 |
| 기존 예시 | 모든 등록 ID에 스크롤 보기 지원. 음반·전시·페스티벌에 별도 전환과 내부 장식 진행률 추가. 탑승권 래퍼의 상태를 유지하며 장면 수집 |
| 종이 극장 | 겹친 종이 아치 안에서 좌우 창이 열림. 사진과 이야기 세 가지 선택. 별도 약속 장면과 예식 안내 |
| 이야기의 집 | 직접 만든 CSS 입체 집의 앞벽 열림. 거실·사진방·정원 가구와 문장 선택. 정원 문이 열리는 별도 예식 장면 |
| 리본 편지 | 매듭과 띠가 풀린 뒤 실제 경첩을 가진 좌우 카드 면이 펼쳐짐. 세 이야기 선택과 약속 리본 장면 |
| 읽기·접근성 | 스크롤 위치에 연결된 순·역재생. 바로 펼침 버튼과 스크롤 복귀. 장면별 펼침 시간·긴 글의 읽기 거리. 필수 글과 버튼은 장식용 3D 요소 밖에 배치. 일반 본문·모션 감소에서는 펼쳐진 그림과 본문 제공 |

설계 보고서의 여섯 공간 카메라 이동·종이 터널 통과·개별 사물의 쪽지 열기는 후속 아이디어다. 이번 구현은 고정된 장면 내부의 물체 펼침과 방/이야기 선택이다. 새 모델 파일·동영상·WebGL 라이브러리·외부 서비스 호출을 추가하지 않았다.

기존 공개 URL·기기 초안 키·공동 선택 스키마·revision·인증 계약을 유지했다. 새 하이픈 ID의 직접 미리보기 경로를 허용하되 등록부 검증은 유지한다. 규칙 변경은 본인 찜 허용 ID 3개와 최대 목록 20→23뿐이다. 체험 상태는 메모리에만 두고 선택서·공동 문서에 넣지 않는다.

## 브라우저 확인

생성한 `/sungso/` 사이트를 `tests/site/couple-qa-server.mjs`의 합성 회원·메모리 DB에서 열었다. 대역 서버는 운영 Firebase·공급자 연결을 차단한다.

- 1440×900: 목록 23개·새 이야기 11개·새 3종 우선 배치·스크롤 소개 선반 제거. 리본 카드의 모바일 진입과 360/430px 실제 콘텐츠 너비 확인.
- 390×844: 새 세 표지를 직접 스크롤하고 다시 올려 종이 문·집 앞벽·카드 날개의 변환과 진행률이 되돌아가는 것을 확인. 리본 바로 펼침 버튼, 극장 이야기·집 사진방 선택, 집 민트 팔레트 변경 후 방/장면 유지, 정원 장면을 확인했다.
- 390×844: 기존 20종 모두 스크롤 활성화·장면 생성·마지막 ending 도달·가로 넘침 0. 페스티벌·음반·전시·탑승권·기본 디자인은 다음 장면도 확인했다. 각 예시의 모든 내부 조작을 다시 실행한 검증은 아니다.
- 360×640: 새 3종의 마지막 장면 도달, 스크롤 해제 시 장면 스타일 제거·펼침 진행률 1·예식 안내 유지·가로 넘침 0. 재활성화도 확인했다.
- 대역에서 확인한 콘솔 오류 0. 최종 서버 카운터는 쓰기·트랜잭션·거절·운영 요청·공급자 요청 모두 0이었다. 새 장면 선택 뒤 펼침이 고정되던 문제를 리뷰에서 발견했고, 선택이 펼침 상태를 바꾸지 않도록 수정한 뒤 단위·브라우저에서 확인했다.

실물 iPhone/Android, Safari, 느린 기기에서의 FPS·배터리, 화면 회전·bfcache, 실제 두 회원의 새 찜/공동 저장은 이번 브라우저 검증 범위에 포함하지 않는다. 모션 감소의 생명주기와 CSS 대체는 자동 검사·코드 검토로 확인했으며 실제 OS 설정 전환 QA로 표현하지 않는다.
