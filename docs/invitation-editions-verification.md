# 청첩장 이야기 에디션 검증

2026-09-14. 기준 master `f849827`에서 기존 12종을 유지하며 전체 이야기 8종과 목록 탐색을 추가했다. 참고한 실제 사이트와 관찰 범위는 [조사 기록](invitation-research.md)을 따른다.

## 변경

신규 ID는 magazine, film, vinyl, museum, greenhouse, scrapbook, festival, promenade다. 모든 예시는 가상 날짜·사진·문구로 구성하며 별도 하객 저장 기능은 없다. 초대글·이야기·날짜·갤러리·교통·감사·참석 예시·방명록 예시·마무리가 테마별로 이어진다. 새 모듈은 기존 앱 허용 목록의 js/css 경계 안에 배포되며 테스트·문서는 포함되지 않는다.

검색·모음·찜 필터, 목록 밀도, 4개 후보 비교, 미리보기 이전/다음 이동을 추가했다. 개수 표시와 목록은 카탈로그에서 계산하고 첫 6개만 자르는 제한은 없다. 기존 기기 초안·공동 선택 JSON과 revision은 보존한다. 새 검색·비교 값은 공동 선택서에 들어가지 않는다. 후속 모바일 보기까지 앱 내부 모듈 query를 `20260914-mobile-preview`로 함께 갱신하며 Firebase SDK·인증 모듈 URL은 유지한다.

Firestore 변경은 본인 찜의 허용 ID 8개 추가와 목록 최대 12→20뿐이다. 회원 확인·상대 찜 보호·공동 선택 revision 계약은 유지한다.

## 실제 검증

- `npm run build`, `npm test`, `npm run check`: 1,576개 검사, 정적 참조 394개, JavaScript 문법 146개 통과.
- 실제 localhost `demo-homehunt` Firestore Emulator: 16개 통과. 새 8종 각각 찜·공동 선택, 20종 전체 찜, 잘못된 ID/21개 목록·상대 찜 수정 거부, 기존 충돌 계약을 확인했다.
- `tests/site/couple-qa-server.mjs`, 포트 8876, 합성 회원·데이터만 사용했다. CSP가 외부 API 연결을 차단하며 운영 데이터·지도·통근 공급자를 호출하지 않는다.
- 1440px/390px에서 새 8종의 본문과 여덟 data-section, 문서 스크롤을 확인했다. 본문 높이는 약 5,600~7,300px이며 문서 가로 넘침은 없었다. 비교는 모바일 2열·데스크톱 최대 4열, 목록은 모아보기·크게 보기를 제공한다.
- 검색으로 음반 한 개 찾기, 검색 해제·모음 필터, 비교 후보 추가·비교 화면에서 미리보기·목록 복귀, 키보드 Enter 후 포커스 유지 확인.
- 음반 B면·트랙·유한 회전, 필름 2단계 현상·리셋·갤러리 숨김/복원, 전시실 변경·세 번째 사진 확대, 매거진 기사 전환, 온실 계절·개화와 팔레트 변경 후 유지, 스크랩북 페이지/스티커, 축제 무대·산책 지점 변경 확인.
- 실제 찜·공동 선택 UI는 합성 DB에만 저장하여 성공과 기존 목록 복귀를 확인했다. 체험·검색·비교만 수행한 동안 대역 쓰기 0, 명시적 찜·공동 선택으로 2건 저장됐다. 실운영 DB 쓰기는 없다.
- 기존 12종의 전체 미리보기도 데스크톱에서 모두 열어 렌더·가로 넘침을 확인했다. 실제 공통 로그아웃 후 미리보기 DOM이 사라지고, 소희 합성 계정으로 다시 진입하는 것을 확인했다. 최종 브라우저 오류 로그는 비어 있었다.
- 모션 감소는 새 컨트롤러의 즉시 상태 전이와 CSS 조건을 확인했다. 운영체제의 모션 감소 설정을 변경하는 검증은 하지 않았다.

## 후속 — 모바일로 보기

- 각 카드에 모바일 보기 링크, 미리보기 상단에 기본/모바일 토글과 PC용 360·390·430px 선택을 추가했다. 휴대폰 프레임은 문서 전체 높이로 이어지며 내부 세로 스크롤은 없다. 실제 작은 화면에서는 프레임과 여백을 제거한다.
- `.invitation`을 이름 있는 inline-size 컨테이너로 두고 콘텐츠 폭 규칙 7곳과 시그니처의 viewport 글꼴 3곳을 컨테이너 기준으로 바꿨다. 앱 목록·상단 UI의 화면 크기 규칙과 모션 감소 조건은 유지한다.
- 보기 방식·너비는 탭 메모리만 사용한다. 토글과 너비 변경은 기존 초대장 DOM을 유지하므로 체험을 다시 시작하지 않는다. Firestore·인증·공동 선택 JSON 변경은 없다.
- `npm run build`, `npm test`, `npm run check`: 1,576개 모두 통과. 공개 파일 235개, 정적 참조 395개, JS 문법 146개. 최초 sandbox 실행은 localhost listen EPERM으로 실패했고, 포트 허용 후 정상 완료했다.
- PC 1440px에서 버튼으로 모바일 진입, 콘텐츠 폭 360/390/430px 선택을 각각 측정했다. PC의 390px 보기와 모바일 배치의 가용 콘텐츠 390px에서 봉투 제목 58.5px·우편 헤더 좌우 20px, 탑승권 제목 30.42px가 일치했다. 검증 브라우저는 15px 스크롤바가 있으므로 이 대조에는 viewport 405px를 사용했다.
- viewport 390px(가용 콘텐츠 375px)에서 기존 12종과 새 8종의 본문·전체 문서 스크롤·가로 넘침 없음·프레임 숨김을 확인했다. 새 8종은 data-section 8개씩 유지됐다. 실제 휴대폰 하드웨어 검증을 뜻하지 않는다.
- 필름 현상 1단계 후 기본 보기→Enter로 모바일 복귀 시 단계와 포커스를 유지했다. 모바일 꾸미기에서 팔레트 변경 후에도 현상 단계·모바일 모드가 유지됐고 사진 확대/닫기도 확인했다.
- 후속 검증의 대역 쓰기는 시작/종료 모두 누적 2건으로 새 쓰기 0건, 운영 요청 0건, 최종 브라우저 error 로그 0건이다. 이번 변경은 로컬 미리보기에 반영했고 원격 배포 상태는 아래와 같다.
