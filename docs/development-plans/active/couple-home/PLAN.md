# 구현 계획: 성우·소희의 개인 홈

## 확정 방향과 기본값

- 기존 /sungso/ URL을 유지한다. 공개 코드·빈 UI는 허용하지만 개인 일정·메모·재무·여행 자료와 파일은 인증 뒤에만 접근한다.
- 개인 Google 계정 두 명만 허용하고 개인 기기에서 로그인을 유지한다. 4자리 PIN이나 기존 로컬 플래그는 데이터 접근 권한으로 사용하지 않는다.
- 비용이 추가되지 않는 기존 Firebase·Render 구성을 사용한다. Firebase Storage/Blaze 전환은 하지 않는다. 개인 PDF는 Google Drive 제한 공유를 사용한다.
- 밝은 흰색 바탕, 분홍 포인트와 옅은 민트·하늘색, 산뜻한 산세리프 글꼴을 기본으로 한다. 시안의 팔레트 비교 도구는 제품의 테마 설정 기능이 아니다.
- 홈 구성은 두 사람이 공유하고 기기 간 동기화하는 기본값을 채택한다. 개인별 홈 설정은 이번 범위에 넣지 않는다.

## 홈·날짜·편집

첫 화면은 짧은 인사, 용도별 앱 바로가기, 다가오는 일정 3개, 최근 공유 메모 3개 순서로 구성한다. 날짜 중심 기존 화면은 /sungso/dates/로 이동한다. 홈에서도 날짜 화면으로 접근할 수 있어야 한다.

| 기본 그룹 | 앱 |
|---|---|
| 일상·집 준비 | 우리의 날짜, HomeHunt |
| 결혼 준비 | WeCost, 모바일 청첩장 |
| 우리의 여행 | Travel, Honeymoon |

홈 편집은 앱 숨김·복원, 그룹 내 순서 변경, 다른 그룹으로 이동, 그룹 이름·순서 변경, 취소·적용을 제공한다. 빈 그룹은 홈에서 숨기고 모든 앱이 숨겨져도 편집 진입·복원이 가능하다. 임의 앱 설치·삭제와 그룹 생성·삭제는 제공하지 않는다. 앱 목록은 기존 앱 등록과 일치하는 명시적 ID/URL 목록을 사용한다.

공유 홈 설정은 회원 전용 문서에 앱 ID·그룹·순서·숨김 상태와 revision을 저장한다. 저장은 편집 시작 revision을 비교하는 트랜잭션으로 수행하며 충돌 시 초안을 보존하고 최신 구성 재확인을 안내한다. 취소는 저장하지 않는다. 새 앱은 기존 설정을 지우지 않고 기본 그룹 마지막에 보충한다. 알 수 없는 앱 ID는 실행 링크로 사용하지 않는다.

날짜 화면은 기존 events 계약과 D-day·고정 일정·목록·달력·추가·삭제 동작을 보존한다. 기존 일정은 다시 시딩하지 않는다. 날짜 정렬은 기존 날짜 의미와 한국 시간대를 유지한다.

home_notes에는 최대 500자 일반 텍스트, 작성자 UID, 서버 작성 시각을 저장한다. 회원만 읽고 작성하며 작성자만 삭제한다. 최근 3개와 이전 메모 더보기를 제공한다. 출력은 텍스트로 처리한다. 시안의 메모·일정은 예시이며 실제 데이터가 아니다.

## 인증과 데이터 경계

shared/firebase에 공통 인증·회원 상태 모듈을 추가한다. 관리자만 관리하는 site_members/{uid}의 활성 회원이며 검증된 Google 로그인인 경우만 허용한다. 회원 역할은 sungwoo/sohee에 대응한다. 브라우저에 이메일 목록을 넣는 방식만으로 권한을 판정하지 않는다.

기존 homehunt-private-cloud 인증을 기준으로 같은 프로젝트의 명명 앱에 updateCurrentUser를 적용한다. [DEFAULT], homehunt-private-cloud, sungso-travel, sungso-travel-budget, sungso-invitation 이름과 SDK 10.12.0을 보존하고 이름으로 앱을 선택한다. getApps()[0]에 의존하지 않는다. 초기화와 인증 동기화가 끝나기 전 개인 데이터 조회·구독·시딩·환율 저장을 시작하지 않는다.

로그인 후 원래 직접 링크로 복귀하되 같은 origin의 /sungso/ 내부 경로만 허용한다. 로그아웃·계정 전환 시 구독을 해제하고 늦게 도착한 비동기 결과를 무효화하며 개인 화면·메모리를 비운다. 기존 로컬 초안과 개인 기록은 임의 삭제하지 않고 비인증 상태에서 가린다. 인증 복구 실패·권한 거절 시 개인 콘텐츠를 먼저 보여주지 않는다.

Firestore 개인 컬렉션 전체를 조사하여 현재 공개 허용 규칙을 회원 제한으로 교체한다. 겹치는 match의 OR 허용 우회를 검사한다. HomeHunt homehunt_user_snapshots의 본인 UID 제한은 유지한다. 회원 문서의 클라이언트 쓰기는 금지한다. 자동 시딩을 포함한 운영 DB 쓰기는 테스트에서 금지한다.

## 연결 앱 보존

모바일 청첩장은 비교·찜·공동 선택 도구다. 실제 하객용 초대장은 별도 범위다. /sungso/invitation/, #preview/{id}, #selection과 기존 템플릿·모션·필터·스크롤·로컬 초안을 보존한다. sungso-invitation 앱, couplePicks/invitation_templates 문서, sungso_invitation_v1 로컬 키를 유지한다. favorites.sungwoo/sohee의 본인 부분만 중첩 병합하고 상대 찜 수정은 규칙으로 거부한다. selection·selectionRevision의 충돌 보호를 유지한다. 수동 작성자 선택을 인증된 회원 역할로 대체하고 updatedBy/At를 검증한다.

Travel–WeCost 예산은 기존 wecost_items의 신혼여행 항목과 itineraries/honeymoon_2027_budget, honeymoon_fx/usd_krw, honeymoon_2027_budget_log_* 계약을 유지한다. 장부·상세안·이력을 원자적으로 저장하고 편집 원본 비교를 보존한다. 작성자는 sungso_trip_actor 로컬 선택 대신 인증에서 얻는다. 과거 이력은 수정하지 않는다. 현재 itineraries/honeymoon_2027와 이전 읽기 전용 itineraries/main을 혼동하지 않는다. 출발 준비를 포함한 최신 Travel 화면과 HomeHunt 개인 기록을 보존한다.

## 공개 자료와 서버 비밀값 정리

허브 이벤트 시드, WeCost 개인 재무 기본값, Travel HTML·shared/travel/trip-data, Honeymoon 견적·일정 기본값 등 정적 개인 자료를 조사하여 인증된 데이터 저장으로 옮긴다. 이미 존재하는 운영 데이터가 항상 우선하며 마이그레이션은 백업·건수·비민감 해시를 비교하고 재실행 시 덮어쓰지 않는다. 개인 데이터가 HTML/JS/JSON/호환 출력에 남지 않게 검사한다.

개인 PDF 10개를 재확인해 Google Drive 제한 공유(소유자와 상대 계정)로 옮긴다. 링크·메타데이터는 회원 전용 Firestore에 보관하고 Drive 뷰어로 연다. 브라우저의 Drive 계정 세션이 별도로 필요할 수 있으므로 접근 실패 시 계정 확인을 안내한다. 무료 용량 내에서 수행하며 유료 전환하지 않는다. 공개 PDF와 호환 복사본은 현재 소스·배포 허용 목록에서 제거한다.

기존 Honeymoon firebase-naver.js의 브라우저 자격증명과 공개 프록시 경로를 제거한다. 실비밀값은 로그·문서에 출력하지 않는다. 유효 여부 확인을 위한 공급자 요청 없이 노출 자격증명의 폐기·교체를 진행한다. 기존 인증된 Render API로 연결하고 default Firebase naverBlogSearch/apartmentHistory의 실제 배포·사용 여부를 확인해 사용 중이면 인증을 보호하고 미사용이면 안전하게 중단한다. 새 로컬 통근 원호출은 0회다.

저장소가 공개이므로 현재 파일 삭제만으로 과거 Git 기록이 비공개가 되지 않는다. 과거 노출 목록은 비밀값 없이 기록하고 Git 이력 재작성은 별도 후속 작업으로 남긴다. 외부에 복제된 자료 회수를 보장하지 않는다. 이번 완료는 현재 배포·데이터 접근 경계의 완료이며 과거 노출 완전 해소로 표현하지 않는다.

## 전환·검증·완료

두 회원 등록·제한 공유·백업을 확인하고 인증 준비된 웹·서버와 보안 규칙을 조율해 전환한다. 개발은 대역/Emulator에서 수행한다. 운영 마이그레이션은 dry-run 차이 확인 후 기존 값 보존 방식으로 수행하고 실제 사용자 데이터와 테스트 데이터를 섞지 않는다. 실패 복구에서도 공개 허용 규칙으로 되돌리지 않는다.

npm run build, npm test, npm run check를 실행한다. 서버 변경 시 의존성을 설치한 뒤 npm run build:services와 Firestore Emulator 검사를 순차 실행한다. 1440px/390px에서 인증 복구·두 회원·비회원·로그아웃·앱 직접 접근, 홈 편집 취소/충돌/전체 숨김 복구, 메모 권한, 날짜 보존, 청첩장 동시 변경, Travel–WeCost 원자 저장, HomeHunt UID 격리를 대역에서 확인한다. 운영 DB 쓰기와 통근 요청 없이 공개 자산·차단 경계를 확인한다.

실제 Pages·필요 서버·규칙 배포 성공과 사용자 계정에서의 접근 확인까지 근거를 기록한다. 실행하지 못한 검증은 미완료로 남긴다. 모든 체크리스트 완료 후 RESULTS.md 작성 및 completed 이동·색인 갱신을 수행한다.
