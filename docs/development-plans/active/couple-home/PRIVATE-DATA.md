# 개인 자료 전환 구현·검증

2026-09-13 작업 기록. 운영 실행·배포 증거는 최종 RESULTS와 운영 runner의 비민감 evidence로 별도 확인한다.

- Travel HTML의 개인 본문, 공통 여행 기준, 달력의 날짜별 이동, 호텔 날짜·항공 검색 주소, 후보 견적, 출발 준비를 회원 전용 `private_data/travel_reference`로 추출했다. 공개 모듈은 빈 컨테이너이며 공통 인증 완료 후 기준 자료와 화면을 로드한다. 이전 자료가 없거나 권한이 없으면 개인 기본값을 표시하지 않는다.
- 기존 Travel 여덟 화면·직접 hash·11일 일정의 구조, 지도·선택·명시적 저장·WeCost 장부/세부안/이력 계약을 유지한다. 여행 순수 로직은 기준 데이터가 로드된 뒤 현재 ID·날짜를 판정한다. 수동 작성자 선택과 PIN 폴링은 인증된 회원 이름 표시로 바꿨다.
- Honeymoon 리조트·여행사·견적 기준을 `private_data/honeymoon_reference`로 옮겼다. 가격 조건과 리조트 함수 API, 지연 탭·이전 일정·picks·현재 여행 연결을 유지한다. 리조트 D-day는 보호된 현재 여행의 숙박 시작일을 사용하고 과거 견적 기준일과 구분한다.
- 개인 자료가 중복된 Honeymoon report/XML은 검증된 비공개 백업 뒤 보관 안내로 치환했다. WeCost를 포함한 공개 호환 사본의 배포 제외는 루트 등록부에서 함께 처리한다.
- 브라우저 Naver 자격증명과 공개 CORS 프록시를 제거했다. 사용자 요청으로만 회원 토큰을 넣어 기존 Render의 `/api/blog-search`를 호출한다. 새 후기 캐시·메타 저장은 서버로 옮기고 후기 고정/숨김을 보존한다. 공급자 호출로 과거 키 유효성을 시험하지 않았다. 실제 키 폐기·교체와 서버 배포/설정은 확인된 별도 증거가 있어야 완료다.

사용자 변경 지시: PDF는 GitHub에 그대로 둔다. PDF 10개·기존 URL·PDF.js 뷰어는 변경하지 않았다. Drive 제한 공유는 보류이며 **개인 PDF의 공개 접근은 유지된다**. 현재 배포의 개인 자료가 모두 비공개라는 주장을 하지 않는다. 과거 Git 이력의 노출도 별도 정리 대상이다.

## 백업과 마이그레이션

소스 백업 54개와 PDF 10개(총 4,922,926 bytes)의 원본/복사 SHA-256을 비교했다. 백업 source inventory SHA-256은 `29c38895d9cbb642e8350fd8423ded25f1f0d395ffd2fa13889256fae72bd833`이다. 백업·원문·파일 목록·계정 식별자는 Git 제외 로컬 출력에만 보관한다.

`scripts/private-migration/`에 외부 자격증명 주입 방식의 REST 도구를 추가했다. 개인 컬렉션·하위 댓글 백업, 미분류 컬렉션 확인, backup/manifest/dry-run 해시 검증, 기존 값 보존, `exists:false` 전제조건의 원자 생성, 저장 후 해시 비교를 제공한다. WeCost 설정/저축의 복구 기본값도 변경 전 소스에서 읽으며 현재 DB 값이 있으면 보존한다. payload는 중첩 배열을 보존하기 위해 JSON 문자열로 저장한다. 실제 운영 실행 여부와 건수는 이 문서의 도구 구현 완료와 구분한다.

## 통합 후 추가 감사

현행 소스와 당시 생성된 dist의 텍스트 716개에서 과거 노출 Naver 자격값과 실제 회원 이메일을 정확 일치 방식으로 검사하여 0개를 확인했다. 실제 여행 ISO 날짜는 명시적 과거 이력 문서 3개에서만 발견됐다. 사용자 보존 예외인 PDF 내용과 Git 과거 기록의 회수는 이 검사 범위에 넣지 않았다.

WeCost의 이전 guide, 세 앱의 현재 README, 청첩장 QA 날짜와 특별 디자인의 남은 월/일을 비공개 백업 후 일반 안내·인공 날짜로 정리했다. HomeHunt 재무 fixture의 과거 실제 예식 날짜도 날짜 간격을 보존하는 인공 연도로 변경했다. 해당 fixture의 0이 아닌 금액은 개인 WeCost 기본값과 동일한 필드가 없었다.

보관한 HomeHunt 개인 백업의 목적지 3곳에서 검색/주소 토큰 5개를 추출하여 현행 소스 358개와 비공개로 대조했다. 실제 목적지와 일치하던 Naver 검색 fixture 한 곳을 인공 장소명으로 바꾸고 재검사 0개를 확인했다. 운영 화면의 기본 목적지 배열과 회사 주소는 빈 값이다. 공개 부동산·역 자료의 일반 지명은 개인 회사 선택 자료로 취급하지 않았다.

이전 Travel 공통 export 4개·Honeymoon export 3개·Travel의 보호 본문을 마이그레이션 payload와 해시로 비교하여 모두 일치했다. 여행 날짜/이동 11개, 준비 7개, 결정 10개와 필수 날짜 설정·항공 주소·견적 금액/통화/메모의 존재를 확인했다. 추가로 청첩장 core/경험 25개, HomeHunt 재무 18개, Naver 검색 7개 검사가 통과했다. 실제 변경 값을 보고서나 출력에 기록하지 않았다.

## 회원 변경·로그아웃 생명주기 보강

공통 정리 시점에 구독을 해제하고, 이미 대기 중인 Firebase 콜백도 시작한 회원 UID/역할과 비교해 차단한다. WeCost 설정·저축이 없을 때 자동으로 문서를 쓰던 경로를 제거했다. 기존 DB 값을 우선하고 누락 상태는 0/빈 날짜의 화면 값만 사용한다. 목표 집값 저장의 순서 검증, 여행 장부 연결과 기존 localStorage 초안을 보존한다.

Honeymoon의 환율·댓글·메타·이미지·picks·일정·후기 구독과 비동기 읽기/쓰기를 회원 작업 범위로 묶었다. 환율 캐시 읽기 후 계정이 바뀌면 외부 조회를 시작하지 않고, 환율 응답이 늦게 도착해도 Firestore에 쓰지 않는다. 이미지/후기/선호의 늦은 읽기는 반환하거나 후속 쓰기를 시작하지 않는다.

Travel 일정과 여행 예산 저장은 각 트랜잭션 읽기 전후에 캡처한 회원을 확인한다. 계정 전환 후 두 번째 읽기나 원자 저장을 시작하지 않으며, 원래 작성자 UID·상태/장부/이력의 원자성·최근 50개 조회를 유지한다. 로그아웃 뒤 늦은 스냅샷이 비운 상태를 복구하지 못한다.

Invitation은 교체한 구독과 폐기한 저장소의 늦은 콜백을 차단하고, 진행 중 저장/모듈 연결이 끝나도 이전 화면에서 성공으로 처리하지 않는다. HomeHunt는 공통 정리에 기존 세션 종료를 연결하고, SDK 초기화·Auth 콜백·토큰·API JSON 처리 중 종료되어도 개인 상태나 요청 권한을 복구하지 못하게 했다. 앱 URL, 디자인 12종, 개인 로컬 기록·초안, 기존 계정 백업 경로는 그대로 유지한다.

대상 6개 테스트 파일의 77개 검사 통과. SDK/HTTP는 모두 메모리 대역이며 운영 데이터·외부 공급자를 호출하지 않았다. 전체 검사에서 발견한 HomeHunt 목표 집값 VM의 새 작업 범위 주입 누락을 수정한 뒤 **최종 `npm run check`: 1,519/1,519개, 로컬 참조 365개, JavaScript 문법 137개 통과**를 확인했다. 최신 `dist`에 공통 작업 범위 모듈을 포함했다. Windows sandbox의 상위 경로 탐색 제한으로 실패했던 서비스 빌드는 동일 로컬 명령의 승인된 실행으로 **`npm run build:services`: Render·HomeHunt Functions·기본 Functions 3개 번들 모두 성공**했다. 원본 로그는 Git 제외 로컬 폴더에 보관한다. 이 결과는 배포 성공이나 실제 회원 브라우저 검증을 대신하지 않는다.
