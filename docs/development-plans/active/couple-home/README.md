# 우리 둘의 홈·인증 전환

상태: **구현·Pages/Render/규칙 배포 완료, 일부 완료 조건 대기**. [결과·남은 작업](RESULTS.md), [진행·검증 기록](PROGRESS.md)을 함께 확인한다. PDF·NAVER 키 교체·소희 전체 앱 및 성우 Honeymoon/HomeHunt 실제 접근 검증이 남아 `active`를 유지한다.

결혼 D-day 중심 첫 화면을 성우·소희의 개인 홈으로 바꾸고, Google 계정 두 명만 개인 데이터에 접근하도록 전환한다. 모바일 청첩장과 여행 예산 연동도 포함한다.

## 읽는 순서

1. 저장소 루트 README·AGENTS와 docs/architecture.md, 변경할 앱·서비스의 AGENTS를 읽는다.
2. [구현 계획](PLAN.md)과 [체크리스트](CHECKLIST.md)를 읽는다.
3. [실행 가능한 프로토타입](prototype/index.html)을 브라우저에서 열고 [시안 안내](prototype/README.md)를 확인한다.

## 다른 컴퓨터에서 요청할 프롬프트

> 저장소를 최신으로 갱신한 뒤 docs/development-plans/active/couple-home/README.md와 연결된 계획·체크리스트·프로토타입을 읽고 구현해줘. 최신 AGENTS.md와 현재 구현을 먼저 확인하고 모바일 청첩장과 Travel–WeCost 예산 기능을 보존하면서 반영해줘. 진행 상황과 검증 결과를 계획 폴더에 기록해줘. 완료 조건을 모두 충족하면 RESULTS.md에 변경 사항·검증·커밋·배포 근거를 남기고 폴더를 docs/development-plans/completed/couple-home/으로 옮겨줘. 미완료 항목은 완료로 처리하지 말고 다음 작업을 명확히 남겨줘. 최종 변경은 git commit·push하고 배포 결과까지 확인해줘. 실제 계정·Drive 권한·자격증명 처리를 위해 내 입력이 필요한 부분은 구체적으로 알려줘. 운영 DB에 테스트 기록을 쓰거나 새 과금을 활성화하지 마.

## 시작 조건과 기록

원격 master의 최신 구현을 기준으로 시작한다. 이 계획 작성 기준은 2026-09-13, master 09b190a이며 청첩장 12종과 여행 예산·출발 준비가 포함되어 있다. 이후 추가된 앱도 등록부와 실제 저장 계약을 재검토한다. 다른 작업의 변경을 덮어쓰거나 함께 커밋하지 않는다.

두 Google 계정 UID와 회원 등록, 비공개 Drive 파일 공유, 데이터 백업, 노출 자격증명 폐기·교체에는 실제 접근 권한이 필요하다. 계정 식별자·비밀값·개인 파일 링크는 공개 문서에 기록하지 않는다. 접근 권한이 없어 미완료인 작업은 체크리스트에 명시한다.

개발 중 체크리스트와 진행 기록을 갱신한다. 모든 완료 조건 충족 후 RESULTS.md를 작성하고 이 폴더 전체를 completed/couple-home으로 이동하며 개발 계획 색인과 인계 경로를 갱신한다. 이동 후에도 내부 상대 링크는 유지한다.
