# sungso 서비스 정리와 UI 개발 스프린트 계획

2026-11-03 · 관리 앱 14개 메인 화면 및 연결된 기존 기능

sungso를 업무별로 묶고, 각 화면에서 지금 필요한 행동만 먼저 보여준다. 선택한 2번의 사이드바와 밝은 글래스 방향을 사용하되, 앞선 이미지의 반복 D-day·큰 소개 영역·불필요한 요약은 그대로 구현하지 않는다. 기능을 실제로 없앨 항목과 화면에서만 접거나 옮길 항목을 구분한다.

1인 전담 기준 **28~37작업일, 약 6~8주**를 초기 범위로 잡는다. 첫 공통 화면과 실제 전환은 분석을 포함해 **6~8작업일**에 검토할 수 있다. 단순 질감 전환의 이전 추정보다 서비스 분석·메뉴 정리·두 모드 회귀 검증이 추가된 범위다. 운영 사용 흐름과 세부 화면 수를 확인하는 Sprint 0에서 다시 산정한다.

## 유지할 기준

- 첫 방문의 기본값은 현재 원래 화면이다. 기본 모드의 기존 배치·스타일·익숙한 편집 흐름을 유지한다.
- 글래스를 처음 선택하면 밝게 시작한다. 이후 사용자가 고른 표시 설정을 복원한다. 이번 1차 범위는 기본과 밝은 글래스이며, 어두운 글래스의 전체 확장은 후속으로 둔다.
- 기존 기능은 양쪽에서 접근할 수 있다. 글래스에서 중복 입력을 한 곳으로 모으거나 보조 메뉴를 접어도 기능·원본 데이터·계산·권한은 같아야 한다.
- 기능 없는 빈 탭과 반복 장식은 글래스에서 제외한다. 기능 폐기나 저장 데이터 삭제는 별도 항목으로 판단한다. 이번 분석에서 즉시 폐기할 핵심 서비스는 확인되지 않았다.
- 공개 청첩장 VER2~5의 작품 화면·기존 URL은 유지한다. 해당 버전의 manage/responses/accounts도 이번 공통 스타일 교체에 자동 포함하지 않는다. 관리 범위는 Invitation 카탈로그와 Wedding 관리 화면 및 기존 작업실 연결이다.
- 조회 실패·미확인 금액·전망 보류·로컬 저장 안내·출처·저장 충돌은 화면을 간결하게 만들더라도 지우지 않는다.

## 사이드바와 첫 화면 구성

전역 이동은 **우리 홈 + 6개 업무 그룹**으로 줄인다. 안쪽 사이드바에는 현재 업무 메뉴만 두어 전역 즐겨찾기와 같은 링크를 반복하지 않는다.

| 전역 그룹 | 내부 서비스 |
| --- | --- |
| 돈 | WeCost의 5개 메뉴 |
| 집 | 탐색 HomeHunt / 판단 HomeHunt VER2 |
| 여행 | 여행 일정 Travel / 리조트 비교 Honeymoon |
| 결혼 | 하객·준비 Wedding / 청첩장 선택 Invitation |
| 일상·기록 | 일정 Dates / 식탁 Table / 장소·데이트 Footprints / 이동·사진 Journey |
| 작업실 | 매출 분석 / 소희 작업실 / 포트폴리오 예시 보조 링크 |

이 분류는 글래스의 표시용 매핑이다. 현재 공유 홈 문서가 허용하는 6개 앱 ID와 3개 그룹을 임의로 다시 저장하지 않는다. 기존 공유 바로가기·순서·숨김 설정은 보존하며, 새 그룹을 선택해도 자동 저장·마이그레이션을 하지 않는다. 모든 앱 목록에서는 각 앱 이름으로도 찾을 수 있어야 한다.

홈은 기존 4개 바로가기·일정 3개·최근 메모를 활용한다. 새로운 금융/후보 통계 집계 저장소는 만들지 않는다. D-day는 홈·일정·결혼처럼 의미가 있는 곳에만 둔다. 모바일에서는 두 사이드바를 항상 차지하게 하지 않고 하나의 메뉴 서랍과 현재 위치로 전환한다.

각 화면은 제목, 핵심 상태, 주 행동, 실제 작업 영역 순으로 정돈한다. 모든 앱을 같은 카드 대시보드로 만들지 않는다. WeCost와 매출의 표, 집과 Journey의 지도, 일정의 달력은 각 작업에 맞게 유지한다. WeCost의 익숙한 작은 글자·행 밀도·결혼비용 표 위치를 존중하며 다른 앱 글꼴을 전부 바꾸지 않는다.

## 데이터와 기능을 공유하는 방법

| 항목 | 현재 원본과 계획 |
| --- | --- |
| 홈과 Dates | 동일 events. 홈은 요약, 편집은 Dates. 새 일정 사본을 만들지 않음 |
| 여행과 WeCost | 기존 wecost_items 신혼여행 항목 하나와 공통 예산 저장소. 합계를 맞추기 위해 새 비용을 생성하지 않음 |
| Travel와 Honeymoon | 현재 여행 honeymoon_2027 편집은 Travel. Honeymoon은 비교와 요약, main은 이전 기록 읽기 전용 |
| 두 HomeHunt | 일부 공유 기록·API를 재사용하지만 조건과 판단 흐름은 독립. UI 묶음이 데이터 이관을 뜻하지 않음 |
| Journey와 Footprints | 공동 이동·사진 기록과 계정별 로컬 장소 기록은 별개. 한쪽을 다른 쪽으로 자동 이전하지 않음 |
| 생활 앱과 Wedding | UID별 브라우저 저장. 새 테마가 상대 계정·다른 기기와 공유되는 것처럼 표현하지 않음 |
| 매출 분석 | 기존 회원 전용 Firestore·메뉴 규칙 revision 유지. 포트폴리오로 자동 공개하지 않음 |

표현 모드를 바꾸어도 앱 상태와 저장소 인스턴스는 하나다. 재초기화로 중복 구독하거나 폼·지도·재생을 다시 만들지 않는다. 현재 탭·필터·입력 초안·모달·지도 중심·재생 위치를 유지한다. 프레임 변화로 지도나 차트 크기 조정이 필요하면 기존 라이브러리의 resize 경로를 사용한다.

글래스 스타일은 루트 조건과 별도 토큰으로 제한한다. 기존 공통 brand.css 기본값을 전역에서 덮지 않는다. 표시 설정 키는 사용자 기록 키와 분리하고, 인증 전에는 개인 데이터나 저장 초안을 읽어 화면에 노출하지 않는다. 기존 경로와 /sungso/ 빌드 출력·모듈 식별·초기화 순서를 보존한다.

## 스프린트 일정

작업일은 분석·UI·개발·해당 범위 검증을 포함한다. 휴일·피드백 대기·새 데이터 기능은 제외한다. 각 스프린트에서 주요 화면을 먼저 검토 가능한 상태로 만들고 세부 상태로 넓힌다.

## 매 스프린트에서 보는 결과

첫 단계에서 해당 서비스의 핵심 업무와 덜어낼 항목을 확인한다. 그다음 PC 메인·모바일·주요 편집 상태를 설계하고, 같은 데이터로 기본/글래스 왕복이 가능한 미리보기를 만든다. 마지막으로 중요한 실제 동작을 확인한다.

완료 보고에는 바뀐 화면, 제거/이동된 항목, 여전히 접근 가능한 기능, 검사 결과, 미해결 항목, 다음 스프린트 한 줄을 남긴다. 예쁜 메인 이미지 한 장만으로 해당 앱 완료를 처리하지 않는다.

| 공통 확인 | 통과 기준 |
| --- | --- |
| 기본 화면 보존 | 같은 조건의 전후 캡처에서 기존 구조·값·조작 경로 유지 |
| 기능 동등성 | 모든 기존 업무에 양쪽 모드 진입 경로가 있고 같은 입력으로 같은 결과 |
| 전환 중 상태 | 초안·필터·현재 탭·모달·지도·재생을 잃지 않음, 중복 구독/저장 없음 |
| 핵심 예외 | 빈 자료·로딩·네트워크 실패·권한 만료·동시 수정에 원본 보호 및 복구 경로 |

| 저장 범위 | 공동/개인/기기 로컬을 정확히 표시, 기존 키·컬렉션·권한 유지 |
| 배포와 복구 | 기존 /sungso/ URL, 직접 링크, 캐시 버전, 공개 출력 목록, 기본 모드 복귀 확인 |

테스트는 변경 위험에 맞게 기존 검사를 활용하고 실제 회귀를 막는 동작 검사만 추가한다. 단계별 대상 검사 이후 릴리스 후보에서 프로젝트의 build/test/check를 수행한다. 운영 DB에 시험 값을 쓰거나 유료/통근 API를 시험 호출하지 않고 대역·Emulator를 사용한다.

## 이번 범위에서 늘리지 않을 기능

새 종합 통계 저장소, 전역 개인 기록 검색, AI 추천, 생활 앱 공동 동기화, Journey와 Footprints 데이터 이관, 하객과 RSVP 자동 매칭, 작업실 프로젝트 저장, 매출 자동 수집, HomeHunt 예측 모델 개편, 공개 청첩장 재설계는 제외한다. 필요하면 서비스별 후속 과제로 분리한다.
