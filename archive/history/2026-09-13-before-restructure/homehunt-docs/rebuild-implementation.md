# HomeHunt 4.0 리빌딩 결과

기준: 2026-09-06, 화면 4.0.1 / 로컬 API 계약 2.5.1.

## 정보구조와 결정 이유

지도는 탐색 문맥으로 유지하고, 옆 작업 공간을 **지금 확인 / 가격 후보 / 지역 범위**로 나눴다. 지도 위 필터는 짧게 유지한다. 숫자는 다음 확인 행동, 실제 가격 범위, 자료 커버리지를 설명할 때 사용한다.

- **지금 확인:** 목적지 A–D, 조회 병목, 이어서 볼 관심·방문 기록, 공식 분양 진입. 조회한 방문의 같은 면적 전후 변화는 메모리에서 다시 사용하며 기록이 달라지면 폐기한다.
- **가격 후보:** 기존 공식 실거래 조건·통근 판정을 유지한다. 긴 경로 표와 외부 정보를 상세로 옮겨 후보 카드를 줄였다.
- **지역 범위:** 시군구·동별 조건 후보, 평균가 확인, 좌표 확인/미확인, 가격 범위. 다른 조건으로 실제 재검색하면 직전 검색과 후보·지역 수 차이를 표시한다. 아직 조회하지 않은 지역이나 현재 판매 매물을 추정하지 않는다.
- **근거 상세:** 출처·기준일·단지 정보·통근·자금 계획·관심 저장·방문 기록·실거래·지도 이동을 한 곳에서 제공한다. 데스크톱은 우측 패널, 모바일은 바텀시트다.
- **판단 보드:** 관심 후보·개인 방문·분양 최대 3곳을 출처별로 비교한다. 기존 방문 전용 비교표도 유지한다. 동명 단지는 주소와 출처별 ID로 분리한다.

`집 찾기 / 내 기록 / 실거래 / 분양·청약 / 사용 안내 / 연결 상태` 여섯 메뉴는 데스크톱에서 모두 보인다. 모바일은 핵심 4개와 상단 안내·연결 진입을 유지한다.

## 구현한 기능

실거래 조회는 단지 확인→캐시→국토부 월자료→면적 분류→화면 계산의 5단계로 표시한다. 고정 퍼센트 대신 경과시간·취소를 제공하고, 최근 12개월을 먼저 검증한 뒤 선택한 3/5년 자료를 추가한다. 확장 실패·취소 시 확보한 범위가 유지된다. 완료 자료의 범위 안에서는 기간·거래유형·면적 변경을 다시 호출하지 않고 계산한다. 누락 월·거래유형·실패 원인과 재시도가 보이며, 부분·stale·지역 요약 일부 거래로 예측이나 방문 변화가 확정되지 않는다. 브라우저 취소 시 서버의 남은 월 요청도 시작하지 않는다.

WeCost는 기존 `computeAll`, 월 상환 계산을 `shared/financial-calc.mjs`에서 함께 사용한다. HomeHunt는 권한 없는 공개 재무 컬렉션을 읽거나 복제하지 않는다. 자동 연결 미준비 상태에서 사용자가 후보를 선택하고 명시적으로 입력한 현금·금리·기간·거치·상환방식·기존대출·월한도·부대비용으로 개인 시나리오를 계산한다. 시나리오는 로컬에 최대 3개 저장하며 원본 WeCost를 수정하지 않는다. `../wecost/?tab=house`로 연결된다.

분양 상세는 공식 분양가, 같은 단지 실거래, 인근 비교가격의 근거를 분리하고, 공급원 7상태·공식 신청 링크·준비 체크리스트를 제공한다. 자동 매칭 근거가 없는 주변 가격은 미연결로 표시한다.

공식 출처 URL·확인일·향후 허용된 어댑터의 24시간 캐시/쿨다운 설계는 [제공자 정책](rebuild-provider-policy.md)에 기록했다. 허용 불명확 상태에서 별도 수집기·숨은 API·접근 우회는 구현하지 않았다.

## 검증

- 자동 테스트 **291개 통과**: 국토부·공급원·통근·예측·방문·저장 계약, 신규 비교 근거, 금융 계산·정밀도·권한 경합, 12개월 우선/취소/부분자료·서버 남은 요청 취소.
- 실제 래미안안양메가트리아: 2025-10~2026-09 **852건** 먼저 수신, 2021-10~2026-09 **3,653건**까지 확장, partial=false, 누락 0. 서버 월캐시 재사용 실행으로 최초 전체 수집 속도를 뜻하지 않는다.
- 실제 12개월 완료 후 취소: 요청 1회만 발생, 5년 확장 중단. 일시 장애에서는 누락 월·유형을 남기고 이전 자료 보존 확인.
- 현재 저장 조건의 실제 가격 후보 **245개**, 좌표 확인 244개·미확인 1개. 원형 클러스터·지역별 가격/좌표 집계·후보 근거 상세와 실제 두 단지 비교를 확인했다. 정밀 통근 호출 없음.
- 390px·430px 모바일, 1024px 태블릿, 1440px 데스크톱에서 여섯 화면 전환·문서 가로 넘침 없음, 콘솔 오류 없음. 모바일 금융 모달 입력·ESC·계산과 비교표 내부 가로 스크롤 확인.
- 실제 브라우저에서 래미안안양메가트리아 84.7㎡, 최근 1년 매매 109건→전세 92건을 바꾸며 단지 제목·요약·가격 흐름·예측 근거의 동기화를 확인했다. 확보한 5년 자료 안에서 기간 변경은 추가 조회 없이 처리되며, 1년 예측은 검증 표본 부족으로 보류됐다.
- 금융 가정값 입력 검증: 후보 평균가격에 현금 1억, 연 4%, 30년, 기존 월상환 0, 월 한도 200만원을 입력하면 원리금균등 월 약 128만 1,064원. 부대비용 미입력은 정보 부족으로 남긴다. 이 값은 검증용 가정이며 사용자 재무 자료로 저장하지 않았다.

## 로컬 실행

저장소 루트의 별도 터미널 2개에서 실행한다.

```powershell
python -m http.server 8000 --bind 127.0.0.1
```

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File homehunt/scripts/start-local-market.ps1
```

브라우저: <http://localhost:8000/homehunt/>. API는 127.0.0.1:8787이다. `.env`는 기존 allowlist로만 읽으며 실제 값은 Git에 올리지 않는다.

```powershell
node --test homehunt/tests/*.test.mjs
node --check homehunt/js/app.js
```

## 배포 전 설정

- 로컬: `MOLIT_SERVICE_KEY`, `NAVER_MAPS_CLIENT_ID`, `NAVER_MAPS_CLIENT_SECRET`, `NAVER_LOCAL_SEARCH_CLIENT_ID`, `NAVER_LOCAL_SEARCH_CLIENT_SECRET`, `KAKAO_REST_API_KEY`, `TMAP_APP_KEY`.
- 정책: `TRANSIT_PROVIDER`, `KAKAO_DAILY_LIMIT`, `TMAP_DAILY_LIMIT`, `TRANSIT_CACHE_HOURS`, `TRANSIT_CONCURRENCY`, `HOMEHUNT_LOCAL_API_PORT=8787`.
- Actions: `DATA_GO_KR_SERVICE_KEY` 또는 `APPLYHOME_SERVICE_KEY`; Telegram 사용 시 `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`; 비민감 조건은 기존 `HOMEHUNT_ALERT_*` Variables.
- Firebase Functions: `MOLIT_SERVICE_KEY`. 원격 endpoint와 인증된 household 읽기 권한을 배포·검증한 뒤에만 활성화한다. 정적 JSON으로 개인 재무를 공개하지 않는다.
- NAVER Web 서비스 URL에 운영 GitHub Pages 호스트 등록, 청약홈·LH 활용승인/인증 상태 및 Kakao 서비스 활성화 확인.

## 다음 우선순위

1. 청약홈·LH 활용권한과 Kakao 활성화를 확인해 해당 공급원만 실검증.
2. Firebase Authentication·household 보안 규칙·읽기 전용 재무 endpoint를 준비해 WeCost 자동 스냅샷 연결.
3. K-apt 식별/상세, 역 출입구 보행 경로, 분양↔단지 매칭을 공식 근거가 확인되는 범위부터 연결.
4. `app.js`의 남은 화면 상태·렌더를 controller/service로 점진 분리하고 차트·분양의 초기 로딩 비용을 추가 축소.

이 문서는 4.0 당시 로컬 구현·검증 기록이다. 이후 4.2.1 공개 릴리스의 배포 방법과 기능 범위는 [배포 가이드](deployment.md)를 따른다. 서버 인증 설정·Telegram 발송은 이 리빌딩 범위에서 실행하지 않았다.
