# 후보별 자금 계획 · WeCost 연결

기준: 2026-09-06 리빌딩 구현.

## 현재 사용할 수 있는 범위

HomeHunt의 후보·방문·분양 상세에서 **이 후보로 자금 계획 보기**를 누르면 선택한 가격을 바탕으로 개인 자금 시나리오를 계산한다. 매매 실거래 평균, 현장 호가, 공식 분양가의 출처와 기준일을 유지한다. 전세·월세 가격은 구매가로 자동 입력하지 않는다.

**WeCost의 실제 금융 데이터 자동 연결은 아직 제공하지 않는다.** Firebase Authentication과 household 읽기 권한이 배포되지 않아 `WeCost 연결 필요` 상태를 표시한다. 현재 공개 `wecost_*` 컬렉션을 HomeHunt에서 조회하지 않으며, 금융 원본·인증 정보·개인 주소를 공개 JSON에 복제하지 않는다.

## 수동 사용 순서

1. 집 찾기, 내 기록 또는 분양에서 후보 상세를 열고 **이 후보로 자금 계획 보기**를 누른다.
2. **WeCost에서 조건 수정**으로 집 시뮬레이션 탭에 이동해 가용 현금과 활성 대출의 월 상환액을 확인한다. 링크는 `../wecost/?tab=house`이며 PIN 인증을 거친 뒤에도 탭을 유지한다.
3. HomeHunt 시나리오에 가용 현금, 월 상환 한도, 기존 월 상환액을 입력한다. 기존 대출이 없음을 확인했다면 `0`을 입력한다. `9.3억`, `9억 3천만원`, `93,000만원`을 같은 금액으로 읽고 월 상환 입력은 원 단위까지 보존한다.
4. 실제 제안받은 금리, 고정·변동 여부, 전체 기간, 거치기간, 상환 방식을 입력한다. 금리와 전체 기간의 가정값을 자동 채우지 않는다.
5. 취득세·중개수수료·등기·이사·수리비 중 확인한 비용을 입력한다. 미입력 비용은 미포함이며, 비용이 없음을 확인한 항목만 `0`을 입력한다. 남겨둘 현금을 비우면 현금을 모두 투입한 시나리오다.
6. **이 브라우저에 시나리오 저장**을 누르면 최근 3개 후보를 자금 계획 비교표에서 비교할 수 있다. 이는 해당 브라우저의 개인 저장이며 WeCost 원본을 변경하거나 다른 기기에 동기화하지 않는다.

## 계산과 상태

- `shared/financial-calc.mjs`가 WeCost와 HomeHunt의 공용 계산 원천이다. WeCost의 `computeAll`은 이 순수 계산 결과를 기존 상태 객체에 반영하므로 기존 저축·결혼비용·지원금·조정·활성 대출 계산을 유지한다.
- 필요 대출은 `기준 가격 + 입력한 부대비용 − 투입할 현금`의 양수 부분이다. 기존 대출 자금을 자동으로 현금에 더하지 않고, 기존 월 상환액만 사용자가 선택한 경우 합산한다.
- 원리금균등은 거치 후 남은 개월의 월 상환액, 원금균등은 상환 시작 첫 달의 월 상환액을 비교한다. 거치 중 이자는 별도로 표시한다. 만기일시는 이자와 만기 원금을 분리한다.
- `안정`은 입력이 완전하고 월 총상환액이 개인 월 한도의 80% 이하인 경우다. `주의`는 80% 초과~100% 이하 또는 남겨둘 현금 목표가 부족한 경우다. 100% 초과는 `한도 초과`다. 현금·금리·기간·기존 부채·월 한도·부대비용이 미확인되거나 기존 대출을 제외하면 안전하다고 확정하지 않고 `정보 부족`을 표시한다.
- 대출이 필요 없는 현금 구매는 금리·기간 입력을 요구하지 않는다. 기타 입력과 한도·부대비용 확인은 유지한다.

## 향후 인증 연결 계약

`financial-snapshot-service.mjs`는 인증 사용자와 household의 읽기 권한을 확인한 어댑터만 허용한다. 어댑터는 서버에서도 권한을 검증해야 한다. 현재 기본 서비스에는 어댑터가 없으며 네트워크 금융 조회가 발생하지 않는다.

허용하는 스냅샷 필드는 계산 버전, 출처, 가용 현금, 기존 월 상환액, 월 상환 한도, 계산 기준일, 마지막 동기화 시각이다. 원본 저축·대출·가족별 데이터는 전달하지 않는다. 동기화 실패·로그아웃·권한 변경 시 이전 숫자를 제거한다. 향후 연결 뒤 WeCost에서 돌아오면 권한과 최신 스냅샷을 다시 확인한다.

개인 시나리오의 현재 저장 키는 `homehunt_financial_scenarios_v1`이다. 서버 저장이 필요하면 인증된 household 전용 범위로 이관해야 한다. 기존 방문 기록 JSON 백업에는 현재 시나리오가 포함되지 않는다.

## 검증과 한계

`node --test homehunt/tests/financial-scenario.test.mjs`의 18개 테스트가 통과한다. 공용 계산 호환, 지원금·활성 대출 필터, 상환 방식·거치·0% 금리, 원 단위 금액 입력, 경계 판정, 부족 입력, 권한 미준비 무조회, 로그아웃 응답 경합, 동기화 실패 값 제거, 개인 저장 분리·손상 복구를 검증한다. 소수점이 반복되는 실거래 평균도 원 단위로 정규화해, 가격을 수정하지 않았으면 입력·계산·저장·재열기에서 공식 가격 출처를 유지한다.

이 기능은 구매 자금 계획 계산이다. 은행 승인·DSR·LTV·대출 가능 한도·규제 지역·세금 확정값을 계산하지 않는다. 변동금리의 미래 변화, 중도상환 수수료, 만기 원금 마련 계획, 소득·보유 주택 등은 별도로 확인해야 한다. 기존 WeCost의 지원금·저축 원천을 수정하는 기능도 HomeHunt에 추가하지 않았다.

다음 우선순위: Firebase Authentication과 household 보안 규칙을 먼저 배포하고, 같은 계산 원천으로 생성한 최소 스냅샷을 인증된 읽기 전용 경로에 연결한다.
