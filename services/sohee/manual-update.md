# 필요할 때 이 컴퓨터에서 매출 갱신

사용자가 Codex에 “매출 갱신해줘”라고 요청한 때만 Codex가 이 컴퓨터의 토스 화면을 열어 새 원본을 받는다. 사용자가 매번 직접 ZIP을 내려받아 올리는 것을 기본 흐름으로 삼지 않는다. 앱을 보거나 서버를 시작하는 것만으로 수집하지 않는다. 토스 Open API 키·파트너 등록·예약 실행은 이 흐름에 필요하지 않다. 과거 페이히어는 이미 보관한 자료를 재사용한다.

## 매번 진행할 순서

1. 현재 저장된 분석의 마지막 원본일·부분일과 로컬 출처 기록을 확인한다. 마지막 부분일부터 최신일까지 포함한다. 사후 수정·환불을 반영하려면 최근 기간을 겹쳐 받는다.
2. 이 컴퓨터에서 토스를 열고 올바른 매장과 조회 기간을 확인한다. 매출 기준은 기존과 같은 ‘결제/환불한 날’, 매출 시작 00:00으로 유지한다. 로그인·인증이 필요하면 사용자가 직접 완료한다.
3. 실제 매출 원본 ZIP을 내려받고 실제 추출 시각을 한국 시간으로 기록한다. 화면 합계만 보고 상세 거래를 만들지 않는다. 비밀번호를 소스·로그·문서에 저장하지 않는다.
4. 로컬 갱신 서비스와 회원용 미리보기를 실행한다. 데이터 관리에서 새 ZIP과 추출 시각을 입력하고 ‘새 원본 검증하기’를 누른다. 가상 자료용 QA 화면은 실제 갱신에 사용하지 않는다.
5. 교체 기간·완결일·부분일·원본 대조 결과를 확인한 뒤 Firebase에 저장한다. 최초 이전·규칙 배포는 완료했다. 수동 운영 갱신 때만 `SOHEE_WRITES_ENABLED=1`로 실행한다.
6. 저장된 분석을 다시 불러와 최신 범위와 검증 상태를 확인한다. 실패하면 기존 버전을 유지하고 실패 지점만 재시도한다. 날짜가 겹치는 원본을 단순 누적하지 않는다.

## Codex에 실행을 요청하는 경우

사용자가 ‘이 컴퓨터에서 토스 매출 갱신해줘’라고 요청하면 기존 로컬 수집 흐름을 이어간다. 연결된 브라우저/앱 제어의 지침에 따라 실제 화면을 확인하고, 문서화되지 않은 비공개 API나 저장된 로그인 정보 추출로 대체하지 않는다. 보안 입력은 사용자가 처리한다. 원본 다운로드·가져오기가 불가능하면 필요한 지점만 안내하며 성공으로 기록하지 않는다.

이 문서는 실행 절차이며, 웹 앱이 Codex나 PC의 토스 앱을 원격 실행하는 기능은 아니다. 직접 내려받은 ZIP도 동일한 검증 경로로 처리할 수 있다.

## 로컬 실행

Firebase 최초 이전 전에도 새 원본을 로컬에 보관·검증할 수 있다.

```sh
node services/sohee/local-import.mjs --zip /받은/원본.zip --captured-at YYYY-MM-DDTHH:mm:ss+09:00
```

실제 추출 시각과 파일 경로로 바꾸고 암호는 로컬 터미널의 숨김 입력에 넣는다. 결과는 Git 제외 `sohee/runtime/versions/`에 별도 보존하고 `runtime/local-current.json`으로 현재 로컬 버전을 가리킨다. 이후 갱신은 이 버전을 이어받는다. 기존 아카이브를 덮어쓰거나 Firebase에 저장하지 않는다. Firebase 최초 이전 이후에는 이전 현재 버전을 확인하고 `migrate.mjs --apply --expected-version <검토한 이전 해시>`로 새 로컬 버전을 저장할 수 있다. 같은 버전은 중복 저장하지 않고 다른 갱신과 충돌하면 기존 포인터를 유지한다. 공개 사이트의 재조회는 저장된 버전만 읽는다.

저장소 루트의 별도 터미널 두 개에서 실행한다.

```sh
# pandas, numpy, openpyxl이 설치된 Python 필요
node services/sohee/server.mjs
```

```sh
node apps/sohee/sales/preview.mjs
```

회원용 화면: `http://127.0.0.1:4177/sungso/sohee/sales/data/`.
Python 경로·Firebase 인증·기본 쓰기 잠금은 [서비스 실행 안내](README.md#실행-환경)를 따른다. 서버 실행만으로 운영 데이터 이전이나 쓰기 잠금 해제를 하지 않는다.
