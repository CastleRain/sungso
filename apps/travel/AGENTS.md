# 여행 일정

`/sungso/travel/`는 2027년 3월 7–17일 신혼여행의 현재 일정·지도·숙박 후보·WeCost 연결 예산·출발 준비를 함께 관리한다. 소스는 `apps/travel/`에 두며 루트 빌드가 기존 공개 경로로 출력한다. [루트 지침](../../AGENTS.md)을 함께 따른다.

- 기준 데이터: `../../shared/travel/trip-data.mjs`; 날짜별 일정 편집은 시간·제목·메모·지도 장소를 변경한다.
- 화면: `navigation.mjs`가 전체 일정 / 숙소 / 항공·크루즈 / 리조트·이동 / 관광·식사 / 여행 비용 / 출발 준비 / 변경 기록의 여덟 화면 중 하나만 표시한다. `#budget`·`#readiness`와 기존 `#flights`, `#cruise`, `#transfers` 같은 주소, 브라우저 뒤로·앞으로 이동을 유지한다. `travel:open-itinerary` 이벤트는 다른 화면의 호텔 지도 미리보기·날짜 바로가기를 연결한다.
- 달력: `calendar.mjs`·`calendar.css`. 2027년 3월 여행이 걸친 두 주를 기본으로 보여주며 전체 월로 전환한다. 싱가포르·해상 크루즈·몰디브·한국을 구분하고 이동일은 달력 칸과 선택 요약에 출발지·도착지를 표시한다. 3/16 몰디브→싱가포르는 다음 날 도착, 3/17은 싱가포르→한국임을 함께 보여준다. 달력은 공동 일정의 날짜 선택과 지도에 연결되지만 보기 전환은 DB를 쓰지 않는다.
- 달력 날짜 선택은 `{scroll:false}`, ‘이날 일정 보기’는 `{scroll:true}`로 전달한다. 국가 국기·활동 이모지와 선택/hover/focus 상태의 배 움직임을 표시하며 동작 줄이기를 존중한다. 3월 6일 결혼식은 배지와 월간 칸에만 표시하는 보조 일정으로, 11일 여행 데이터나 DB에 추가하지 않는다.
- 디자인: 아이보리·코랄·남색. 여행 상단에는 홈 복귀와 여행 내부 메뉴를 두며 다른 앱으로 가는 공통 메뉴는 홈으로 모은다. 여행 전용 결정 패널은 유지한다.
- 공동 저장: 기존 Firebase 프로젝트 `sungso-358cb`의 `itineraries/honeymoon_2027`.
- 이력: 같은 컬렉션의 `honeymoon_2027_log_` 접두사 문서. 대상 값과 변경 전후, 작성자, 서버 시간을 같은 트랜잭션으로 추가한다. 역순 시간 ID를 사용하여 기본 오름차순 인덱스와 문서 ID 범위로 최근 50건을 읽는다. 초기 구성 중의 `honeymoon_2027_history_` 원본 6건은 동일한 내용·시간으로 새 조회 방식에 복사하고 보존했다. 과거 이력은 UI에서 덮어쓰거나 삭제하지 않는다.
- 여행 전용 오른쪽 패널: 소스 `decision-panel.mjs`·`.css`는 기존 공개 `shared/decision-panel.mjs`·`.css` URL로 출력하고 여행 일정에서만 로드한다. 홈·WeCost·Honeymoon·HomeHunt에는 여행 할 일이나 패널용 여백을 넣지 않는다. 모바일은 dialog. 여행의 상태·메모·변경 기록은 기존 공동 저장소를 유지한다.
- 작성자는 기기별 localStorage의 표시 이름(성우/소희/미지정)이며 인증된 신원이 아니다. 기존 PIN은 화면 진입 장치이며 DB 접근 권한을 대신하지 않는다. 기존 공개 Firestore 규칙을 확장하거나 변경하지 않았다. 예약번호·여권·결제정보를 여기에 저장하지 않는다.
- 저장은 사용자 버튼으로만 실행한다. 단순 조회로 상태를 쓰지 않는다. 연결 전/오프라인은 저장 차단, 실패 시 편집 내용 유지. 같은 날짜 동시 편집은 원본을 비교해 덮어쓰기를 막는다.
- `itineraries/main`의 예전 8일 일정과 리조트 비교 picks/comments는 보존한다. 기존 리조트 화면의 ‘이전 일정 기록’은 읽기 전용이다.
- 호텔 후보 선택은 예약이 아니다. 항공과 크루즈는 미발권 후보이며, 아나네아만 사용자가 예약했다고 공유했다. 항공 시간·가격은 2026-09-13 사용자 공유 캡처, 나머지 가격은 2026-09-12 조회 자료다. 현재 견적이나 발권 완료로 표시하지 않는다.
- 지도는 Google Maps embed/search/directions 링크. 별도 위치 추적이나 Google 계정 연동은 없다. 선택한 숙박 후보를 날짜에 맞춰 동선에 적용한다.

## 여행 비용·출발 준비

2026-09-13 개인 홈 전환: 공개 개인 기본값은 `private_data/travel_reference`로 옮긴다. 공통 인증 완료 후 `prepareTravelPage()`로 여행 본문과 공통 기준을 먼저 로드하고 기존 앱 모듈을 실행한다. 여행 예산·출발 준비·현재 일정/이전 일정·변경 이력 계약은 유지하며 작성자는 로그인 회원 이름이다. 상세한 검증과 운영 이관 상태는 [계획의 자료 전환 기록](../../docs/development-plans/active/couple-home/PRIVATE-DATA.md)을 따른다. 아래 과거 기기별 작성자/PIN 설명은 전환 전 동작이며 새 접근 권한은 Google 회원 검증으로 처리한다.

- 예산 UI는 `budget.mjs`·`budget.css`, 공통 계산·저장은 `shared/finance/travel-budget-core.mjs`·`travel-budget-store.mjs`다. `cat === '✈️신혼여행'`인 기존 `wecost_items/{id}` 한 항목을 사용하고 새 비용 항목을 자동 생성하지 않는다. 여러 후보가 있으면 사용자가 합계 항목을 선택한다.
- 상세 예산 문서는 `itineraries/honeymoon_2027_budget`이며 `linkedItemId`, `baselineTotal`, `availableCash`, `fxRate`, `rows`, `note`, `updatedAt`를 사용한다. 첫 명시 저장 때 기존 장부 예상액을 비교 기준으로 고정한다. 최초 조회의 메모 분해는 인식한 항목 합계가 장부 예상액과 일치할 때만 초안에 적용하고 원래 WeCost 메모를 보존한다.
- 예상 총액·처음 기준 대비 증감, 지급액 `deposit + actual`, 앞으로 지출할 금액, 사용자가 입력한 남은 여행용 준비금과 추가 필요 금액을 구분한다. 준비금은 WeCost 전체 저축을 자동 배정한 금액이 아니다. 미입력 비용·환율은 `0원`으로 확정하지 않으며, 금액이 미확인이거나 USD 비용에 필요한 환율이 빠졌으면 장부 총액 저장을 막는다. 참고 환율 `honeymoon_fx/usd_krw`는 읽기만 하고 자동 조회·갱신·시딩을 하지 않는다.
- ‘WeCost와 함께 저장’은 연결한 장부의 `planned`·`balance`, 상세 예산, `itineraries/honeymoon_2027_budget_log_…` 이력을 같은 트랜잭션으로 반영한다. 지급액·잔금일·WeCost 메모와 다른 필드는 유지한다. 지급 기록 버튼은 같은 장부의 지급액·잔금일을 편집하고 이력도 함께 기록한다. 저장 시 장부·예산의 편집 전 원본을 비교하며 실패하면 초안을 유지한다.
- 금액 이력은 예산/장부의 변경 전후·증감·작성자·서버 시간을 기록한다. 앱은 이력을 추가만 하며 편집·삭제하지 않는다. 역순 시간 문서 ID의 범위로 최근 50건을 읽고 일정 변경 이력과 섞지 않는다. WeCost에서 예상액을 변경해 세부 합계와 달라지면 최신 장부 금액과 차이를 보여주고 사용자가 조정 후 저장한다.
- `readiness.mjs`·`readiness.css`는 준비 카드 7개와 공식 안내를 표시한다. 기존 `cruise`·`transfers`·`flights`에 `documents`·`insurance`·`connectivity`·`homebound` 결정을 더하고, `travel:edit-decision` 이벤트로 기존 패널의 사용자 편집을 연다. 조회만으로 새 결정이나 서류를 저장하지 않는다. 2026년 확인한 규정·기한은 2027년 출발 전 재확인이 필요한 안내로 표시한다.

검증: 저장소 루트의 `npm run build`, `npm test`, `npm run check`; 여행·예산 범위는 `node --test tests/*.test.mjs`. 1440px/390px에서 여덟 화면·달력 이동 국가·패널·날짜·호텔과 WeCost 왕복 연결, 예산 초안·지급액·금액 이력을 확인한다. 저장 성공·실패·오프라인·동시 변경, 중복 비용 생성 방지와 조회 쓰기 0은 테스트 대역으로 검증한다. 기존 자동 시딩·환율 갱신도 브라우저 QA에서 차단하고 운영 데이터에 테스트 값을 넣지 않는다.
