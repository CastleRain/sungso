# 여행 일정

`/sungso/travel/`는 2027년 3월 7–17일 신혼여행의 현재 일정·지도·숙박 후보를 함께 관리한다. 소스는 `apps/travel/`에 두며 루트 빌드가 기존 공개 경로로 출력한다. [루트 지침](../../AGENTS.md)을 함께 따른다.

- 기준 데이터: `../../shared/travel/trip-data.mjs`; 날짜별 일정 편집은 시간·제목·메모·지도 장소를 변경한다.
- 화면: `navigation.mjs`가 전체 일정 / 숙소 / 항공·크루즈 / 리조트·이동 / 관광·식사 / 변경 기록 중 한 화면만 표시한다. 기존 `#flights`, `#cruise`, `#transfers` 같은 주소와 브라우저 뒤로·앞으로 이동을 유지한다. `travel:open-itinerary` 이벤트는 다른 화면의 호텔 지도 미리보기·날짜 바로가기를 연결한다.
- 달력: `calendar.mjs`·`calendar.css`. 2027년 3월 여행이 걸친 두 주를 기본으로 보여주며 전체 월로 전환한다. 싱가포르·해상 크루즈·몰디브·한국을 구분하고 이동일은 선택 요약에 출발지와 도착지를 표시한다. 달력은 공동 일정의 날짜 선택과 지도에 연결되지만 보기 전환은 DB를 쓰지 않는다.
- 달력 날짜 선택은 `{scroll:false}`, ‘이날 일정 보기’는 `{scroll:true}`로 전달한다. 국가 국기·활동 이모지와 선택/hover/focus 상태의 배 움직임을 표시하며 동작 줄이기를 존중한다. 3월 6일 결혼식은 배지와 월간 칸에만 표시하는 보조 일정으로, 11일 여행 데이터나 DB에 추가하지 않는다.
- 디자인: 아이보리·코랄·남색. 여행 상단에는 홈 복귀와 여행 내부 메뉴를 두며 다른 앱으로 가는 공통 메뉴는 홈으로 모은다. 여행 전용 결정 패널은 유지한다.
- 공동 저장: 기존 Firebase 프로젝트 `sungso-358cb`의 `itineraries/honeymoon_2027`.
- 이력: 같은 컬렉션의 `honeymoon_2027_log_` 접두사 문서. 대상 값과 변경 전후, 작성자, 서버 시간을 같은 트랜잭션으로 추가한다. 역순 시간 ID를 사용하여 기본 오름차순 인덱스와 문서 ID 범위로 최근 50건을 읽는다. 초기 구성 중의 `honeymoon_2027_history_` 원본 6건은 동일한 내용·시간으로 새 조회 방식에 복사하고 보존했다. 과거 이력은 UI에서 덮어쓰거나 삭제하지 않는다.
- 여행 전용 오른쪽 패널: 소스 `decision-panel.mjs`·`.css`는 기존 공개 `shared/decision-panel.mjs`·`.css` URL로 출력하고 여행 일정에서만 로드한다. 홈·WeCost·Honeymoon·HomeHunt에는 여행 할 일이나 패널용 여백을 넣지 않는다. 모바일은 dialog. 여행의 상태·메모·변경 기록은 기존 공동 저장소를 유지한다.
- 작성자는 기기별 localStorage의 표시 이름(성우/소희/미지정)이며 인증된 신원이 아니다. 기존 PIN은 화면 진입 장치이며 DB 접근 권한을 대신하지 않는다. 기존 공개 Firestore 규칙을 확장하거나 변경하지 않았다. 예약번호·여권·결제정보를 여기에 저장하지 않는다.
- 저장은 사용자 버튼으로만 실행한다. 단순 조회로 상태를 쓰지 않는다. 연결 전/오프라인은 저장 차단, 실패 시 편집 내용 유지. 같은 날짜 동시 편집은 원본을 비교해 덮어쓰기를 막는다.
- `itineraries/main`의 예전 8일 일정과 리조트 비교 picks/comments는 보존한다. 기존 리조트 화면의 ‘이전 일정 기록’은 읽기 전용이다.
- 호텔 후보 선택은 예약이 아니다. 항공과 크루즈는 미발권 후보이며, 아나네아만 사용자가 예약했다고 공유했다. 항공 시간·가격은 2026-09-13 사용자 공유 캡처, 나머지 가격은 2026-09-12 조회 자료다. 현재 견적이나 발권 완료로 표시하지 않는다.
- 지도는 Google Maps embed/search/directions 링크. 별도 위치 추적이나 Google 계정 연동은 없다. 선택한 숙박 후보를 날짜에 맞춰 동선에 적용한다.

검증: 저장소 루트의 `npm run check`, 여행 단독 `node --test tests/*.test.mjs`; 1440px/390px에서 패널·날짜·호텔·모바일·오프라인·이력 검증. 실제 DB 쓰기 없이 저장 흐름을 모킹해 테스트하며, 기존 자동 환율 갱신의 쓰기도 브라우저 QA에서 차단한다.

### 2026-09-13 — 몰디브 밤 출발 항공 후보 반영

- 사용자 항공 캡처 기준 3/16 MLE 23:30 → 3/17 SIN 07:15, 3/17 SIN 14:35 → ICN 22:00으로 변경했다. 귀국 환승은 7시간 20분, 항공료는 1인 1,677,800원·2인 3,355,600원 캡처 기준 후보다. 3/7·12 항공편과 리조트 4박·싱가포르 2박 계획은 유지한다.
- 기본 일정·항공표·달력 국가/날짜·결정 설명·검색 링크·수상비행기/퇴실 후 이용 안내를 맞췄다. 3/16 지도는 리조트를 먼저 표시하고 말레공항 장소를 추가했다. 기존 낮 출발 고정 검색·시간 필터를 제거했다.
- 공동 문서의 마지막 이틀과 항공·이동 메모만 원본 updateTime 조건으로 저장하고, 기존 형식의 변경 기록 4건을 원자적으로 추가했다(2026-09-13 04:53:17 UTC). 작성자는 신원을 추정하지 않고 ‘미지정’으로 기록했다. 재조회로 나머지 9일·호텔·모든 결정 상태·다른 메모·문서 필드 보존을 확인했다. 이전 `itineraries/main`은 쓰기 대상에 포함하지 않았다.

- 사용자 배포 승인 후 `b4a7bbe`를 master에 반영하고 [Pages 34739072900](https://github.com/CastleRain/sungso/actions/runs/34739072900)의 검증·배포 성공을 확인했다. 공개 다섯 앱 진입점과 Travel·공동 여행 모듈·Honeymoon 요약 모듈 등 11개가 HTTP 200·로컬 파일 해시 일치다. 공개 Travel 1440px/390px에서 실제 공동 일정·마지막 이틀·새 항공표·달력·이동 안내·변경 기록을 확인했고 JS 오류·가로 넘침·DB 쓰기 0이었다. 공개 브라우저 QA의 SDK/네트워크 쓰기 차단과 결과는 `qa-public.cjs`·`qa-public-report.json`에 남겼다.
