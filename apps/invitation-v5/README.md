# 성우 · 소희 Invitation VER5

Seychelles 참고: https://toourguest.com/preview/seychelles

공개 `/sungso/invitation-v5/`, 사진 관리 `manage.html`. 기존 참석 응답 관리 `responses.html`은 회원 전용으로 유지한다.

`js/config.mjs`에서 확정된 연락처, 계좌와 선택 안내를 입력하고 `node apps/invitation-v5/scripts/build.mjs`를 실행한다. 미입력 항목은 숨긴다. 사진 추가/순서/제외는 기존 두 회원 웹 관리 화면에서 하며 VER3/4/5에 같은 앨범이 표시된다. 방명록도 동일한 기존 데이터를 사용한다.

VER5.2에서 하객용 참석 응답 영역과 제출 모듈을 제거했다. 기존 응답 API와 회원 전용 목록은 보존하며 두 회원만 `/manage`에서 읽는다. 사용자는 같은 기기의 편집 증명으로 재응답할 수 있다. 서버 응답 전에는 완료 표시를 하지 않는다. 전체 전화번호·비밀번호를 수집하지 않는다. 선택 전화 뒤 4자리는 공개되지 않는다. 예식 30일 뒤 조회/접수 종료 및 실행 중 6시간 주기 서버 정리로 내용 삭제.

## 로컬

`node apps/invitation-v5/scripts/preview.mjs --port 8024`

로컬 API 8025의 `.local` JSON을 사용하며 운영 DB와 분리한다. 정적 배포 구조는 루트 `npm run build`로 만든다.

## 원본과 의도적으로 다른 점

- 사진, 이름, 사연, 날짜와 부산 목화웨딩홀 정보는 두 사람 자료.
- 한글 SUIT 동일 계열. 사용권을 확인할 수 없는 AbramoSerif/SometimesTimes 대신 OFL Antic Didone 사용. 픽셀 단위 동일 복제라고 표현하지 않는다.
- 실계좌/개인 연락처/식사/피로연/추천 장소는 미입력 상태라 숨김. 설정하면 해당 UI가 나온다.
- 원본의 상품 구매·무료 시안 도구·공급자 광고는 하객 화면에서 제외.
- 직접 카카오 공유 SDK 키가 없으므로 기기 공유와 URL 복사를 제공. 네이버·카카오·TMAP은 기존 실제 예식장 연결을 사용.
- 원본 방명록 비밀번호 대신 기존 기기별 자기 글 삭제 증명 방식을 유지. 참석 응답은 실제 비공개 저장과 회원 조회를 제공.

## 자산

사용자 사진과 제공 MP3는 기존 VER4에서 그대로 사용한다. 한글 마루부리 기반 Invitation Serif와 Antic Didone·Pinyon은 각 OFL을 fonts 폴더에 포함한다. 원본 페이지에서 관찰한 작은 기능 아이콘과 꽃잎의 출처는 `assets/SOURCES.txt`에 기록한다. 웹사이트 브랜드 로고나 커플 사진·샘플 사연은 사용하지 않는다.

## VER5.1 모션과 색상

사용자 후속 선택으로 웜 화이트·하늘색·블루 잉크를 혼합했다. 표지는 OFL Pinyon Script의 벡터 손글씨 With love이며, 본문 영문은 Antic Didone를 유지한다. 손글씨를 변경할 때 Python fontTools/Pillow/NumPy/OpenCV가 있는 환경에서 `scripts/generate-handwriting.py` 후 `scripts/build.mjs`를 실행한다. 생성 SVG는 저장소에 보관하므로 일반 사이트 빌드에는 Python이 필요 없다.

`js/editorial-motion.mjs`가 글자/줄 순차 등장과 사진/날짜의 스크롤 이동을 관리한다. 화면 효과 끄기·prefers-reduced-motion에서는 본문과 손글씨가 완성된 채 보이며, 탭이 숨겨지면 획 애니메이션과 예약 프레임을 해제한다. 원본 Seychelles와 최초 색감/서체의 버전은 5.0.0 기록을 참고한다.

## VER5.2 표지와 흐름

사진을 화면 가득 보여 주고, 어두운 오프닝에서 Pinyon 벡터 손글씨 `We are getting married`를 약 2초 동안 쓴다. 이후 사진이 밝아지며 성우·소희와 일시가 등장한다. 음악은 실제 재생 준비가 됐을 때만 짧은 안내를 띄우며, 오른쪽 위의 기존 켜기/끄기와 전체 MP3 재생을 유지한다.

`intro-boot.js`가 첫 화면 스크롤을 잠깐 잠근다. 바로 보기/Escape/섹션 직접 링크/다른 요소로 포커스 이동/탭 숨김으로 잠금을 해제하며, 모듈 실패 시에도 4.5초 후 해제한다. 효과 끄기·기기 모션 감소·뒤로 가기로 복원할 때는 잠그지 않는다.

화이트·웜 그레이·차분한 블루 그레이로 조정했다. 중복되던 큰 MARCH 06 2027 장면과 하객 RSVP를 제거했다. 예식 안내의 실제 날짜/시간에 줄별 리빌을 적용하고, OUR LOVE STORY를 타임라인 바로 아래에 배치했다. 제목·본문·하단 공유는 스크롤 등장, 사진·마무리 사진은 스크롤 이동을 사용한다. 작은 나비는 효과 끄기/모션 감소에서 정지한다.

## 마음 전하실 곳 관리 (VER5.3)

`accounts.html`은 기존 승인된 두 Google 회원만 사용한다. 사진첩 관리 상단에서도 이동할 수 있다. 신랑·신부 각 한 개, 양가 아버지·어머니 최대 여섯 계좌의 은행·예금주·번호를 입력하고 ‘청첩장에 공개’를 선택한 뒤 ‘청첩장에 반영’을 누른다. 미선택 계좌는 비공개 초안으로 남으며, 전체 미선택이면 하객의 계좌 구역이 숨겨진다. 번호를 은행 앱에 자동 붙여넣거나 송금하지 않는다. 카카오페이의 본인 송금코드 HTTPS 링크를 선택 입력하면 연결만 제공한다.

동시 수정 충돌은 입력 중인 폼을 보존하고 저장을 거절한다. ‘최신 내용 불러오기’는 변경 폐기 확인 후 사용한다. 계좌 초안은 localStorage에 저장하지 않는다. 로그아웃·계정 변경 시 진행 요청과 개인 DOM을 정리한다. 공개 계좌도 브라우저/서버 캐시 없이 최신 API로 읽으며 연결 실패 시 오래된 번호를 노출하지 않는다.

로컬 `scripts/preview.mjs`의 `accounts-preview.html`은 같은 UI를 로컬 JSON API에 연결한다. ‘예시 번호 채워 보기’는 실제 계좌가 아닌 짧은 번호 여섯 개를 채운다. 이 페이지·스크립트는 배포 등록부에 포함되지 않는다. 운영 계좌는 읽기만으로 시딩하지 않는다.

## 마음 전하실 곳 화면 (VER5.4)

관리 입력은 네 그룹·여섯 계좌를 유지하며 하객 화면은 신랑 측/신부 측 두 탭에 본인·아버지·어머니를 모아 보여 준다. 번호는 숫자만 복사하며 수신인 이름이 포함된 완료 안내와 체크 표시를 제공한다. 카카오페이 링크는 관리자가 등록한 항목에만 표시한다. 은행 앱 자동 실행·자동 붙여넣기·송금 실행은 제공하지 않는다.

`account-view.mjs`의 마크업과 `account-interactions.mjs`의 탭 동작을 공개 화면·관리 미리보기가 공유한다. 하객의 양가 선택 키(groom/bride)만 sessionStorage에 유지하고 복귀할 때 계좌값을 최신 API로 확인한다. 관리 미리보기에서는 탭을 바꿀 수 있지만 복사/송금 동작은 비활성이다.

## VER5.5 가족 소개와 서체

부모님 이름은 `js/config.mjs`의 `family.groom.parents` / `family.bride.parents` 두 배열에서 바꾼 뒤 `node apps/invitation-v5/scripts/build.mjs`로 생성한다. 현재 ‘아빠’, ‘엄마’는 사용자가 지정한 임시 표기다. 계좌의 예금주와는 별도이며, 계좌 정보는 기존 회원 관리 화면에서 등록한다.

한글 본문·이름·액션은 MaruBuri Regular/SemiBold의 자체 호스팅 WOFF2(변환명 Invitation Serif), 영문 제목은 Antic Didone, 계좌의 장식 제목은 Pinyon을 사용한다. 글리프 전체를 보존하므로 나중에 입력하는 이름·메시지도 같은 서체가 적용된다. 관리자 전체는 공통 회원 UI를 유지하고 하객 미리보기만 청첩장 서체를 쓴다.

## VER5.5.1 첫 화면 안정화

손글씨 오프닝은 `intro-boot.js`가 문서 파싱 직후 독립 실행한다. 전체 앱 모듈의 다운로드·실행이나 DOMContentLoaded를 기다리지 않는다. 준비 안내는 한 번만 잠깐 표시하고 ‘음악과 함께 보기’ 버튼은 제거했다. 고정 음악 토글·자동재생 시도·브라우저 차단 시 첫 실제 조작으로 재생하는 동작은 유지한다.
