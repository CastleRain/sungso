# 우리 발자국 작업 지침

[루트 지침](../../AGENTS.md)과 [앱 설명](README.md)을 따른다. 소스 `apps/footprints/`는 `/sungso/footprints/`에 출력한다.

- `index.html`의 `[data-private-root]`는 숨긴 상태로 시작한다. 공통 `shared/firebase/boot.mjs`가 회원 확인 뒤 앱 entry를 로드한다. 앱이 새 Firebase 인스턴스·컬렉션·규칙을 만들지 않는다.
- 앱 정의의 ID는 `footprints`, 탭은 `places/visits/albums`다. `js/entry.mjs`는 실제 소스 경로로 공통 `shared/life/ui.mjs`를 import한다.
- 생활 기록은 계정별 브라우저 로컬 저장이다. UI에서 이 범위와 자동 공동 저장 미구현을 알린다. 로그인 전 읽기와 샘플 자동 시딩을 금지한다.
- 장소는 하나의 ID로 보존하고 식당·데이트·우리 식탁에서 같은 기록을 사용한다. 여러 방문은 같은 `placeId`를 참조하는 별도 기록이다. 방문이 남은 장소를 보관해도 방문 기록은 유지한다.
- 지도는 사용자가 입력한 HTTPS 링크를 여는 범위다. NAVER 저장 목록 자동 동기화, 비공식 API, 스크래핑·쿠키 추출, 위치 추적·통근 호출을 추가하지 않는다.
- 앨범은 HTTPS 보기 링크이며 선택적 `visitId`로 방문을 연결한다. 외부 이미지를 가져오거나 사진 원본·썸네일·Base64를 로컬/Firestore/Git/공개 자산에 넣지 않는다. 개인 권한 링크도 Git·문서·캡처에 남기지 않는다.
- 링크를 저장했다는 이유로 권한·안전·공유 상태 확인을 완료로 표시하지 않는다. 외부 원본 삭제·공유 대상 추가는 하지 않는다.
- 로그아웃·계정 전환 때 개인 DOM·메모리·리스너를 정리하고 로컬 저장 기록은 임의로 삭제하지 않는다. 저장 실패나 충돌에서 입력을 보존한다.

검증은 루트 build/test/check와 1440px·390px 운영 연결 차단 대역을 사용한다. 사용자 개인 자료나 실제 서비스에 테스트 기록을 쓰지 않는다.

## 진행 상황

### 2026-09-14 — 생활 앱 기본틀

장소·방문/데이트·사진첩의 앱 정의와 회원 인증을 거치는 진입점을 작성했다. 사진은 외부 앨범 링크만 다루며, 새로운 운영 데이터 연동·원격 배포는 수행하지 않는다.

공통 UI·저장소를 통합하고 장소·방문·앨범 연결과 우리 식탁 후보를 1440px·390px 대역에서 확인했다. 외부 앨범 접근·사진 업로드 검증은 포함하지 않는다. [통합 검증](../../docs/life-local-verification.md)을 따른다.

**다음:** 로컬 기록 흐름을 검토하고 공동 저장·사진 보관의 다음 범위를 정한다.
