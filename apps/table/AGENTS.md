# 우리 식탁 작업 지침

[루트 지침](../../AGENTS.md)과 [앱 설명](README.md)을 따른다. 소스 `apps/table/`은 `/sungso/table/`에 출력한다.

- `index.html`의 `[data-private-root]`는 숨긴 상태로 시작한다. 공통 `shared/firebase/boot.mjs`가 회원 확인 뒤 앱 entry를 로드한다. 앱이 새 Firebase 인스턴스·컬렉션·규칙을 만들지 않는다.
- 앱 정의의 ID는 `table`, 탭은 `shopping/food/recipes`다. `js/entry.mjs`는 실제 소스 경로로 공통 `shared/life/ui.mjs`를 import한다.
- 생활 기록은 계정별 브라우저 로컬 저장이다. UI에서 이 범위와 자동 공동 저장 미구현을 알린다. 로그인 전 읽기와 샘플 자동 시딩을 금지한다.
- 품목 수량은 문자열을 허용한다. 레시피 재료는 한 줄씩 저장하고 서로 다른 단위·내용을 임의로 합치지 않는다.
- 레시피→장보기는 사용자의 명시적 동작이며 추가 시점의 재료와 출처를 보존한다. 이후 레시피 수정·삭제가 이미 만든 구매 항목을 변경하거나 삭제하지 않는다.
- 뭐 먹지의 식당·카페는 우리 발자국 장소를 참조한다. 외식 후보 선택은 공급자 요청이나 운영 DB 쓰기를 발생시키지 않는다.
- 로그아웃·계정 전환 때 개인 DOM·메모리·리스너를 정리하고 로컬 저장 기록은 임의로 삭제하지 않는다. 저장 실패나 충돌에서 입력을 보존한다.

검증은 루트 build/test/check와 1440px·390px 운영 연결 차단 대역을 사용한다. 사용자 개인 자료나 실제 서비스에 테스트 기록을 쓰지 않는다.

## 진행 상황

### 2026-09-14 — 생활 앱 기본틀

장보기·뭐 먹지·레시피의 앱 정의와 회원 인증을 거치는 진입점을 작성했다. 공통 생활 UI·로컬 저장소와 연결하며, 새로운 운영 데이터 연동·원격 배포는 수행하지 않는다.

공통 UI·저장소를 통합하고 장보기 추가·완료·분류, 레시피 재료 선택 전달, 발자국 식당 후보 연결을 1440px·390px 대역에서 확인했다. 다른 탭 충돌 보호·계정 격리와 루트 검사도 통과했다. [통합 검증](../../docs/life-local-verification.md)을 따른다.
