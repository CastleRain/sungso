# Hub — 우리 홈과 모든 앱

소스는 `apps/hub/`, 공개 경로는 `/sungso/`다. [작업 지침](AGENTS.md)과 [저장소 구조](../../docs/architecture.md)를 함께 읽는다.

공통 Google 회원 확인 뒤 밝은 아이보리·살구·연두색의 개인 홈을 연다. 화면 구성은 CSS에서 밝은 테마로 고정하며 로그인/로그아웃은 기존 공통 인증이 담당한다.

- `#home`: 기존 6개 앱 중 직접 고른 바로가기 최대 4개, 저장된 중요 일정의 D-day, 다가오는 일정 3개, 최신 메모 두 줄 요약.
- `#apps`: 기존 6개와 신규 생활 앱 3개를 합친 9개 앱, 이름·용도·그룹명 검색과 그룹 필터, 카드/목록 보기. PC에서는 9개를 한 페이지에, 휴대폰에서는 6개와 3개로 나누어 보여준다.
- 바로가기 편집: 기존 6개 앱 중 최대 네 앱을 선택 순서대로 함께 적용한다. 취소는 저장하지 않으며 동시 편집이나 실패 시 초안을 유지한다. 신규 생활 앱은 모든 앱에서 연다.
- 앱 정리: 기존 6개 앱의 그룹 이름·그룹 순서·앱 분류와 그룹 안 순서·홈 표시 여부 편집을 유지한다.
- 메모: 홈에서 눌러 전문을 읽고, 최근 3개부터 이전 기록을 6개씩 더 읽는다. 작성과 본인 메모 삭제는 대화상자에서 제공하며 닫기만 한 작성 초안은 유지한다.

## 기존 저장 계약

`site_home/shared`의 `groups/apps/revision/updatedBy/updatedAt`만 사용한다. 읽기에서 문서를 생성하거나 기존 표시 설정을 변환해 저장하지 않는다. 홈 바로가기는 저장된 `apps` 배열 중 `hidden !== true`인 앞 네 개다. 바로가기를 직접 적용할 때 선택 앱은 배열 앞에 두고 `hidden: false`, 나머지는 기존 상대 순서를 유지한 채 `hidden: true`로 저장한다. `hidden`은 홈 표시 여부이며, 모든 앱에서는 숨긴 앱도 열 수 있다. 모든 바로가기를 빼도 편집과 전체 앱 접근이 남는다.

그룹 순서는 모든 앱의 필터·목록에 적용하고, 홈 바로가기 순서는 저장된 앱 배열 순서에 따른다. 기존 설정의 그룹 이름·앱 그룹·revision을 보존하며 저장 전 원본 revision을 비교한다. 새 필드·컬렉션·보안 규칙은 필요하지 않다.

일정은 `events`, 메모는 `home_notes`를 그대로 사용한다. 계정 변경·로그아웃 시 구독·날짜 갱신 타이머·해시/화면 이벤트·대화상자·개인 DOM과 메모리 초안을 정리한다. 다른 앱의 로컬 초안과 저장 키를 변경하지 않는다.

## 추가한 생활 앱

| 앱 | 경로 | 로컬 기본 기능 |
|---|---|---|
| [우리 식탁](../table/README.md) | `/sungso/table/` | 장보기, 먹을 후보 고르기, 레시피와 재료를 장보기에 담기 |
| [우리 발자국](../footprints/README.md) | `/sungso/footprints/` | 장소, 방문·데이트 기록, 외부 HTTPS 앨범 링크 |
| [우리 결혼](../wedding/README.md) | `/sungso/wedding/` | 하객노트, 준비할 일, 기존 결혼·여행 앱 연결 |

세 앱은 별도 생활 앱 목록에서 모든 앱 화면에 합쳐 표시한다. 신규 ID를 기존 `site_home/shared`의 앱 배열이나 바로가기 저장에 넣지 않으므로 기존 6개 앱의 공유 설정·Firestore 규칙을 유지한다. 원래 앱의 공개 URL도 바꾸지 않는다.

생활 기록은 공통 Google 회원 확인 뒤 **UID별 브라우저 `localStorage`에만 저장**한다. 같은 계정·브라우저 안에서는 세 생활 앱이 장소·레시피 등의 기록을 연결한다. 상대 계정이나 다른 기기로의 자동 공유, 사진 원본 업로드, NAVER 즐겨찾기 자동 동기화는 구현하지 않았다. 자세한 현황과 후속 범위는 [생활 앱 확장 계획](../../docs/development-plans/active/couple-life/README.md)을 따른다.

## 일정 기준과 로컬 미리보기

일정의 기준은 사용자가 지정한 현재 [공개 Dates](https://CastleRain.github.io/sungso/dates/)다. 공개 브라우저에서 현재 일정 3개를 확인했으며, Hub와 Dates는 같은 운영 `events` 컬렉션을 읽는다. 앞서 로컬 QA에 표시한 과거 8개 일정은 잘못 선택한 검토 자료여서 폐기했다. 신혼집 계약 같은 과거 사본 항목을 운영에 추가하거나 현재 일정을 정적 기본값으로 복제하지 않는다.

`http://127.0.0.1:8796/sungso/`는 일반 `npm run dev` 서버이며 실제 Google 회원 로그인 뒤 같은 운영 일정을 읽는다. 일정 사본을 주입하는 `QA_PRIVATE_EVENTS_INPUT` 방식은 이번 정정에서 제거한다. 이 로컬 주소의 실제 회원 로그인·화면 대조와 이번 공개 배포는 아직 확인 대기다. 일반 개발 서버의 일정·홈·메모 저장은 운영 연결이므로 기능 QA는 별도 대역에서 수행한다.

남긴 말은 앞선 로컬 대역의 예시 데이터만 비웠으며, 실제 메모를 쓰는 입력 영역과 기존 메모 기능은 유지한다. 운영 사용자 메모를 삭제한 것으로 기록하지 않는다. 새 생활 앱의 기록은 위 안내대로 UID별 브라우저 저장이며 일정의 운영 연결과 구분한다.

## 검증

```sh
node --test apps/hub/tests/*.test.mjs tests/site/couple-home.test.mjs
npm run build
npm test
npm run check
```

브라우저 검증은 [공공·운영 연결 차단 대역](../../tests/site/couple-qa/README.md)을 사용한다. `/sungso/`, `/sungso/#apps`, 1440px·390px에서 직접 진입·뒤로 가기·검색·바로가기 취소/저장/실패/충돌·메모·로그아웃과 연결 앱을 확인한다. [이번 검증 기록](../../docs/hub-library-verification.md)에 실제 실행 결과를 남긴다.

대문과 세 생활 앱의 기본틀은 로컬에 구현했다. [생활 앱 통합 검증](../../docs/life-local-verification.md)은 이전 사본 검증과 현재 운영 일정 기준 정정을 구분한다. 이번 릴리스 검사·로컬 실회원 대조·공개 배포 결과는 확인 뒤 추가한다. 공동 저장과 이미지 기능은 [생활 앱 확장 계획](../../docs/development-plans/active/couple-life/README.md)의 후속 범위다.
