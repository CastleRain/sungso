# 모바일 청첩장 선택·공통 설정

성우·소희가 총 29가지 디자인을 끝까지 내려보며 비교하고, 각자의 찜과 공동 디자인 선택을 저장하는 앱이다. 두 사람이 저장한 대표사진·갤러리·예식장을 모든 디자인에 함께 적용한다. 기존 23종에 살롱드레터·투아워게스트 원본 구성을 참고한 6종을 더했다. 하객용 공개 링크와 실제 참석 응답 수집은 별도 작업이다.

## 함께 사용하는 예식 일정

표지·본문·마무리·달력·우표/발권번호·목록 썸네일은 `js/wedding-date.mjs`의 같은 날짜와 시간을 사용한다. 2026-09-15 사용자가 전체 청첩장에 본인의 예식 날짜·시간을 표시하도록 명시 요청한 범위이며, 현재 일정은 해당 파일 한 곳에서 설정한다. 한국어/영문 표기와 두 달력은 같은 설정에서 계산한다. 목록과 모든 디자인의 예식 정보에는 한국 시각 기준으로 남은 일·시간·분·초를 표시한다. 예식 시각 이후에는 0으로 고정하고 도착 문구로 바뀐다.

기존 찜·선택 revision·공동 문서와 로컬 초안 스키마는 바꾸지 않는다. 사용자가 작성한 메모/노트의 날짜 문자열을 임의로 치환하지 않는다. 예식 날짜를 바꾸는 작업은 다른 앱의 운영 일정을 자동 수정하지 않는다.

## 우리의 사진과 예식장

목록과 미리보기의 **사진·예식장 설정**에서 대표사진 1장, 갤러리 최대 20장과 순서, 예식장 이름·홀/층·주소·HTTPS 지도 링크·교통·주차 안내를 편집한다. 갤러리 사진을 대표사진으로 함께 사용할 수도 있다. **저장하고 모든 디자인에 적용**을 눌러야 두 회원과 다른 기기에 함께 반영되며, 디자인을 찜하거나 공동 선택으로 저장하는 작업과는 독립적이다.

JPG·PNG·WebP 입력은 브라우저에서 긴 변 최대 1,600px의 웹용 JPEG로 다시 만들고 크기에 따라 품질과 해상도를 줄인다. 입력 한 장은 25MiB·6천만 화소 이하, 저장할 data URL은 360,000자 이하로 제한한다. 원본 파일은 업로드하지 않는다. 사진은 회원 전용 Firestore 문서에 보관하며 공개 파일 URL이나 Git 자산으로 만들지 않는다. Firebase Spark를 유지하고 Cloud Storage·새 Functions·요금제 전환을 추가하지 않는다.

사진형 표지의 첫 사진은 대표사진을 사용하고, 갤러리는 저장한 순서를 따른다. 인물 소개·이야기의 사진 자리에도 같은 갤러리 사진을 사용한다. 사진 한 장만 있어도 고정된 이야기 장면을 표시할 수 있다. 그림·탑승권·제주 이름 표지처럼 사진이 없는 구성은 그대로 유지한다. 사진을 모두 해제해 저장하면 기존 가상 커플 사진 3장으로 돌아간다. 실제 예식장이 있으면 예시 지도·예시역·가상의 주차 혜택 대신 입력한 안내만 표시하고, 지도 링크는 누를 때 새 탭으로 연다. 자동 지도 검색·경로 조회는 하지 않는다. 사진·예식장 미설정 항목과 이야기·부속 식순·계좌·RSVP·방명록은 예시임을 구분한다.

편집 중인 사진과 예식장은 메모리에만 있으며 편집창을 닫거나 로그아웃하면 미저장 내용을 정리한다. 저장 실패나 동시 편집 충돌 때는 열린 편집창의 초안을 유지한다. **최신 설정 다시 불러오기**는 서버 내용을 다시 편집하도록 불러오는 동작이며 저장을 실행하지 않는다. 이 동작으로 편집창을 갱신한 뒤 필요한 변경을 다시 입력하고 저장한다. 새 사진과 예식장의 구현·검증·배포 상태는 [검증 기록](../../docs/invitation-personalization-verification.md)을 따른다.

## 원본 샘플 구성 여섯 가지

[원본 대응표와 관찰 근거](../../docs/invitation-reference-research.md)에 공식 샘플 링크를 정리했다. 살롱드레터의 전면 사진 레터링·폴라로이드·네 모서리 타이포, 투아워게스트의 서울·포르투·제주를 긴 청첩장으로 재구성한다. 예식 날짜·시간은 사용자가 지정한 일정이며 사진·장소는 공통 설정을 따른다. 문구와 미설정 사진·장소는 예시다. 상용 사진·서체·원본 코드는 포함하지 않는다. 원본의 자동 참석 팝업과 상거래는 제외한다.

| ID | 참고한 구성 |
|---|---|
| `salon-lettering` | 전면 사진 위 한 번 쓰이는 글씨·인물 소개·인터뷰 |
| `salon-polaroid` | 하얀 사진 카드·세로 이름·사진 초대글·달력 |
| `salon-editorial` | 사진 네 모서리 이름·짧은 오프닝·사진 기록 |
| `guest-seoul` | 흑백 필름 두 장·큰 날짜·인물 카드·타임라인 |
| `guest-porto` | 전면 사진과 흰 하트·푸른 날짜·하객 안내 |
| `guest-jeju` | 장밋빛 이름 표지·넓은 여백·사진 기록 |

제주·서울·포르투·폴라로이드는 `wedding-lettering.mjs`와 전용 CSS의 직접 그린 Wedding 필기를 첫 표지에서 재생한다. 기존 두 살롱 오프닝도 유지한다. 손글씨 도입의 이전 검증은 [예식 일정·필기 기록](../../docs/invitation-wedding-date-verification.md), 이후 추가한 전환은 [공통 설정·연출 검증 기록](../../docs/invitation-personalization-verification.md)을 따른다.

여섯 가지도 표지의 필기·오프닝에서 본문으로 이어지는 스크롤 장면 전환을 제공한다. 긴 장면은 끝까지 읽고 다음 장면으로 넘어가며, 스크롤을 되돌리면 전환도 되돌아간다. 레터링/오프닝은 글자가 보일 때 한 번만 재생하고 스크롤 복귀·팔레트 변경·같은 탭의 예시 재진입에는 다시 쓰지 않는다. 새로고침은 새 미리보기이므로 첫 재생이 가능하다. 모션 감소·연출 끄기에서는 전체 본문을 자연스럽게 길게 읽는다. 사진 갤러리는 가로 넘김·이전/다음·확대와 색상 변경 후 위치 복원을 지원한다.

| 적용 디자인 | 본문에서 이어지는 효과 |
|---|---|
| 전면 레터링·포르투 | 사진이 미세하게 멀어지고 다음 장면이 확대 상태에서 겹쳐 들어온다. |
| 폴라로이드·서울 | 종이 마스크가 아래에서 열리고 사진 사이의 작은 깊이 차이를 보여준다. |
| 네 모서리 사진형·제주 | 다음 장면이 세로로 이어지고 이야기 구간의 진행선이 채워진다. |

효과의 참고 사례와 직접 설계한 부분은 [추가 조사](../../docs/invitation-personalization-research.md)에 구분했다. 업체의 실제 동작 시간과 동일하다고 보장하는 재현은 아니다.

`reference-catalog.mjs`는 등록·원본 링크, `reference-{salon,toourguest}.mjs`는 본문, `reference-flow.mjs`는 최초 오프닝과 갤러리, `reference-scenes{,-core}.mjs`는 장면 전환·읽기 위치·효과 계산, `preview-scroll.mjs`는 연출 모드 연결을 담당한다. 디자인·연출 모듈은 저장 계층을 직접 호출하지 않는다.

## 이야기 에디션과 새 목록

[네이버 블로그와 공식 샘플 조사](../../docs/invitation-research.md)를 바탕으로 첫 화면부터 본문·안내·마무리까지 이어지는 긴 구성을 만들었다. 공통 설정의 사진 또는 기존 예시 사진과 새로 작성한 문구를 사용하며 다른 서비스의 사진·코드를 복사하지 않았다.

| ID | 디자인 | 본문 체험 |
|---|---|---|
| `paper-theater` | 종이 속 작은 결혼식 | 표지의 종이 창 열림·본문 사진 카드·장면 선택 |
| `memory-house` | 우리라는 집에 초대합니다 | 표지의 외벽 열림·열린 거실/사진방/정원 선택 |
| `ribbon` | 한 줄로 이어진 우리 | 표지의 매듭/카드 펼침·본문 사진 타임라인·이야기 선택 |
| `magazine` | 우리의 웨딩 매거진 | 인터뷰 기사 선택·화보·편집 지면 |
| `film` | 천천히 현상되는 우리 | 사진 현상 단계·콘택트 시트 |
| `vinyl` | 사랑의 B-side | 음반 A/B면·트랙 이야기·유한 회전 |
| `museum` | 두 사람의 작은 전시 | 전시실·작품 캡션·사진 확대 |

| `festival` | 오늘은 우리의 페스티벌 | 무대 타임테이블·기념 팔찌 |
| `promenade` | 너에게 가는 산책길 | 산책 지점·사진과 이야기·길 안내 |

이야기 11종은 우리 이야기·참석 예시·방명록 예시를 기본으로 포함한다. 옵션에서 숨기거나 복원할 수 있고, 기존 초안의 명시적인 섹션 설정은 그대로 유지한다. 체험은 메모리에서만 동작하며 음원 재생·하객 정보 수집·응답 전송은 없다. 모션 감소에서는 같은 조작 결과를 애니메이션 없이 읽을 수 있다. 새 3종의 [조사와 설계](../../docs/invitation-immersive-research.md), [구현 검증 범위](../../docs/invitation-immersive-verification.md)를 함께 참고한다.

목록은 **원본 샘플 구성 / 새로운 이야기 / 손으로 여는 초대 / 사진과 여백**으로 탐색한다. 모음별 숫자는 등록된 디자인에서 계산한다. 이름·분위기·체험 키워드 검색과 두 사람의 찜 필터를 함께 적용하고, 모아보기(모바일 2열)·크게 보기를 전환한다. 최대 4개의 후보를 한 번에 나란히 비교할 수 있다. 이는 동시 비교의 한도이며 디자인 등록 개수 제한이 아니다. 직접 미리보기 안에서는 이전·다음 예시로 이동한다.

검색·목록 밀도·비교 후보는 기존 기기 저장 키에 추가되며 공동 선택 JSON에는 포함되지 않는다. 기존 초안·찜·선택 revision은 보존한다. 새 ID를 추가할 때는 카탈로그와 서버의 찜 허용 목록도 함께 갱신하고 Emulator에서 검증한다.

새 모듈은 `edition-catalog.mjs`(등록), `editions.mjs`(연결), `editions-{editorial,playful}.mjs`와 해당 CSS(전체 디자인·체험), `library.css`(목록·비교)다. 인증이나 저장 계층을 디자인 모듈에서 호출하지 않는다.

- 공개 경로: `/sungso/invitation/`.
- 화면: `#catalog`, `#preview/{templateId}`, `#selection`. 직접 접근·새로고침·뒤로가기를 지원한다.
- 홈: 용도별 그룹의 **결혼 준비**에서 모바일 청첩장으로 연결한다.
- 각 카드의 **모바일로 보기**로 휴대폰 프레임에 바로 진입한다. 미리보기 상단에서 기본 보기와 모바일 보기를 전환하고, PC에서는 360·390·430px를 고른다. 모바일 모드의 **꾸미기**로 색감·구성을 바꿀 수 있다.
- 모바일은 문서 자체를 세로 스크롤한다. 실제 작은 화면에서는 프레임 장식을 숨기고 가용 너비를 그대로 사용한다. 기본 데스크톱 미리보기는 최대 430px와 옆 설정 영역을 사용한다.
- 보기 방식·너비는 현재 탭에서만 기억하고 공동 선택에 넣지 않는다. 전환 시 청첩장 DOM을 유지한다. 초대장 자체의 폭을 기준으로 컨테이너 쿼리와 글꼴을 계산해 PC의 모바일 보기에도 같은 반응형 배치를 적용한다.
- 모든 29종의 **스크롤 연출**이 기본으로 켜진다. 원본 구성 6종도 첫 오프닝 이후 위의 세 효과로 장면을 전환한다. 별도의 스크롤 소개 선반과 중복 링크는 없애고, 한 목록의 **모바일로 보기**로 열도록 정리했다. 기존 일곱 연출과 함께 음반 회전·전시실 전환·축제 무대 상승을 지원하며, 종이 극장·이야기의 집·리본 편지는 표지에서 종이 창·집의 벽·접힌 카드가 펼쳐지고 본문은 다른 사진 구성으로 이어진다. 한 화면을 고정하고 문서 스크롤 위치에서 연출을 계산하므로 위로 올리면 같은 순간으로 돌아간다. **한 번에 펼쳐보기**를 켠 장면은 버튼을 다시 눌러 스크롤 연동으로 복귀한다.
- 긴 장면은 본문 끝까지 읽은 뒤 전환한다. 이전·다음 장면 버튼을 제공하고 연출을 끄면 전체 본문을 길게 읽는다. 기기의 모션 감소 설정에서도 일반 본문으로 표시한다. 기존 사진 확대·현상·계절·스티커·별 잇기·편지 펼침·산책 지점 선택을 함께 사용한다.
- 공통 Google 회원 인증·홈 복귀를 따른다. 이전 PIN 플래그는 접근 권한으로 사용하지 않는다.

| `envelope` | 봉투 속 초대 | 왁스 크림·로즈·올리브 | 격자 |
| `constellation` | 우리의 별자리 | 인디고·플럼·딥 틸 | 슬라이드 |
| `camera` | 찰칵, 우리의 순간 | 버터·라벤더·민트 | 필름 스트립 |
| `storybook` | 펼치면, 우리 | 포레스트·살구·라일락 | 격자 |
| `ticket` | 둘만의 탑승권 | 오션·선셋·코발트 | 필름 스트립 |
| `curtain` | 우리의 첫 장면 | 벨벳·에메랄드·네이비 | 슬라이드 |

색감은 각 템플릿의 첫 번째가 기본이다. 갤러리·오시는 길·마음 전하실 곳은 기본 켬, 우리 이야기·참석 여부·방명록은 기본 끔이다. 표지·초대글·예식 정보·마무리는 고정한다. 메모는 최대 1,000자다.

봉투·별자리·탑승권은 **시그니처 에디션**으로, 손으로 여는 초대 모음에서 열 수 있다. 종이 편지·밤하늘 장면·하객 여정처럼 첫 장부터 마무리까지 고유한 본문과 체험을 제공한다. 새 초안은 세 디자인의 우리 이야기, 탑승권의 참석 체험을 기본으로 켠다. 이전 초안과 공동 선택의 명시적인 섹션 켜짐/꺼짐은 유지한다.

사진 미설정 시 같은 가상 커플 사진 3장을 모든 템플릿에서 사용한다. 그림 템플릿의 표지는 같은 커플을 참고해 생성한 일러스트다. 날짜·시간은 공통 예식 일정, 사진·장소는 회원 공통 설정을 따르며 이야기·부속 식순·계좌·방명록은 예시다. 탑승권의 교통수단 전환은 예식장 미설정 시에만 제공하며, 가상 하객의 참석 티켓은 입력이나 전송 없이 현재 세션에서만 보여준다. 갤러리 확대·닫기·사진 이동은 동작한다. 기본 예시 이미지의 경로와 생성 프롬프트는 [이미지 기록](docs/image-prompts.md)에 있다.

## 특별한 여섯 장

기존 특별한 여섯 장은 **손으로 여는 초대** 모음에 남아 있다. 사람별 찜과 검색을 함께 적용하고 목록 복귀 시 모음·검색·스크롤 위치를 유지한다.

| 디자인 | 직접 해보는 동작 |
|---|---|
| 봉투 속 초대 | 봉인을 누르면 봉투 날개가 접히고 초대장이 올라온다. 다시 닫을 수 있다. |
| 우리의 별자리 | 별 다섯 개를 눌러 선을 이어 사진을 드러낸다. 한 번에 잇기와 다시 그리기도 제공한다. |
| 찰칵, 우리의 순간 | 셔터를 누르면 즉석사진이 나온다. 공통 설정의 사진을 순서대로 꺼내며 미설정 시 예시 3장을 사용한다. |
| 펼치면, 우리 | 책을 펼치면 종이 꽃과 사진으로 만든 입체 장면이 나타난다. |
| 둘만의 탑승권 | 탑승권의 절취선을 누르면 티켓이 나뉘고 결혼 도장이 찍힌다. |
| 우리의 첫 장면 | 커튼을 열면 스포트라이트와 짧은 축하 장식이 첫 장면을 드러낸다. |

장면 상태는 현재 앱 세션의 메모리에만 두며 색감·갤러리·섹션 변경으로 캔버스를 다시 그려도 유지한다. 브라우저를 새로고침하면 체험을 처음부터 시작한다. 찜·공동 선택·선택서에는 열린 봉투, 누른 별, 촬영 순서 등을 저장하지 않는다. 예식 정보는 체험을 완료하지 않아도 아래로 내려서 바로 읽을 수 있다. 키보드로 같은 버튼을 사용하며 모션 감소 설정에서는 동작 결과를 즉시 보여준다. 음원 재생은 추가하지 않는다.

## 모듈과 저장 계약

- `catalog.mjs`: 템플릿·팔레트·섹션 정의와 공통 사진 목록 연결.
- `personal-content.mjs`: 저장된 사진·예식장의 렌더용 상태, 표지 사진 교체, 예시 복원, 입력값 이스케이프.
- `wedding-date.mjs`·`countdown.mjs`: 공통 예식 일정·달력과 남은 일·시간·분·초. 숨겨진 탭·페이지 이탈·로그아웃 시 주기 갱신을 정리한다.
- `profile-core.mjs`·`profile-store.mjs`·`profile-adapter.mjs`: 공통 사진·예식장 검증, 준비 상태, 명시적 저장과 revision 충돌, 사진 문서와 부모 설정의 원자적 변경.
- `profile-images.mjs`·`profile-editor.mjs`·`css/personalization.css`: 사진 웹 최적화, 대표사진/갤러리 순서·예식장 입력, 메모리 초안과 편집창 정리.
- `core.mjs`: 입력 정리, 임시 설정, 경로, 필터, 트랜잭션 변경 규칙, 선택서 출력.
- `templates.mjs` / `css/invitation.css`: 기본 여섯 디자인의 표지·본문·마무리.
- `special-paper.mjs`·`special-worlds.mjs`와 같은 이름의 CSS: 특별한 여섯 디자인의 표지와 본문.
- `experiences.mjs`: 표지 체험 진행·다시 보기·키보드 버튼·타이머 정리. 저장 계층과 독립한다.
- `signature-{envelope,constellation,ticket}.mjs`와 같은 이름의 CSS: 세 시그니처의 전체 본문과 메모리 체험. `signatures.mjs`가 렌더·마운트·정리를 연결하고 `signature-catalog.mjs`가 목록 소개를 만든다.
- `app.mjs` / `css/app.css`: 목록·꾸미기·공동 선택·모달 UI.
- `scroll-story-core.mjs`·`scroll-story.mjs`·`css/scroll-story.css`: 장면별 스크롤 거리 계산과 고정 화면 연출. 기존 본문 DOM·체험 버튼을 유지하며 장면 위치는 저장 문서에 포함하지 않는다. 검증 범위는 [스크롤 연출 기록](../../docs/invitation-scroll-verification.md)을 따른다.
- `scroll-designs.mjs`·`scroll-motion*.mjs`와 대응 CSS: 모든 등록 디자인의 스크롤 지원과 장면별 순수 계산. 중첩된 체험 컨테이너를 유지하며 각 본문 장면만 화면에 배치한다. 이전 `scroll-library` 공개 파일은 주소 호환을 위해 남기고 현재 목록에서는 로드하지 않는다.
- `immersive-catalog.mjs`·`immersive-scenes.mjs`·`immersive-{theater,house,ribbon}.mjs`와 대응 CSS: 새 3종 등록과 내부 물체 펼침. `immersive-experiences.mjs`는 방/이야기 선택·바로 펼침을 메모리에만 유지한다. `data-story-hold`는 복잡한 펼침 장면에 충분한 스크롤 거리를 제공하고 기존 읽기·전환 계산을 보존한다.
- `store.mjs`: 공동 상태와 실패 처리. `firestore-adapter.mjs`: SDK를 주입하는 실제 트랜잭션·구독.
- `firebase.mjs`: SDK 10.12.0, 이름 `sungso-invitation`, 공통 공개 설정만 사용한다.

디자인 선택은 기존 **`couplePicks/invitation_templates`** 문서에 저장한다. 공통 사진·예식장은 아래의 별도 경로와 revision을 사용한다. 관리자가 승인한 두 Google 회원만 접근하며, 본인 찜·공동 선택·공통 콘텐츠 변경을 서버 규칙으로 검증한다. 기존 리조트 문서 `couplePicks/main`에는 접근하지 않는다. 조회로 문서를 생성하지 않는다.

```js
{
  schemaVersion: 1,
  favorites: { sungwoo: ['minimal'], sohee: ['garden'] },
  selection: {
    schemaVersion: 1,
    templateId: 'garden', paletteId: 'sage', galleryLayout: 'grid',
    sections: { story: false, gallery: true, directions: true,
                accounts: true, rsvp: false, guestbook: false },
    note: ''
  },
  selectionRevision: 1,
  updatedBy: 'MEMBER_UID',
  updatedAt: /* Firestore serverTimestamp */ null
}
```

찜은 트랜잭션에서 최신 문서를 읽고 해당 사람의 배열만 중첩 병합한다. 찜 변경은 공동 선택 번호를 증가시키지 않는다. 공동 선택 저장은 초안을 시작한 `baseRevision`과 서버의 `selectionRevision`이 같을 때만 설정·번호·변경자·시각을 한 번에 기록한다. 충돌하면 최신 선택을 보여주며, 확인 버튼은 초안 기준 번호만 갱신한다. 사용자가 저장을 다시 눌러야 반영된다.

`localStorage.sungso_invitation_v1`에는 기기의 선택자, 디자인 모음·목록 필터·스크롤 위치, 템플릿별 임시 설정과 기준 번호를 저장한다. 임시 옵션은 공동 문서를 바꾸지 않는다. 연결·저장 실패를 성공으로 표시하지 않고 예시와 임시 설정은 계속 제공한다. 저장소가 막힌 브라우저에서는 세션 중 사용과 안내를 제공한다.

**선택 내용 복사**와 **선택서 내려받기**는 공동으로 저장된 `selection`만 사용한다. 내려받는 `sungso-invitation-selection.json`에는 위의 선택 객체 7개 키만 포함한다. 선택자·찜·변경 번호·시각·공통 사진·예식장 정보는 제작용 JSON에 넣지 않는다. 실제 사진과 예식장은 아래 회원 전용 설정으로 관리하며, 자유 문구 편집·음원·연락처·계좌정보·하객 응답은 별도 범위다.

### 공통 사진·예식장 저장

| 경로 | 저장 내용 |
|---|---|
| `invitation_settings/shared` | `schemaVersion: 1`, 독립된 `revision`, `coverId`, 순서 있는 `galleryIds`, `venue`, 서버 시각·변경자 |
| `invitation_settings/shared/photos/{photoId}` | 웹용 JPEG/WebP `dataUrl`, `width`, `height`, 서버 시각·변경자 |

`photoId`는 새 UUID v4이며 저장된 사진 문서는 덮어쓰지 않는다. 대표사진과 갤러리가 같은 ID를 참조할 수 있으므로 최대 고유 사진 수는 21장이다. `venue`는 `name`, `hall`, `address`, `mapUrl`, `transport`, `parking`만 허용하며 이름이 없으면 나머지 필드도 비워야 한다. 이름·홀은 각각 80자, 주소는 300자, 지도 링크·교통·주차는 각각 1,000자 제한이다. HTTPS 이외의 지도 URL과 제어 문자는 거부하고, 화면에는 이스케이프한 텍스트로 표시한다.

어댑터는 `expectedRevision`과 현재 설정의 `revision`을 비교하고, 새 사진 생성·더 이상 참조하지 않는 사진 삭제·프로필 revision 증가를 하나의 트랜잭션으로 저장한다. 갤러리에서 뺀 사진도 대표사진으로 남아 있으면 삭제하지 않는다. 사진 추가·삭제는 부모 설정의 새 revision과 함께 수행하도록 규칙을 제한한다. 부모 설정의 직접 삭제와 사진 문서 수정·목록 조회는 허용하지 않는다. 사진을 모두 비우는 동작도 부모 설정을 삭제하지 않고 빈 참조를 명시적으로 저장한다.

새 사진과 삭제할 사진의 data URL 길이를 합해 한 저장에서 8,000,000자를 넘으면 어댑터가 저장을 중단하고 더 작은 사진이나 나누어 저장하도록 안내한다. 충돌·권한 거부·오프라인·사진 누락을 성공으로 표시하지 않으며 자동 덮어쓰기를 하지 않는다. 설정과 연결된 모든 사진이 서버에서 확인돼야 새 revision을 화면에 적용한다. 최초 연결 실패를 빈 설정으로 간주해 예시를 덮어 표시하거나 자동 저장하지 않는다.

편집 초안과 읽은 사진은 앱 메모리에서 관리하고 사진을 `sungso_invitation_v1`이나 선택서에 기록하지 않는다. 로그아웃·계정 전환 시 사진 구독, 늦은 비동기 응답, 편집창, 개인 DOM과 렌더용 메모리를 정리한다. 기존 디자인 초안은 보존한다. 예식장 변경·사진 저장은 다른 앱의 일정이나 찜·공동 디자인 선택 번호를 변경하지 않는다.

## 로컬 검증

루트 `npm test`와 `npm run check`에 디자인·체험 검사와 `tests/profile-core.test.mjs`, `tests/profile-store.test.mjs`, `tests/personal-content.test.mjs` 등 공통 설정 검사가 포함된다. 이번 변경의 검증·배포 상태와 남은 기기 확인은 [공통 설정 검증 기록](../../docs/invitation-personalization-verification.md)을 따른다. 브라우저 검증은 다음 대역 서버를 사용한다.

```sh
node apps/invitation/tests/qa-server.mjs
```

`http://127.0.0.1:8017/sungso/invitation/`에서 대역 인증을 확인한다. 서버가 빌드 결과를 제공하므로 소스 수정 후 `npm run build`와 브라우저 새로고침이 필요하다. 이 서버의 공동 데이터는 메모리에만 있고 재시작하면 사라진다. 홈의 일정은 읽기 전용 대역이며 CSP로 외부 API 연결을 차단한다. `/__qa/state`는 대역 상태, `/__qa/mode`는 `live`·`failure`·`offline` 상황 제어용이다. 이 파일과 테스트·문서는 웹 배포에 포함되지 않는다.

카탈로그·저장 규칙을 수정하면 QA 서버도 재시작한다. 로컬 선택을 보존하려면 `/__qa/state` 응답을 임시 JSON 파일로 저장하고 `INVITATION_QA_SEED_FILE=/tmp/저장한파일.json` 환경 변수로 시작한다. `INVITATION_QA_PORT`로 독립 검증용 포트를 지정할 수 있다.

Emulator 테스트는 `services/homehunt/cloud`의 설치된 Firebase 테스트 SDK와 Java·Firebase CLI를 사용한다. [기존 Emulator 환경](../../docs/development.md#firestore-emulator)을 준비한 뒤 루트에서 실행한다.

```sh
npx firebase-tools emulators:exec --only firestore --project demo-homehunt "node --test apps/invitation/tests/firestore.emulator.mjs apps/invitation/tests/profile.emulator.mjs"
```

로컬 Emulator 주소가 없거나 localhost가 아니면 테스트가 중단된다. 조회 시 미생성, 두 사람 동시 찜, 공동 선택 충돌·재저장, 오프라인 실패에 더해 공통 사진·예식장의 회원 경계·충돌·원자적 삭제를 실제 어댑터와 저장소 규칙으로 검사한다. 합성 사진과 가상 예식장을 사용하며 운영 저장·공개 배포를 검증 목적으로 실행하지 않는다. 이전 디자인 검증은 [검증 결과](../../docs/invitation-verification.md)를 참고한다.
