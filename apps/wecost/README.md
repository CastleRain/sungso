# WeCost

결혼비용과 저축을 모아 가용현금·집 예산·월 대출 부담을 비교하는 5탭 앱이다. **현재 데이터는 Firebase Firestore**이며 Google Sheets는 사용하지 않는다.

| 탭 | 역할 |
|---|---|
| 대시보드 | 가용현금·집 예산·월 납입·다가오는 지출·목표가 |
| 우리 자금 (현금흐름) | 두 사람의 현재 저축·월 저축·예상 저축 |
| 고정비 | 성우·소희·공동의 정기 지출, 월/연 결제·144개 아이콘·검색/정렬 |
| 결혼비용 | 항목별 계획·지급·잔금·분류·일정, Travel 신혼여행 세부 예산 연결 |
| 집 시뮬 | 지원금·대출·조정 항목을 포함한 자금 계획 |

소스는 `index.html`, `css/`, `js/`이며 `/sungso/wecost/`로 출력된다. 금융 계산·목표 집값 연결은 `shared/finance/`에서 HomeHunt와 공유한다. 컬렉션과 편집 시 주의할 필드는 [AGENTS.md](AGENTS.md)에 정리했다.

다섯 탭과 편집창은 `css/base.css`의 `--wecost-font-sans`를 통해 같은 로컬 Pretendard Variable을 사용한다. 공통 브랜드의 시스템 글꼴은 대체 글꼴로 유지하며 다른 앱의 글꼴을 바꾸지 않는다.

집에 쓸 예상 현금은 **결혼 시 예상 저축 + 포함한 부모님 지원 − 결혼비용의 추가로 모을 돈 ± 별도 조정**이다. 현재 저축에는 이미 지출한 비용이 반영되어 있으므로 전체 예정 비용을 다시 차감하지 않는다. 추가 필요액에는 남은 잔금·보유 결혼자금·현재 환율·예상 수입이 이미 반영된다. 등록된 회사 대출 등은 이 현금과 구분해 집 예산에 한 번 더한다. 결혼자금이나 필요한 환율이 미확인일 때는 집 예산도 미확인으로 표시한다.

Travel은 기존 `✈️신혼여행` 비용 항목 하나를 연결해 세부 예산과 증감을 보여준다. 양쪽 앱에서 같은 예상액·지급액·잔금을 사용하며, 신혼여행 비용을 새 장부 항목으로 복제하지 않는다. 공통 `travel-budget-core.mjs`·`travel-budget-store.mjs`가 계산·동시 편집 검사·금액 변경 이력을 담당한다.

저장소 루트에서 `npm run dev`를 실행한다. [개발·검증](../../docs/development.md), [과거 백업·참고자료](../../archive/wecost/)를 참고한다. 백업은 현재 앱의 원본으로 덮어쓰지 않는다.

고정비는 `?tab=fixed`에서 관리한다. 첫 화면은 각 담당자당 최대 5개이며 전체 목록에서 모든 항목을 검색·수정한다. 금액은 원 단위로 보관하고 연간 결제만 월 환산해 비교한다. 기존 월 저축액은 순저축 계획이므로 고정비를 다시 차감하지 않는다.
