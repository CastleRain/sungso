# 매출 앱 지침

루트와 상위 소희 지침을 따른다. 이 앱의 회원 전용 Firestore 저장/조회·원본 갱신 구현은 사용자가 요청한 범위다. 운영 데이터 이전·공개 배포는 별도다.

- `sohee/`는 비공개 입력일 뿐 웹 자산이 아니다. 분석 숫자를 JSX·CSS·테스트 fixture·문서에 옮기지 않는다.
- 기본 빌드는 공통 인증 뒤 Firestore만 읽는다. QA 대역은 별도 로컬 빌드에만 연결한다. URL 파라미터로 인증을 끄는 기능을 넣지 않는다.
- 갱신 시 실제 새 토스 원본을 사용한다. 화면 합계로 거래를 만들어서는 안 된다. 페이히어의 메뉴 시각을 보간하지 않는다.
- 팩/개, 부분일, 큰 주문, 표본 부족, 실제 예측 오차를 유지한다. 사장의 판단을 돕되 개인 성과 원인이나 확정 생산량을 주장하지 않는다.
- 새 서버 계약은 `services/sohee/`가 소유한다. 읽기 시 시딩하지 않는다. 공통 테마·기존 Firebase 앱 이름·SDK·회원 정리를 보존한다.
- `verification.md`에 실제 확인한 범위만 기록한다. 화면 QA는 합성 데이터로 진행한다.

- 수집은 사용자가 “매출 갱신해줘”라고 요청한 때 Codex가 이 컴퓨터에서 토스를 여는 수동 절차다. 예약·백그라운드 수집이나 Open API 연결을 기본 후속으로 제안하지 않는다. 페이히어는 과거 자료로 보존한다.

- 주 탐색은 대시보드(`changes`)·매출 내역(`overview`)·메뉴 전략(`menus`)·디저트 준비(`prep`) 네 화면이다. 기본 `/sales/`는 대시보드이고 기존 다섯 URL을 보존한다. `data`는 호환용 직접 경로이며 자료 기준/저장된 분석 재조회는 하단에서 제공한다.

## 진행 상황

### 2026-11-03 — 매출 원본 글래스 재질 복원

- 주요 요약·차트·표·기간 카드의 표면을 공통 `--ss-material-*`에 연결하고 중첩 카드 blur를 제거했다. 앞선 날짜 선택 가독성 보완을 유지하도록 Mantine 팝오버·달력·편집 서랍은 불투명하게 두었다.
- 기본 모드·배치·서체·상태색·JS 변경 없이 투명도 줄이기/필터 미지원 fallback을 보완했다. 통합 check 2,323개·최종 빌드를 통과했다. 합성 1440/390px의 주요 지표·그래프, 실제 달력 팝오버의 불투명 배경과 화면 내 경계를 확인했다. 모바일 가로 넘침은 0이다.

**다음:** 새 배경에서 매출 지표·차트·기간 선택과 열린 달력의 대비를 재확인한다.

### 2026-11-03 — 밝은 글래스 표면과 비교 자료 접기

- 기본 화면 구조와 네 메뉴·다섯 경로를 유지하고 글래스에서만 공통 셸과 밝은 카드·지표·차트·표·달력·서랍을 적용한다. 실제 현재 다섯 지표, 기간·부분일·표본 제한·원본 갱신·규칙 저장 동작을 유지한다.
- 과거 아메리카노 포장할인 비교는 글래스에서 접어 보조 정보로 제공한다. 기본에서는 기존처럼 펼쳐지며 내용 DOM을 유지해 정렬·읽기 상태를 보존한다. 전환 이벤트와 펼침 상태 유지의 합성 컴포넌트 검사를 추가했다.
- 계산/조회 등 61개 검사와 실제 Mantine 컴포넌트 검사를 통과했다. 브라우저에서 실제 차트·모바일 배치 검증은 통합 담당의 후속 범위다. 서버·운영 DB·개인 수치·원본 갱신 계약은 변경하지 않았다.

**다음:** 기본/글래스 왕복 시 날짜·필터·열린 편집 상태와 네 경로를 통합 화면에서 확인한다.

### 2026-11-03 — 글래스 매출 실제 화면 검증
- 대시보드·매출 내역·메뉴 전략·디저트 준비의 기존 4개 경로를 확인했다. 최근 7일 선택 후 두 모드의 주요 금액 텍스트가 같고 기간이 유지된다. 날짜 선택 패널·메뉴 구성 편집/취소·과거 포장할인 펼침도 확인했다.
- 1440/390/320px 가로 넘침 없이 표시되며 KPI 글씨 대비와 달력의 뒤쪽 글자 비침을 보완했다. 달력 패널은 불투명 흰색, 강조 라벨은 rgb(53,101,138)이다. 계산·원본 수집·운영 DB 쓰기는 없다.
- 전체 회귀 2,323개 통과. 별도 공개 번들 경계 검사는 통과했으며 비공개 아카이브가 없는 이 작업 폴더에서는 실제 수치 sentinel 검사는 생략됐다.

**다음:** 운영 자료로 표시 밀도를 읽기 전용 확인한 뒤 릴리스 여부를 결정한다.
