# 양정커피 회원 전용 매출 분석

기존 `sohee/combined`의 React·Recharts·TanStack Table·Lucide 화면과 준비량 계산을 재사용한 회원 전용 앱이다. 작업실·포트폴리오는 보존하고 작업실에 매출 앱 링크를 추가했다. 최신 분석의 Firebase 이전과 회원 접근 규칙 반영을 완료했다. 웹 배포 결과는 검증 기록의 운영 연결 항목을 따른다.

## 화면과 실행

| 경로 | 주요 판단 |
|---|---|
| `/sungso/sohee/sales/changes/` | 대시보드: 매출 요약·완결일 비교·일별/누적·메뉴 순위·요일/시간·큰 주문 영향 |
| `/sungso/sohee/sales/overview/` | 매출 내역: 일별 금액·결제 순건수·여러 날짜 달력·월별 원장 |
| `/sungso/sohee/sales/menus/` | 메뉴 판매: 수량·금액·메뉴 금액 비중·월 변화·토스 날짜/주문 시간, 개/팩 구분 |
| `/sungso/sohee/sales/prep/` | 디저트 준비: 당일 초안·요일/시간·여유분·직접 수량·검증 오차 |
| `/sungso/sohee/sales/data/` | 이전 직접 링크 호환용 자료 기준·원본 검증/저장. 주 탐색에서 제외 |

각 경로의 HTML을 생성하므로 해시 라우팅이나 서버의 SPA fallback 없이 직접 접근·새로고침·뒤로/앞으로 이동이 가능하다. `/sales/`는 대시보드다. 매출 내부의 일반 링크 클릭은 History API로 화면만 전환하여 회원 셸·조회한 자료·분석 날짜를 유지한다. 매번 sungso 인증 화면을 다시 띄우거나 Firebase 분석을 다시 내려받지 않는다. 새 탭·직접 진입·새로고침에는 기존 공통 인증을 그대로 적용한다. 분석 화면은 작업실로 돌아갈 수 있고, 대시보드의 ‘과거 변화와 비교 근거’ 옆 패널에서 기존 포트폴리오 예시로 이동한다. 매출을 포트폴리오로 복제하지 않는다.

루트에서:

```sh
npm ci --prefix apps/sohee/sales
node apps/sohee/sales/preview.mjs --qa
```

`http://127.0.0.1:4176/sungso/sohee/workspace/`는 **가상 자료 전용 화면 QA**다. 실제 계정·DB·토스 요청을 보내지 않는다. 테스트 전용 연결 모듈은 QA 빌드에만 포함한다.

`node apps/sohee/sales/preview.mjs`는 `4177`에서 실제 공통 회원 인증을 사용하는 로컬 셸을 제공한다. 운영 Firebase에 저장된 최신 분석을 읽는다. 원본 갱신 API는 같은 PC의 `8791`로만 프록시하며 서버 실행은 [서비스 안내](../../../services/sohee/README.md)를 따른다.

독립 프로토타입 Vite만 실행한 `4175` 대신 위 통합 미리보기를 사용한다. 소희 프로토타입의 기존 Sites 파일은 보존했다. 루트 `config/apps.json`은 생성된 회원 셸과 코드만 등록한다. 대문·모든 앱에서 소희 작업실로 이동하며 기존 공유 홈 저장 스키마는 유지한다. 프로토타입이나 비공개 아카이브 전체를 공개 허용 목록에 넣지 않는다.

## 화면 구성

기본 표현 계층은 `src/polish.css`와 `src/charts.jsx`, 데스크톱의 한 화면 배치는 `src/compact.css`, 메뉴/준비 화면의 밀도는 `src/menu-compact.css`·`src/prep-compact.css`에서 관리한다. 넓은 화면에서는 상단 로고와 네 메뉴를 같은 줄에 놓고 제목·기간·지표의 여백을 줄인다. 1440×900·1920×1080·1327×998 기본 상태에서 네 화면 모두 문서 세로 스크롤 없이 확인했다. 긴 목록은 이름과 값을 자르지 않고 표/순위 안에서 스크롤하며, 상세는 필요할 때 옆 패널로 연다. 작은 화면은 읽을 수 있는 크기와 문서 세로 스크롤을 유지한다.

기간 선택은 한 영역에 모으고 메뉴 정렬은 순위 카드 안에 둔다. 순위는 긴 이름·정확한 금액·수량·비중을 함께 읽는 Mantine Progress 목록, 메뉴 월별 변화는 매출 막대와 수량 선을 분리한 두 축, 누적 매출/시간대는 면적, 큰 주문 비중은 링, 준비 흐름은 시간창별 가로 막대를 사용한다. 수량과 금액의 단위·부분일·표본·검증 오차는 계속 표시한다. 모바일에서도 네 주 메뉴가 바로 보이며 넓은 표는 내부 스크롤한다.

사용자가 선택한 2번 ‘원장 중심’ 시안에 공통 날짜 필터를 더했다. 월·연속 기간·떨어진 여러 날짜·최근 7개 달력일·전체 기간을 선택하며, 하단 매출 달력의 기본 클릭은 일별 메뉴 상세를 열고 분석 기간은 유지한다. ‘여러 날짜 선택’으로 전환하면 다른 달의 날짜도 추가/해제한다. 최근 7일은 마지막 완결일까지다. 부분일 포함 조건과 날짜 선택은 매출 내부 이동·뒤로/앞으로 이동·명시적 분석 재조회 동안 유지하고, 새로고침/새 진입과 상단 양정커피 홈 클릭 시 최신 월 전체로 초기화한다. ‘최신 월 전체’ 버튼으로도 복귀한다. 선택은 메모리에만 보관한다.

대시보드·매출 내역·메뉴 판매·디저트 준비의 네 메뉴를 제공한다. 대시보드는 선택 기간 실매출·완결된 매출 기록일·일평균·결제 순건수·결제 1건당 실매출을 먼저 보여준다. 이어 일별/선택일 누적 Recharts 그래프, 메뉴 TOP 5와 메뉴 집계 금액 비중, 요일별 기록일당 매출/표본, 시간대, 토스 대량 주문 비중과 제외 금액을 한 화면에서 비교한다. 이전 기간 변화는 매출 옆에 한 번 표시하고 자세한 기간/비교 근거는 기록일 패널로 옮겼다. 비교 자료가 없으면 부족 상태를 표시한다. 과거 대량 주문/아메리카노/포트폴리오 근거는 ‘과거 변화와 비교 근거’ Drawer로 연다.

매출 내역은 달력과 일별 원장을 중심으로 구성하며 월별 원장은 펼쳐본다. 메뉴 판매의 기본 화면에는 7행씩 보는 원장과 상위 10개 순위를 두며 메뉴 금액 비중의 분모는 메뉴 집계의 합계다. 원장/순위의 메뉴 또는 ‘선택 메뉴 분석’을 누르면 월별 변화·선택일 시간대·날짜별 수량/금액을 Drawer에서 본다. 상세를 닫아도 선택 메뉴와 분석 기간을 유지한다.

디저트는 당일 총량·예측 기준, 요일/여유분/수량 조절, 준비표와 시간창별 흐름을 우선한다. 단순 평균보다 정확하지 않았다는 오차 설명은 기본 화면에 남긴다. 계산 방법·표본·판매 편차, 소량 메뉴 추가, ‘과거 판매와 비교하기’는 각각 Drawer에서 확인하며 실제 판매 기간과 고정된 학습 구간을 구분한다. 요일 비교·예측 검증은 기존 탭에서 전환한다.

자료 기준은 하단 작은 팝오버에서 수집 기간·완결일·부분일을 확인한다. ‘저장된 분석 다시 불러오기’는 Firebase 조회만 수행하며 토스 수집을 시작하지 않는다. 기존 데이터 관리 경로는 호환을 위해 남겨두지만 네 메뉴에 표시하지 않는다.

연속/개별 날짜의 메뉴·메뉴 시간·대량 주문은 토스 완결일 상세만 사용한다. Payhere 월별 메뉴를 날짜로 배분하지 않는다. 저장된 결제 시간대는 월 단위이므로 날짜 선택 시 메뉴 주문 시작 시각으로 명확히 구분해 표시한다. 비교는 선택 완결일의 시작~끝 길이만큼 이전으로 이동한 같은 날짜 간격을 사용하고, 수집 누락이나 이전 자료 부족 시 변화율을 제시하지 않는다. 예측은 저장된 학습 구간을 유지하며 날짜 필터로 재학습하지 않는다.

소희 작업실·포트폴리오·매출은 같은 사이트에서 제공하는 Pretendard Variable을 사용한다. 다른 sungso 앱의 글꼴은 유지한다. 좁은 화면도 네 메뉴를 바로 표시하고 내부 표 스크롤, 준비표의 고정 메뉴 열을 사용한다.

버튼·선택창·달력·날짜/시간·수량·체크박스·슬라이더·접기·파일/암호 입력은 Mantine 8.3.18로 구성하고 sungso 테마 토큰을 연결한다. React 19.1.1을 유지하며 라이브러리의 브라우저 기본 입력 외형을 그대로 노출하지 않는다. 선택창은 회원 화면 트리 안에서 열려 로그아웃 시 함께 제거된다.

[시안 대조와 반응형 검증](design-qa.md)에 가상 자료 캡처와 확인 범위를 기록했다. 실제 매출은 디자인 시안이나 캡처에 사용하지 않았다.

## 일별 상세와 메뉴 집계 수정

대시보드와 매출 내역의 **일평균 매출**은 선택 날짜 중 `record_day=true`인 완결일의 실매출 합계를 해당 날짜 수로 나눈 값이다. 순매출이 0원이어도 결제 기록일이면 포함한다. 부분일·미수집일·`record_day=false` 날짜는 분자와 분모에서 제외한다. `record_day=false`에는 환불만 기록된 날도 있을 수 있으므로 휴무나 0원으로 단정하지 않는다. 해당 완결 기록일이 없으면 평균은 ‘—’다. 선택 기간의 **총매출**은 기존 집계 범위를 유지하므로 평균에 제외한 환불/부분일 금액도 원래 조건에 따라 반영될 수 있다.

‘매출 기록일’의 날짜 확인 또는 ‘집계 기준·기록일’에서 포함/제외 날짜와 계산식을 확인한다. 근무·출퇴근 기록은 없으므로 실제 근무일시를 만들지 않는다. 토스 완결일은 저장된 메뉴 주문 기록 중 가장 이른 시간대와 가장 늦은 시간대를 별도 상세로 제공한다. 수량 또는 금액이 있는 시간별 집계이며 보존된 환불 기록도 포함할 수 있다. 정확한 첫/마지막 거래 시각, 개점·폐점·근무 시간이나 전체 영업 시간을 뜻하지 않으며, 페이히어와 부분일의 메뉴 시각을 추정하지 않는다.

매출 내역 상단의 전체·토스·페이히어로 출처를 나눈다. 이 필터는 현재 매출 내역에만 적용되며 선택 출처의 요약·기록일·달력·원장·CSV를 함께 좁힌다. 선택 기간에 해당 출처의 날짜가 전혀 없으면 그 출처의 최신 월 전체로 이동한다. 출처를 다른 화면으로 전달하거나 원본을 수정하지 않는다.

상단 분석 기간을 바꾸면 달력은 마지막 선택 날짜가 있는 달로 맞춰진다. 월 전체 상태에서 달력 월을 넘기면 상단 월도 바뀌며, 연속/개별 기간 상태에서는 선택한 달 사이를 이동해도 분석 기간을 유지한다. 여러 날짜 선택 모드는 다른 달에서도 날짜를 추가/해제한다. 상단 날짜 팝업도 현재 기간의 마지막 달에서 열린다.

표와 달력에서 메뉴 조회 가능 여부를 표시한다. 토스의 메뉴 보기·부분일·상세 없음과 페이히어의 월별만을 구분한다. 페이히어 상세의 월별 메뉴 바로가기는 해당 월을 적용하고, 메뉴 화면은 그 월의 모든 출처를 집계한다.

매출 내역의 날짜 또는 달력을 누르면 토스 완결일의 판매 메뉴·수량·단위·금액을 옆 패널로 확인한다. 월 전체 필터는 그대로 유지한다. 메뉴 날짜가 없는 Payhere, 저장 상세에서 제외된 부분일, 상세가 없는 날은 이유를 표시하고 월별 합계로 메뉴를 만들어 넣지 않는다.

메뉴 판매의 **메뉴 이름·수량 수정**은 판매 상품 → 구성 메뉴의 두 단계로 표시한다. 원본 상품 하나가 팔릴 때 반영할 **집계할 메뉴·들어있는 수량·수량 단위**를 직접 지정하고 Firebase에 저장한다. 집계할 메뉴는 기존 메뉴에서 고르거나 새로운 이름을 입력할 수 있으며, 저장한 새 이름은 다음 상품 설정의 선택 후보에 나타난다. 미리보기는 실제 원본 이름 1팩 → 지정한 메뉴 4개처럼 표시한다. 별도 낱개 상품도 같은 메뉴/단위와 수량 1로 지정하면 합산되며, 같은 대상에 연결된 다른 설정을 보여준다. 이름에 숫자를 쓰는 것만으로 수량을 추정하지 않는다. 같은 이름과 같은 단위만 합산하며 원본과 매출액은 보존한다. 수정은 과거 전체 기간과 앞으로 같은 원본 이름으로 들어오는 자료에 적용된다. 원본 이름이 달라지면 사용자가 별도로 연결해야 한다.

`sohee_menu_rules/{SHA256(원본 이름)}`는 인증된 활성 회원이 공유하는 별도 설정이다. `sourceName`, `targetName`, `unit`, 정수 `multiplier`(1–100), `enabled`, `revision`, `updatedBy`, 서버 `updatedAt`을 저장한다. 읽기로 문서를 만들지 않고, 저장 시 transaction으로 기존 revision을 비교한다. 충돌 시 입력은 유지하며 닫고 다시 열면 최신 서버 설정을 읽는다. 원본 집계 복원은 설정을 비활성화하며 삭제하지 않는다. 새 토스 분석을 올려도 이 컬렉션을 덮어쓰지 않는다. 다른 화면의 변경은 재조회 또는 편집 패널을 다시 열 때 가져온다.

디저트 준비 초안과 예측 오차는 원본 이름·학습 단위 그대로다. 표시 이름을 고쳤다고 과거 예측을 재학습하거나 서로 다른 모델 결과를 합치지 않으며 화면에 이를 알린다.

## 수동 갱신

요청할 때 Codex가 이 컴퓨터에서 토스를 열어 새 원본을 받아 검증하고 Firebase에 저장한다. 로컬 갱신 도구와 기존 관리 경로를 유지하며 일반 대시보드에서 수집을 시작하지 않는다. 예약 수집·앱 실행 시 자동 수집·토스 Open API를 사용하지 않는다. 페이히어는 과거 자료로 유지한다. [구체적인 절차](../../../services/sohee/manual-update.md)를 따른다.

## 데이터·보호 경계

- 빌드에는 코드·공통 테마·라이브러리만 들어간다. 실제 매출 JSON/CSV/XLSX, 원본 HTML 보고서와 QA 자료는 운영 번들에 포함하지 않는다.
- `shared/firebase/boot.mjs`가 Google 활성 회원 확인 후 앱을 시작한다. 기존 SDK 10.12.0과 `homehunt-private-cloud` 앱을 재사용하고 `syncAppAuth` 후에만 조회한다.
- Firestore `sohee_sales/current`의 현재 버전과 `sohee_sales_versions/{hash}/chunks/{index}`를 서버에서 읽는다. 누락 조각·해시 불일치를 거부하며 브라우저 디스크 캐시를 새로 만들지 않는다.
- 원본 분석은 두 활성 역할 회원만 get 가능하고 브라우저의 list·쓰기·삭제는 금지한다. 계정 전환/권한 변경/로그아웃 시 공통 정리로 React·메모리·진행 중 요청을 정리한다. 늦은 응답은 무시한다.
- 조회와 첫 진입은 시딩·쓰기·수집을 하지 않는다. 저장된 분석 재조회와 새로운 토스 원본 수집을 명확히 구분한다.
- `sohee/` Git 제외는 루트에서도 고정했다. 실제 원본은 그대로 보존했다. 화면에서 따로 관찰된 합계를 거래로 생성하지 않았다.

## 해석

디저트는 당일 판매·이월 0 기준이다. 메뉴 시각과 준비 예측은 토스 완결일만 사용하며 큰 주문을 분리한다. 예측/단순 평균의 MAE·WAPE, 표본 부족·참고 메뉴를 함께 표시한다. 준비 수량 조정은 화면 메모리에서만 유지하며 CSV로 내려받을 수 있다. 미래 판매나 확정 생산량을 보장하지 않는다.

수정하지 않은 4구는 판매 표에서 1팩, 준비 합계에서 실물 4개로 표시한다. 매출 기록 없는 날을 휴무로 단정하지 않고, 개인 기여 시점·운영 변경일·매출 변화의 원인은 미확인으로 표시한다. 비용 자료가 없어 순이익을 계산하지 않는다.
