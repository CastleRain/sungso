# 소희 공간 지침

루트 AGENTS.md와 README.md를 따른다. 기존 공동 앱을 대체하지 않는다.

- 현재 `prototype/`은 독립 로컬 미리보기이고 config/apps.json에 등록하지 않는다.
- `prototype/`은 둘 모두 편집할 미래 공간의 예시이며 개인 데이터를 직접 연결하지 않는다. 사용자 요청의 `sales/`는 공통 회원 인증·Firestore 조회와 별도 원본 갱신 서비스를 사용한다.
- 실제 프로젝트가 아직 없으므로 작업실은 빈 상태다. 포트폴리오 구성 예시를 실제 경력·실적으로 기록하지 않는다.
- Sheets·사진 업로드·AI 추천·PDF·배포는 요청 전까지 범위를 확대하지 않는다.
- 선택된 대문 시안은 오른쪽 ‘우리의 작업실’ 영역이다. 포트폴리오는 사용자 요청에 따라 첫 시안을 임시 예시로 구현했으며 최종 디자인 선택으로 간주하지 않는다.
- 기존 공통 테마 토큰을 직접 import한다. 새 색상을 하드코딩하지 않는다.
- 사용자 선택에 따라 Pretendard Variable은 소희 앱 전체에만 적용한다. 공통 `reading-font.css`를 선택적으로 로드하며 다른 sungso 앱의 글꼴을 변경하지 않는다.
- 정식 통합 시 공통 회원 인증 이후 개인 영역을 표시하고 기존 저장 계약을 보존한다. 프로토타입의 무인증 예시 화면을 실제 개인 기록에 재사용하지 않는다.

- 2026-09-27: 소희 작업실에서 별도 다섯 경로의 매출 앱으로 연결한다. 통합 로컬 미리보기는 `sales/preview.mjs`다. 운영 데이터 이전·규칙/Pages 배포·토스 자동 수집은 별도이며 가상 QA와 실제 매출을 구분한다.

- 2026-09-27: 사용자 연결 요청으로 `workspace/`에 회원 진입점을 만들고 기존 구성 요소를 재사용한다. `build.mjs`가 생성한 코드 전용 `dist/`만 등록부에 포함한다. `prototype/`의 독립 시안·Sites 파일과 가상 표시를 보존한다.

## 진행 상황

### 2026-11-03 — 회원 작업실의 밝은 글래스 화면

- 기존 작업실 구성 요소·기본 화면·저장 없는 빈 상태를 유지하고, 글래스에서만 빈 세 탭을 감춰 매출과 포트폴리오 진입을 우선한다. 공통 셸과 Pretendard를 사용하며 별도 `workspace/glass.css`로 카드·빈 화면·모바일 표면을 구성했다. 실제 프로젝트나 경력을 만들지 않았다.
- `build.mjs`는 `/sohee/`와 `/sohee/workspace/`에만 공통 전환 자산을 넣는다. 세 포트폴리오 HTML과 기존 작업실 JS/CSS는 보존 기준본과 SHA-256이 모두 같다. 독립 prototype과 포트폴리오 스타일은 변경하지 않았다.
- 앱 빌드, 매출 61개 검사와 실제 Mantine 컴포넌트 검사를 통과했다. 이번 단계의 실제 브라우저·공통 셸 연결 검증은 통합 담당이 진행한다. 인증·서버·DB 계약과 운영 자료를 변경하지 않았다.

**다음:** 공통 셸에서 기본/글래스 전환과 작업실→매출 이동을 PC·모바일로 검증한다.

### 2026-11-03 — 회원 작업실 실제 화면 확인
- 1440/390/320px 글래스와 기본 전환을 확인했다. 빈 오늘·프로젝트·인박스 탭은 기본에서 복원되며, 글래스에서는 매출·포트폴리오 진입을 우선한다. 매출 분석 링크를 직접 이동해 확인했다.
- 실제 프로젝트 기록을 새로 만들지 않았으며 포트폴리오·원래 작업실 번들은 기준 해시를 유지한다.

**다음:** 매출 사용 피드백에 따라 작업실의 실제 콘텐츠가 생길 때만 메뉴를 확장한다.
