# 우리 결혼 작업 지침

[루트 지침](../../AGENTS.md)과 [앱 설명](README.md)을 따른다. 소스 `apps/wedding/`은 `/sungso/wedding/`에 출력한다.

- `index.html`의 `[data-private-root]`는 숨긴 상태로 시작한다. 공통 `shared/firebase/boot.mjs`가 회원 확인 뒤 앱 entry를 로드한다. 앱이 새 Firebase 인스턴스·컬렉션·규칙을 만들지 않는다.
- 앱 정의의 ID는 `wedding`, 탭은 `guests/tasks`다. `js/entry.mjs`는 실제 소스 경로로 공통 `shared/life/ui.mjs`를 import한다.
- 신규 생활 기록은 계정별 브라우저 로컬 저장이다. UI에서 이 범위와 자동 공동 저장 미구현을 알린다. 로그인 전 읽기와 샘플 자동 시딩을 금지한다.
- 하객의 초대는 `pending/sent`, 참석은 `unknown/yes/no`, 인원은 동반인 포함 1~20 정수다. 상태 변경은 기록 수정이며 초대·메시지 전송이 아니다.
- 하객 연락처·축의금·외부 연락 기능·공개 응답 페이지를 부수적으로 추가하지 않는다. 실명·개인 메모는 Git·공개 자산·QA 캡처에 넣지 않는다.
- 기존 청첩장·WeCost·Honeymoon·Travel·Dates는 공개 URL을 유지한 링크로 연결한다. 기존 공동 선택·비용·일정을 새 하객/준비 저장소에 복제하거나 자동 변경하지 않는다.
- 로그아웃·계정 전환 때 개인 DOM·메모리·리스너를 정리하고 로컬 저장 기록은 임의로 삭제하지 않는다. 저장 실패나 충돌에서 입력을 보존한다.

검증은 루트 build/test/check와 1440px·390px 운영 연결 차단 대역을 사용한다. 사용자 개인 자료나 실제 서비스에 테스트 기록을 쓰지 않는다.

## 진행 상황

### 2026-09-14 — 생활 앱 기본틀

하객노트·준비 메모의 앱 정의와 회원 인증을 거치는 진입점, 기존 결혼·여행 앱 링크를 작성했다. 새로운 운영 데이터 연동·원격 배포는 수행하지 않는다.

공통 UI·저장소를 통합하고 하객 참석 3명 집계·준비 완료·수정/삭제 취소, 생활 앱 간 연결을 1440px·390px 대역에서 확인했다. 원래 결혼 앱 데이터는 변경하지 않았다. [통합 검증](../../docs/life-local-verification.md)을 따른다.
