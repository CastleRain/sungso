# 우리 결혼 작업 지침

[루트 지침](../../AGENTS.md)과 [앱 설명](README.md)을 따른다. 소스 `apps/wedding/`은 `/sungso/wedding/`에 출력한다.

- `index.html`의 `[data-private-root]`는 숨긴 상태로 시작한다. 공통 `shared/firebase/boot.mjs`가 회원 확인 뒤 앱 entry를 로드한다. 앱이 새 Firebase 인스턴스·컬렉션·규칙을 만들지 않는다.
- 앱 정의의 ID는 `wedding`, 탭은 `guests/tasks`다. `js/entry.mjs`는 실제 소스 경로로 공통 `shared/life/ui.mjs`를 import한다.
- 신규 생활 기록은 계정별 브라우저 로컬 저장이다. UI에서 이 범위와 자동 공동 저장 미구현을 알린다. 로그인 전 읽기와 샘플 자동 시딩을 금지한다.
- 하객의 초대는 `pending/sent`, 참석은 `unknown/yes/no`, 인원은 동반인 포함 1~20 정수다. 상태 변경은 기록 수정이며 초대·메시지 전송이 아니다.
- 하객 연락처·축의금·외부 연락 기능·공개 응답 페이지를 부수적으로 추가하지 않는다. 실명·개인 메모는 Git·공개 자산·QA 캡처에 넣지 않는다.
- 기존 청첩장·WeCost·Honeymoon·Travel·Dates는 공개 URL을 유지한 링크로 연결한다. 기존 공동 선택·비용·일정을 새 하객/준비 저장소에 복제하거나 자동 변경하지 않는다.
- 로그아웃·계정 전환 때 개인 DOM·메모리·리스너를 정리하고 로컬 저장 기록은 임의로 삭제하지 않는다. 저장 실패나 충돌에서 입력을 보존한다.

검증은 루트 build/test/check와 1440px·390px 운영 연결 차단 대역을 사용한다. 사용자 개인 자료나 실제 서비스에 테스트 기록을 쓰지 않는다.

## 진행 상황

### 2026-11-03 — 하객·준비·공동 작업실 밝은 글래스

- 기본 화면과 하객/준비 저장 흐름을 유지하며 글래스 하객 행에서 양측·초대·참석·인원을 구분했다. 기존 집계와 메모·수정/삭제·준비 체크·로컬 저장 안내·백업을 보존하고 대형 반복 D-day는 추가하지 않았다.
- 기존 앱 정의에 있었지만 링크 허용식에 걸려 누락되던 `./invitation.html` 공동 작업실 연결을 명시적으로 허용했다. 임의 상대 페이지·외부 주소는 계속 허용하지 않는다. 작업실의 기존 스타일은 해당 본문으로 범위를 좁혀 공통 메뉴를 덮지 않도록 했으며 공개 청첩장 코드는 바꾸지 않았다.
- 신규 생활 UI 대역 4개와 기존 저장·핵심 로직 16개 통과. 합성 하객 3명 집계·초대/참석 구분·작업실 링크·로그아웃 DOM 정리를 검증했다. 실제 브라우저와 공동 작업실 원격 상태 검증은 통합 단계에서 이어간다.

**다음:** 통합 화면에서 하객 행·편집 창·작업실 진입과 기본/글래스 복원을 확인한다.

### 2026-09-14 — 생활 앱 기본틀

하객노트·준비 메모의 앱 정의와 회원 인증을 거치는 진입점, 기존 결혼·여행 앱 링크를 작성했다. 새로운 운영 데이터 연동·원격 배포는 수행하지 않는다.

공통 UI·저장소를 통합하고 하객 참석 3명 집계·준비 완료·수정/삭제 취소, 생활 앱 간 연결을 1440px·390px 대역에서 확인했다. 원래 결혼 앱 데이터는 변경하지 않았다. [통합 검증](../../docs/life-local-verification.md)을 따른다.

**다음:** 하객 입력 흐름을 로컬에서 검토하고 공동 하객노트 저장을 설계한다.


### 2026-10-31 — 청첩장 공동 작업실

사용자가 studio 선택을 wedding과 연계하도록 요청했다. invitation.html은 기존 회원 인증 뒤 전용 Render studio API로 공동 초안과 공개 상태만 읽는다. 저장·명시적 공개·이전 공개본 복원은 인증된 Vercel 스튜디오에서 수행한다. 기존 하객노트·준비 메모의 로컬 저장과 계좌·사진 관리 권한은 유지한다.

**다음:** 배포 후 두 회원이 실제 조합을 공동 저장하고 확인한 뒤 공개한다.

### 2026-11-03 — 결혼 준비 글래스 화면 검증
- 하객 합계·수정 창·취소, 준비 메모 탭의 모드 전환 보존, 1440/390/320px 가로 넘침 없음을 합성 기록으로 확인했다. 청첩장 작업실 연결을 복구하고 관리 페이지에도 공통 스타일을 적용했다.
- 외부 스튜디오 API는 QA에서 차단한다. 공동 초안 저장·공개와 하객용 페이지는 변경하지 않았다.

**다음:** 실제 하객 목록과 공동 초안 상태를 읽기 전용으로 확인한다.


### 2026-11-03 — 글래스 재질 보완과 재검증

shared/life/glass.css의 준비 목록·요약을 공통 유리 재질로 연결했다. 중첩 블러를 제거하고 입력은 읽기용 표면을 유지했다. 합성 1440px에서 결혼 화면의 재질·가독성을 대조했다. 기본 배치·데이터 계약·JS는 변경하지 않았다. 전체 검증과 한계는 루트 design-qa.md의 재질 보완 항목을 따른다.

**다음:** 실제 사용 화면에서 대표색·투명감의 균형을 확인한다.
