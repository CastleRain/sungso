# 우리의 발자취

성우와 소희가 서로 만나러 간 이동과 함께한 장소·사진을 날짜별로 보관한다. `/sungso/journey/`에서 공통 Google 회원 로그인 뒤 사용한다.

1. **타임라인 추가**에서 누구의 기록인지 고르고 Google 타임라인 JSON을 선택한다. 미리보기 뒤 날짜별로 저장한다. 같은 원본·겹친 경로는 중복 저장하지 않으며 직접 수정한 기록을 유지한다.
2. **기록 추가 / 사진 추가**에서 날짜·사람·장소 제목·선택 메모를 작성한다. 위치가 있으면 지도에서 선택하거나 좌표로 입력한다. 모르는 시간·위치는 비워둘 수 있다.
3. **달력 펼치기**에서 저장한 달·날짜를 고르거나 날짜 양옆 화살표로 기록 있는 날을 이동한다. DB의 기록과 사진을 다시 읽으며, **사진·기록 펼치기**에서 사진/기억을 눌러 수정할 수 있다.
4. 지도에서 **이동 재생**을 누르면 실제 기록 시각에 맞춰 성우·소희의 이동점과 지나온 길을 표시한다. 일시정지·시간 막대·0.5~4배속·시작으로를 사용할 수 있다. 기본 1배속은 한 날짜의 기록 범위를 60초로 압축한다.

지도부터 보이며 달력과 아래 기록은 각각 펼치고 접을 수 있다. **지도에 집중**은 둘 다 접는다. GPS가 끊긴 구간은 직전 확인 위치에 `기록 공백`으로 표시하며 빈 구간을 경로로 만들지 않는다. 마지막 확인점은 `마지막 기록`으로 구분한다.

브라우저는 썸네일과 긴 변 1600px 이하 JPEG를 만든다. 원본 사진과 원본 타임라인 파일은 자동 백업하지 않으므로 별도로 보관한다. 저장은 회원 전용 Render API·전용 Firestore 문서를 사용하며 공개 저장소에 개인 파일을 올리지 않는다. 한도에 도달하면 기존 내용을 유지하고 안내한다.

기존 `/footprints/`의 장소·방문·앨범 링크는 그대로 남아 있다. 네이버 길찾기 파일 가져오기와 MP4 제작 연결은 이번 범위에 포함하지 않는다. 지도 SDK가 연결되지 않아도 사진·메모·좌표 입력과 DB 다시 보기는 사용할 수 있다.

개발: 루트 `npm run build`, `npm run check`, `npm run build:services`. 합성 기록 검증은 `node apps/journey/tests/qa-server.mjs`로 별도 localhost에서 수행한다. 실제 서비스에 검증용 쓰기를 하지 않는다.
