# 우리의 발자취

공개 경로 `/sungso/journey/`. 2026-10-28 사용자가 승인한 타임라인 누적·사진/수동 입력·회원 공동 DB 저장 범위다. 후속 요청에 따라 지도를 우선 표시하고 달력·사진 기록을 각각 접는다. 기존 footprints 로컬 기록은 별도 유지한다.

- 공통 Firebase boot 뒤에만 entry를 실행한다. 새 인증 인스턴스·공개 Firestore 직접 구독은 만들지 않는다. API는 기존 Render의 `/api/journey/v1`이며 두 활성 회원만 사용한다.
- shared/journey/core.mjs의 날짜별 계약을 사용한다. 시간은 UTC epoch ms, 날짜는 KST. 날짜만 아는 기록은 null 시간이며 정확한 시각을 생성하지 않는다.
- 타임라인은 브라우저 Worker에서 파싱하며 날짜별 명시적 저장을 한다. 중복된 사람·시각·좌표 구간과 원본을 비교하고 수동 입력·수정은 보존한다. 중간 실패는 저장된 날짜를 알리고 나머지만 재시도한다.
- 사진은 사용자 파일만 읽고 웹용 JPEG로 줄여 private API에 저장한다. 원본 파일·위치·토큰을 Git·공개 자산·로그에 넣지 않는다. EXIF 없는 사진은 위치와 시간을 추측하지 않는다.
- 네이버 Web SDK는 지도와 선택한 위치 표시만 사용한다. Directions·비공식 API·스크래핑·위치 추적은 없다. 링크/GPX 경로 가져오기와 MP4는 사용자에 의해 후속 범위로 남겨졌다.
- 계정 전환 때 요청·Worker·사진 URL·개인 DOM을 정리한다. 저장 실패에서 입력을 유지하고 다른 revision의 내용은 덮어쓰지 않는다.
- 검증은 합성 데이터/메모리 서버/Emulator만 사용하며 운영 테스트 쓰기·사진 업로드를 하지 않는다.
- 사용자가 명시적으로 지정한 실제 원본의 등록은 별도 승인된 작업으로 수행할 수 있다. 2026-10-28 Journey Studio의 Google 원본을 성우 기록으로 등록하라는 직접 요청에 따라 가져오기를 완료했다. 이후 검증은 읽기만 수행하며 원본·좌표·개인 장소·운영 캡처를 저장소에 넣지 않는다.
- 재생은 지도 어댑터의 `getPlayback()` 범위와 상태를 단일 기준으로 사용한다. 단독 GPS점과 구간 사이 공백은 경로로 연결하지 않는다. 접기·펼치기는 기록이나 현재 재생 위치를 바꾸지 않는다.

## 진행 상황

2026-10-28: 달력·사람별 지도·파일 미리보기·수동/사진 편집·사진 확대와 비공개 저장 API를 구현했다. 합성 브라우저 저장·재방문·실패 재시도와 네 화면 크기, UI15개·파서19개·지도/사진10개·API/저장13개 검사와 실제 Emulator63개를 통과했다. 상세 결과는 루트 진행 상황 및 `docs/journey-qa-2026-10-28/design-qa.md`에 기록한다.

공개 배포와 회원 조회·지도 표시·위치 선택을 확인했다. 운영 DB 검증 쓰기는 없다.
