# HomeHunt 작업 가이드

성우와 소희가 직접 본 아파트와 공식 실거래를 분리해 관리하는 정적 부동산 탐색 앱이다.

## 핵심 원칙

- 지도/주소: 네이버 Maps Web SDK. 브라우저 코드에는 Client ID만 두고, 서울·경기 시군구 선택은 공식 법정동 정적 대조표를 사용한다. 역지오코딩은 지도 중심 주소 자동입력용 선택 기능이다.
- 가격: 네이버 매물 크롤링이 아니라 국토부 매매·전월세 실거래를 사용한다.
- 개인 기록: 주소·메모는 기본적으로 `localStorage`에 둔다. 사용자가 로그인 후 저장을 선택하면 Google 검증·관리자 회원 등록·본인 UID 규칙으로 보호한 `homehunt_user_snapshots`에만 백업한다. 기존 공개 Firestore 컬렉션에는 쓰지 않는다.
- 공개 캐시: GitHub Actions가 생성한 집계 JSON에는 공공 실거래와 청약홈·LH·SH 공식 분양 공고만 포함한다.
- 단지 검색: 서울·경기 공식 단지 JSON → 로컬 서버/브라우저 IndexedDB → Firebase Function/Firestore 캐시 순으로 조회한다. 연결되지 않은 체험용 가격·단지는 실제 결과처럼 만들지 않는다.
- 지역 비교는 전용면적 구간을 맞추고, 단지 이력은 실제 전용면적 0.1㎡ 단위로 분리한다.

## 저장소 계약

방문 기록 localStorage 키: `homehunt_visits_v1`

후보 비교 localStorage 키: `homehunt_compare_ids_v1` (방문 ID 최대 3개, JSON 백업 v2에 포함)

```js
{
  id, name, address, lat, lng, visitDate,
  dealType, askingPrice, areaM2, floor, builtYear,
  households, walkMinutes, direction, status,
  visitedBy: ['성우', '소희'], pros, cons, memo, tags
}
```

시장 데이터는 `market-core.mjs`의 `normalizeTransaction()` 결과를 사용한다. 금액 단위는 만원, 면적은 ㎡, `priceP33 = amountManWon * 3.3 / areaM2`이다.

## 외부 설정

- Ncloud 운영 Web 서비스 URL: `https://castlerain.github.io`
- Ncloud 필수 API: `Dynamic Map`, `Geocoding`; 선택 API: `Reverse Geocoding` (지도 중심 주소 자동입력)
- 로컬 실행기는 Git에서 제외된 `homehunt/.env`의 허용 항목만 읽고, 이미 설정된 프로세스 환경변수를 우선한다. 화면에서 입력한 값은 `.env`에 쓰지 않고 실행 중인 서버 메모리에만 둔다.
- 로컬 환경변수: `MOLIT_SERVICE_KEY`, `NAVER_MAPS_CLIENT_ID`, `NAVER_MAPS_CLIENT_SECRET`, `NAVER_LOCAL_SEARCH_CLIENT_ID`, `NAVER_LOCAL_SEARCH_CLIENT_SECRET`, `KAKAO_REST_API_KEY`, `TMAP_APP_KEY`. 정책 값은 `TRANSIT_PROVIDER=auto|kakao|tmap`, `KAKAO_DAILY_LIMIT`(기본 1000), `TMAP_DAILY_LIMIT`(기본 10)이며 `HOMEHUNT_LOCAL_API_PORT`는 프런트와 함께 8787을 유지한다.
- 회사명·업체명 POI 검색은 Maps 키 범위가 아니다. 현재는 2026-07-30 이전 신청한 NAVER Developers `지역 검색` Application의 Client ID/Secret을 `homehunt/.env` 또는 로컬 서버 실행 메모리에 연결한다. 이 기존 계약은 2027-06-30까지만 지원되므로 그 전에 NAVER API HUB용 엔드포인트·인증으로 이관한다. 키가 없어도 주소·등록 건물명 후보와 지도 직접 선택을 유지한다.
- GitHub Actions secret: `DATA_GO_KR_SERVICE_KEY` 또는 청약홈 우선용 `APPLYHOME_SERVICE_KEY`. 같은 공공데이터 일반 인증키를 쓸 수 있지만 청약홈·LH 서비스는 각각 활용신청해야 한다.
- Telegram Actions secrets: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`. 맞춤 지역·신혼·가격·평형·세대수는 비민감 `HOMEHUNT_ALERT_*` Repository Variables로 별도 설정하고 개인 주소·청약정보는 넣지 않는다.
- Firebase Function secret: `MOLIT_SERVICE_KEY`
- Function cache: `homehunt_apartment_cache`
- Function raw cache: `homehunt_molit_month_cache`
- Function rate limit: `homehunt_api_limits`

실제 비밀키는 Git에서 제외된 `homehunt/.env` 또는 배포 플랫폼의 비밀 저장소에만 둔다. 코드, 추적 문서, `.env.example`, 테스트 fixture, URL, 브라우저 저장소·응답에는 넣지 않는다. `.env`는 로컬 평문 파일이므로 강제 add·공유·화면 캡처를 금지한다.
