# 무료 Firestore 운영과 서버 자료 정리

Render 서버가 재시작되어도 가격 검색 작업, 공공 원자료 캐시, 일일 통근 사용량은 Firestore에 남는다. Kakao·NAVER 경로 응답과 그 경로에서 계산한 점수는 저장하지 않는다. 일일 사용 장부에는 공급자·한국 날짜·사용 건수·갱신 시각만 남기며, 정리용 보관 종료 시각을 함께 둔다.

## 무료 범위

2026-09-08 공식 안내 기준 Standard Firestore 무료 할당량은 저장 공간 1 GiB, 하루 문서 읽기 50,000회·쓰기 20,000회·삭제 20,000회다. 무료 사용량의 날짜 갱신은 태평양 시간 기준이며 HomeHunt 통근 장부의 한국 날짜와 다르다. 관리형 TTL 삭제는 무료 할당 대상이 아니므로 이 구성에서는 TTL 정책을 만들지 않는다. [Firebase 사용량과 한도](https://firebase.google.com/docs/firestore/quotas), [과금 안내](https://firebase.google.com/docs/firestore/pricing)

HomeHunt뿐 아니라 같은 프로젝트의 WeCost·일정·신혼여행도 프로젝트의 무료 할당량을 사용한다. 조회 제한과 아래 정리는 사용량을 줄이기 위한 장치이며 **전체 저장 공간을 1 GiB 아래로 강제 제한하는 기능은 아니다.** 사용이 몰리거나 과거 자료가 많으면 무료 한도에 도달할 수 있다. Firebase Console의 Firestore 사용량에서 전체 저장 용량과 읽기·쓰기를 확인한다.

## 주차·난방·승강기 재사용

시설 정보는 이미 서버의 `homehunt_kapt_source_cache`에 공식 원자료로 보관한다. 같은 단지의 기본·상세 정보는 1일, 시군구 단지 목록은 7일 동안 재사용하므로 다른 기기에서 조회하거나 Render가 재시작되어도 유효한 원자료를 공급자에게 다시 요청하지 않는다. 개인 주차 메모·회사·통근 경로는 이 공공 캐시에 저장하지 않는다.

UI 4.15부터 같은 브라우저의 재방문에는 `homehunt_public_facilities_v1` IndexedDB도 사용한다. 단지 대조를 마친 공공 시설 응답만 API 주소·대조 버전별로 분리해 저장하며, 한 번에 읽어 가격 후보에 붙인다. 유효한 시설 579곳이 이미 있으면 이 579곳의 시설 API 요청을 생략하므로 인증과 Firestore의 반복 읽기도 줄어든다. 이는 통근 조회와 별개이며 Kakao 응답·점수·통과 판정을 저장하지 않는다.

- 공식 응답의 원래 만료 시각을 유지하며 최대 1일이다. 새 페이지를 열어도 유효기간이 늘어나지 않는다.
- 일부 항목만 확인된 경우에는 확인된 사실의 유효기간과 실패 부분의 재시도 시점을 각각 유지한다. 연결 실패 응답은 브라우저 DB에 저장하지 않는다.
- 브라우저 저장은 전체 API 환경을 합쳐 최대 3,000개로 제한하고 오래 저장된 항목부터 비운다. 저장소가 차단되면 기존 서버 조회로 진행한다.
- 다른 기기나 처음 보는 단지는 서버 공공 캐시를 확인한 뒤 부족한 원자료만 수집한다. 처음 조회하는 모든 단지의 시설이 즉시 채워지는 것은 아니므로 가격 후보를 먼저 보여주고 시설을 이어 보강한다.

이 브라우저 저장을 위해 Firestore 컬렉션·로그인 권한·유료 요금제를 추가하지 않는다. 공공 정보는 서버 캐시와 브라우저 캐시를 함께 사용하며, 개인 검색의 계정 저장과는 분리한다.

## 자동 정리 범위

`homehunt/server/firestore-maintenance.mjs`를 서버 시작 시 한 번 실행하고 이후 서버가 실행 중일 때 6시간 간격으로 호출한다. 정리를 위해 Render 무료 서버를 따로 깨우지는 않는다. 여러 프로세스가 동시에 시작해도 공유 제어 문서가 다음 실행 시각을 지키며, 예정 시각 전에는 정리 목록을 조회하지 않는다.

| 자료 | 재사용과 정리 기준 |
|---|---|
| 가격 검색 작업 `homehunt_jobs` | 작업 유효기간 24시간. 추가 1시간이 지난 만료 작업을 정리한다. 실행 중인 임대가 남아 있으면 보류한다. |
| 국토부 월별 자료 `homehunt_molit_month_cache` | 수집 후 90일 보관. 가격의 최신성은 기존 월별 유효기간과 서명된 수집일로 별도 판정한다. 이전 자료를 최신 자료로 표시하지 않는다. |
| K-apt 공공 자료 `homehunt_kapt_source_cache` | 목록 7일, 기본·상세 1일의 만료 자료를 정리한다. 갱신 중인 자료는 보류한다. |
| 허용된 TMAP 경로 캐시 `homehunt_route_cache` | 기존 8시간 유효기간이 지난 자료만 정리한다. Kakao·NAVER 경로는 이 캐시에 들어가지 않는다. |
| 요청 제한 `homehunt_request_limits` | 기존 2시간 보관이 지난 분 단위 제한 문서를 정리한다. |
| 통근 사용 장부 `homehunt_provider_usage` | 새 장부의 보관 기간은 한국 날짜 시작부터 7일. 추가로 **당일과 전일 장부는 만료 시각이 잘못되어도 삭제하지 않는다.** 공급자·날짜·문서 ID·사용량이 불일치하는 장부는 삭제하지 않는다. |

개인 백업·가구 저장소·회원 목록·WeCost·일정·신혼여행은 정리 대상에 포함하지 않는다. 서버 재시작이나 키 교체로 통근 사용량을 초기화하지 않는다.

## 한 번에 수행하는 작업의 상한

- 정리 실행당 문서 읽기 최대 500회, 삭제 최대 250회로 제한한다. 공유 제어 문서는 실행 시작·완료 때만 갱신한다. 정상 6시간 주기의 실행 부분은 하루 최대 2,000회 읽기·1,000회 삭제이며, 서버 재시작 시의 실행 여부 확인 읽기는 별도다.
- 부모 목록은 `expiresAt` 하나의 범위 조건·같은 필드 정렬·최대 25개 제한으로 찾는다. 하위 `chunks`도 한 번에 최대 64개만 조회한다. 전체 컬렉션 순회나 컬렉션 그룹 조회를 하지 않는다.
- 실제 삭제 직전에 트랜잭션으로 부모의 만료·진행 상태를 재확인한다. 갱신된 자료를 삭제하지 않으며 트랜잭션의 자동 재시도 횟수를 늘리지 않는다.
- 가격 작업과 월별 원자료는 하위 조각부터 지운다. 한도를 만나 조각이 남으면 부모를 유지하고 다음 정리에서 이어간다. 부모만 먼저 지워 하위 자료를 찾지 못하게 만들지 않는다.
- 정리 중 오류가 나도 다음 실행 시각은 유지한다. 오류 원문·회사 위치·인증 정보는 정리 결과에 넣지 않는다.

단일 필드 범위 검색과 같은 필드 정렬은 기본 단일 필드 색인을 사용한다. `expiresAt`의 기본 색인을 제외하지 않는다. 별도 복합 색인이나 관리형 TTL 설정이 필요한 쿼리는 사용하지 않는다. [Firestore 색인 안내](https://firebase.google.com/docs/firestore/query-data/index-overview)

## 남아 있는 제한

만료 문서가 많으면 여러 차례에 걸쳐 정리되므로 즉시 모두 사라지지 않는다. 기존 문서 중 `expiresAt`이 없던 월별 자료·과거 통근 장부는 이번 코드가 전체 스캔해서 바꾸지 않는다. 새 월 자료 수집·새 통근 호출로 기록되는 문서부터 보관 종료 시각이 붙는다. 기존 자료를 별도로 정리해야 하면 컬렉션과 기간을 정해 소량으로 이관해야 한다.

한도 도달 시 연결 오류·조회 보류가 생길 수 있다. 서비스 전체의 저장 용량을 강제하는 한도나 모든 Firestore 작업을 합산하는 별도 일일 예산 장부는 아직 없으므로, 무료 범위 내에서 항상 동작한다고 보장하지 않는다.

## 계정별 최근 가격 검색 (4.15)

`homehunt_job_lookups`의 가구별 조건 색인은 24시간 이내 동일 가격 검색 작업을 재사용한다. 계정별 최근 작업 포인터는 인증된 UID·가구로만 조회하며, 완료된 공개 가격 후보·가격 확인 대기 목록 1건만 압축해 7일 보관한다. 원시 월 자료를 7일치 중복 보관하지 않는다. 가격 최신성 24시간과 보관 기간 7일을 구분하고 만료 작업의 보관본에는 `stale`과 `resumable:false`를 표시한다. 최신 가격 다시 조회는 새 작업을 만든다.

같은 계정으로 재방문하면 현재 가격 조건이 같은 결과를 자동 복원한다. 조건이 다르면 이전 가격 조건으로 여는 버튼을 제공한다. 다른 회사·예산 입력 중 도착한 옛 응답은 적용하지 않는다. 미완료 작업은 버튼으로 이어 조회하며 다른 메뉴 이동·로그아웃은 공유 작업 자체를 취소하지 않는다. 과거 배포의 아직 유효한 가격 작업도 계정 한정 최대 50건 안에서 복구한다.

이 색인·보관본은 기존 자동 정리의 총 읽기·삭제 한도 안에 포함된다. 최근 보관이 실패해도 24시간 작업의 정상 가격 결과를 유지하고 보관 지연을 표시한다. Kakao 경로·소요시간·통과 여부·추천 점수와 회사 좌표는 보관 대상이 아니다. 회사 주변 조회는 브라우저에서 비중별 공식 역 참고거리로 고른 공개 시군구 코드만 서버에 전달하며, 60분 도달권을 계산한 결과가 아니다.
