확인일: 2026-09-06 (KST). 정책 확인일은 데이터 조회일과 별개다. 조회한 정책에서 자동 수집 허용을 확인하지 못했으므로 이번 구현에는 포털 네트워크 수집기를 넣지 않았다.

## 향후 어댑터 활성화 조건

현재 `providers/portal/index.mjs`에는 `fetch`·스토리지·환경변수 활성화 경로가 없다. 따라서 단지 상세를 여러 번 열어도 포털 요청은 0회이며 데이터 캐시는 없다.

향후에는 제공자별 공식 API/제휴 문서, 허용 필드, 정확한 경로, 요청 한도, 저장·표시 조건을 먼저 기록하고 별도 검토한 어댑터를 추가한다. 이때만 사용자 단지 상세 진입/명시 새로고침에 한해 요청하고 제공자 한도 이내 동시성 1, 24시간 이상의 캐시가 계약상 허용되는지 확인, 수동 새로고침 쿨다운과 지수 재시도 대기를 적용한다. 인증 실패·금지·불명확 상태에서는 우회 재시도하지 않는다. 24시간 캐시와 특정 호출 수를 제공자가 허용했다고 주장하지 않는다.

로그인·CAPTCHA 우회, 비공개 API, 전수 수집, 사진 복제·중개사 연락처 저장은 구현 범위에 포함하지 않는다.

## 공급원 상태 계약

`providers/official/supply.mjs`의 `supplySourceState`가 기존 JSON을 다음 7개로 정규화한다.

| 상태 | 판정 근거 |
| --- | --- |
| 정상 수집 | 성공 상태, 실패 없음, 공고 1건 이상 |
| 정상 0건 | 성공 응답 확인, 실패 없음, 해당 범위 공고 0건 |
| 첫 기준선 수집 중 | 정상 최초 수집/기준선 이력이 없는 초기 상태. 실제 진행률을 만들지 않음 |
| 승인 대기 | 명시적인 approval/awaiting API 상태 또는 서비스 접근 미승인 코드 |
| 인증 실패 | 누락·만료·유효하지 않은 키 또는 HTTP 401/403. HTTP만으로 미승인과 잘못된 키를 확정 구분하지 않음 |
| 형식 변경 | JSON/XML 파싱·필수 schema·인코딩 검증 실패 |
| 일시 장애 | 타임아웃·통신 장애·부분 실패·기타 불명확 오류 |

원본 수집 상태와 기존 공고 보존 규칙은 유지한다. 청약홈 오류에서 안전한 `INVALID_JSON`, `INVALID_SCHEMA`, `MISSING_CREDENTIAL` 코드를 보존하여 UI가 원인을 구분하도록 했다. 비밀키나 원문 응답을 추가 출력하지 않는다.

## 분양 가격·신청 흐름

분양 주택형의 `maxPriceManWon`은 해당 주택형 최고가격이다. 여러 주택형 최고가격 중 최솟값을 단지의 최저 분양가라고 부르지 않는다. 상세와 판단 보드에서는 `공식 분양가 · 주택형별 최고`로 동일하게 표현한다.

같은 단지 현재 실거래 및 인근 비교는 분양가와 독립된 축이다. 어댑터는 출처 `molit-trade`, 매매, 면적, 표본 수, 기준일, 단지/면적 또는 인근/면적 매칭 근거가 제공된 자료만 받는다. 현재 화면에는 이 자동 매칭 자료가 없어 `미연결`을 표시하고 기존 실거래·주변 지도 이동으로 이어진다.

`청약 신청하기`는 [청약홈](https://www.applyhome.co.kr/), [LH 청약플러스](https://apply.lh.or.kr/), [SH 인터넷청약](https://www.i-sh.co.kr/app/)의 기관별 공식 사이트로 연결한다. 검증된 `applicationUrl`이 없는 경우 공식 사이트에서 공고·공급유형을 다시 선택하도록 안내한다. 모집공고 URL을 실제 신청서 URL처럼 취급하지 않는다.

접수일·자격·공고별 서류·납부일·직접 신청 체크리스트는 민감한 번호를 수집하지 않는다. 체크 상태는 메모리에만 있고 페이지를 닫으면 사라진다. 자격 승인·실제 신청 완료·당첨확률로 해석하지 않는다.

## UI와 모듈 사용

- `js/controllers/evidence-detail.js`: `renderCandidateEvidence(candidate, {catalogMeta, fetchedAt, personalRecord})`는 안전한 HTML 반환. 방문 기록은 `personalRecord`를 전달해 개인 확인가격·장단점·메모로 표시한다.
- `renderEvidenceFields(fields)`는 등급·출처·관측일·조회일·계산법을 분리 표시한다.
- `mountSupplyDecisionSupport(element, notice)`는 전달된 컨테이너에 가격 맥락·체크리스트·공식 신청 링크만 렌더한다. 원본 공고나 금융 데이터는 쓰지 않는다.
- `css/hh-evidence.css`는 430px 이하에서 근거 항목을 한 열로 바꾸고 체크리스트·공식 링크 터치 영역을 유지한다.

검증: `node --test homehunt/tests/evidence-providers.test.mjs`. 공식 식별 없는 값의 확정 표시 차단, 과거 중위값의 평균 오인 차단, 7개 공급원 상태, 가격 기준 분리, HTML escape, 호스트 allowlist, 포털 네트워크 0회와 개인정보 입력 없음 확인.

다음: 공식 K-apt 식별자·필드별 API 계약을 확보하고 분양 공고 위치와 실거래 단지의 정확한 매칭을 구현한 뒤 비교 가격 범위를 넓힌다.
